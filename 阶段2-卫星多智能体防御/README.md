## 一句话方向

**卫星场景下，构建能抵御多步注入攻击的多智能体防护机制，并兼顾轻量化。**

## 威胁模型（导师给的攻击链）

攻击的特点是**逐步篡改认知**，单步防御拦不住：

```
① 获取卫星运行参数
② 篡改认知范围，让篡改"显得合理"
③ 在篡改后的认知下，执行不合理操作 / 篡改遥操数据
```

导师的比喻是"**连环锁**"——每一环都要独立校验，不能只靠最后一道关。

## 约束

- **轻量化**：星上算力受限，要能用开源小模型（大模型在云端不一定可用）
- 场景是**卫星影像数据**
- ⚠️ **待确认**："细读影像数据相关论文"这个要求只来自口头转述，**纪要里没有**，需要跟导师核实

## 可以复用的阶段一资产

上一阶段的 8 篇调研是现成的**「攻击面目录」**，每篇对应一种攻击面或防御点：

| 阶段一调研 | 对上新方向的什么 |
|---|---|
| AgentVerse 的破坏性行为 | 攻击第三步长什么样；决策与执行之间没校验 |
| MacNet 只传 artifact、丢掉讨论过程 | 污染可以藏在产物里——过程不可见就查不出来 |
| GeoLLM-Squad 编排者写排班表、零 Agent 通信 | 排班表是单点信任，被改就控全局 |
| Multiagent Debate 用分歧做校验 | 可直接当防御原语：认知不一致就停 |
| ChatDev 交际式去幻觉 | 防御原语：信息不完整不许往下走 |
| MetaGPT 结构化产物 + 可执行反馈 | 产物可程序校验，天然是校验点 |
| AutoGen 拓扑由代码定 | 中心节点既是单点故障，也能是强制校验点 |
| CAMEL 角色扮演 + 终止标记 | 攻击可伪造终止标记 → 需要角色边界校验 |
