### ① SSH（ICML 2026）——最危险的一篇

**Speculative Safety Honeypot: Toward Proactive Defense Against Multi-turn Agent Attacks**
（Zezhong Wang, Xueyang Tang, Rui Lian, Yang Lou, Heqing Huang；ICML 2026 poster）

**它做了什么**：
- 用**多智能体小模型**做"**推测—验证**"工作流
- 推测阶段：**预测目标 Agent 的未来行为**，异步构建**轨迹树**，提前暴露潜在风险
- 验证阶段：用 Agent 的真实动作校准、剪枝轨迹树，降低误报
- 判断依据是**整棵轨迹树的演化**，不是单个时间点
- 定位是**组件式（plug-and-play）**，给现有检测器提供冗余

**为什么危险**：它的卖点——**"多轮里分散的恶意意图"、"从被动反应转向提前预防"、"看轨迹演化"**——**几乎就是你方案的 pitch**。

### ★ ② CMU 那篇：跟卫星场景直接撞

**Governing the Intelligence Loop: Architectural Mitigations for Epistemic Fragility in Autonomous Space-Cyber Threat Analysis**（CMU，Kilthub 预印本）

**航天网络威胁分析 + 认知脆弱性（epistemic fragility）+ 架构缓解**。

**场景重合度很高**，必须先读，再说"卫星场景没人做"。

## 二、★ 还剩的那个切口（窄，但真实）

**SSH 与你的设想的区别**：

| | SSH | 你的设想 |
|---|---|---|
| 观测什么 | Agent 的**未来动作**（轨迹树） | Agent **相信什么**（目标、约束、判断标准） |
| 盲区 | **一个攻击可以不改任何动作** | ← 这正是你要的位置 |

**具体场景**（就是 PPT 的 P13）：
Agent 读到被污染的输入 → **没调任何工具** → 只是把错误的认知写进给操作员的报告。
**SSH 的轨迹树上看不出来**，因为动作序列完全正常。

**→ 这个切口仍然成立，但表述必须从"认知层没人管"改成"现有防御观测动作，不观测信念"。**

## 四、方法论教训（已写进 AGENTS.md）

**错误做法**：从读过的 7 篇里归纳出"空白"，直接当成领域空白。

**正确做法**：
1. 归纳出的只能叫"**我这批文献里的空白**"
2. **必须专门检索**这个空白关键词（认知层防御、自适应评测、多模态注入……），看有没有人做
3. **检索不到**才能说空白，而且措辞要用"**现有工作极少关注**"而不是"没人做"

**"空白"是要花检索成本去证伪的结论，不是读几篇就能下的判断。**
