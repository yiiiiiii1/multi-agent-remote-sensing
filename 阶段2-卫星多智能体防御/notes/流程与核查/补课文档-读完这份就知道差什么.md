## 1. Speculative Safety Honeypot（SSH）★ 最危险的一篇

**出处**：ICML 2026
**作者**：Zezhong Wang, Xueyang Tang, Rui Lian, Yang Lou, Heqing Huang

**它要解决什么**：现有的多轮攻击检测**依赖历史上下文**，是**回顾式**的——但攻击者会把恶意意图**拆散到多轮里**，让你看不出未来的风险。

**它怎么做**（借了"推测解码"的思路）：

```
【推测阶段】
  用一个小模型组成多智能体模拟系统
  预测目标 Agent 接下来会做什么
  异步构建一棵【轨迹树】——把所有可能的未来路径摊开
        ↓
【验证阶段】
  用 Agent 的【真实动作】校准、剪枝轨迹树
  → 降低误报
        ↓
【判定】
  看【整棵轨迹树的演化】，不是看单个时间点
```

**性质**：**组件式（plug-and-play）**——不替换现有检测器，而是给它提供"决策冗余"。

**为什么对你最危险**：它的三个卖点——**"多轮里分散的恶意意图"、"从被动反应转向提前预防"、"看整条轨迹的演化"**——**几乎就是你想说的**。

**但它和你有一个真实区别**（这是你唯一还站得住的地方）：

| | SSH | 你 |
|---|---|---|
| 观测 | Agent 的**未来动作**（轨迹树） | Agent **相信什么**（目标、约束、判断标准） |
| 盲区 | **一个攻击可以不改任何动作** | ← 你要的位置 |

**具体讲**：Agent 读到被污染的输入，**没调任何工具**，只是把错误的认知写进给操作员的报告——**SSH 的轨迹树上看不出来**，因为动作序列完全正常。

**这个区别是真的，但很窄。你必须在方案里明说 SSH 做了什么、你差在哪。**

## 2. Adaptive Adversaries ★ 直接填掉了你的空白②

**出处**：arXiv:2607.18063，Lambda 公司，"Agents in the Wild" 工作坊
**标题**：Adaptive Adversaries: A Multi-Turn, Multi-LLM Benchmark for LLM Agent Security

**它做了什么**：一个**自适应跨轮攻击**的评测基准。

```
21 个场景
攻击方是一个自主 LLM：观察防守方上一轮的回答，然后调整策略再打
防守方每轮都被当成【全新的交互】来评
3×3 的攻击方—防守方矩阵 = 945 场对抗
```

**★ 最关键的一个数字**：

| 评测方式 | 攻击成功率 ASR |
|---|---|
| **只算第一轮** | **0–1%** |
| **允许 15 轮** | **7.9–16.8%** |

**这一行数字的意义**：**单轮评测会把风险严重低估一个数量级。** 这一条直接证明了"必须多轮评测"，而且是用**基准**证明的，不是用论证。

**其它发现**：
- 把 3 个攻击 LLM 合起来，比最好的单攻击方多找到 **1.7–2.2 倍**的唯一成功输入
- **加一段溯源说明**，ASR 从 110/270 降到 70/270（说明溯源确实有用，但**收益是选择性的**，不同任务差别大）
- 还办了个竞赛：18,422 场留出对抗，固定 gpt-oss-20b 底座

**对你的影响**：
- **不能再说"没人测自适应攻击"** —— 现在有专门的基准了
- **要改成**："已有自适应基准（Adaptive Adversaries），我们在此基础上……"
- **好消息**：你可以直接**用它当评测基准**，省掉自己造评测的工作量

## 3. CoopGuard ★ 填掉了你的空白④的一部分

**出处**：arXiv:2608.00134，投 **IEEE TIFS**

**标题**：Stateful Cooperative Agents Safeguarding LLMs Against Evolving Multi-Turn Attacks

**一句话**：现有防御是**被动反应式**的，跟不上攻击者跨多轮的策略调整；这篇做**主动防御 + 多智能体协作**。

**三种防御策略**（分工给不同 Agent）：

| 策略 | 做什么 |
|---|---|
| **干扰（disruption）** | 控制响应节奏，**提高攻击成本** |
| **误导（misdirection）** | 故意给模糊输出，**把攻击者引到无效策略上** |
| **适应（adaptation）** | 对交互日志做**取证分析**，识别攻击模式、改进防御 |

再由一个**自适应协调机制**根据威胁升级动态调整策略。

**数据**：EMRA 数据集，5,200 条对抗样本，8 种攻击类型。

**效果**：
- ASR **平均降 69%**
- 欺骗性周旋（DR）是最好基线的 **6 倍以上**
- 攻击方 token 消耗 **+198.83%**

**对你的影响**：
- 它是**单 LLM 被多轮攻击**的防御，不是**MAS 内跨 Agent 传播**——这个区别还在
- 但它已经"多智能体协作 + 有状态 + 主动防御"了，**你的表述得往后退一步**

## 4. VIGIL ★ 你的清单里本来就该有它（A1 引过）

**出处**：**ACL 2026**，中科大
**标题**：VIGIL: Defending LLM Agents Against Tool Stream Injection via Verify-Before-Commit

**它要解决什么**（它的问题陈述写得很好，值得学）：

> 现有防御面临一个**两难**：越强的模型因为对齐得好，**反而会优先执行被注入的规则**；而静态防护机制又会**切断自适应推理所需的反馈回路**。

**它怎么做**：从"限制隔离"转向 **verify-before-commit（先验证再提交）协议**：
- **推测式假设生成**（speculative hypothesis generation）
- **意图锚定的验证**（intent-grounded verification）

**效果**：ASR 再降 **22% 以上**，同时在攻击下把**可用性翻倍**（对比静态基线）。

**还有**：SIREN 基准，959 个**工具流注入**案例。

**对你的影响**：
- 它做的就是"**让 Agent 生成假设，再验证意图**"——**跟你的"认知校验"思路是同一条线**
- 你原来的笔记里就把 VIGIL 列为"值得顺藤摸的引用"（在 A1 笔记里），但**没有正式读它**
- **它是 ACL 2026，你引用它比引用预印本有力**

## 5. Pictionary（Render Before Reading）★ 思路最漂亮的一篇

**出处**：arXiv:2609.36121，**ETH Zurich + Leiden**（**Tramèr 组**，就是 CaMeL 那个组）
**标题**：Render Before Reading: Visual Rendering as a Prompt Injection Defense

**它的核心发现**（一句话）：

> **多模态 LLM 更容易执行"文本形式"的恶意指令，而同样的指令用图片等非文本通道给它，它就不太会听。**

**为什么**（它的假设）：**指令微调是文本中心的**——模型被训练成"服从文本指令"，而把其他模态**当成要解析的内容**，不当成指令。

**然后它把这个"模态差"变成了防御**：

```
把所有不可信的内容，在送进模型之前，
【渲染成印刷体图片】（或者音频）

→ 模型不再把它当指令，只当内容解析
→ 训练-free，不用改模型
```

**效果**：
- 10 个模型、2 个基准（DirectInject、AgentDojo）
- **即使面对最强的自适应攻击和人类红队，ASR 仍然下降**
- 可用性基本保住
- 反过来验证：如果拿图片渲染过的指令做**良性微调**，这个"模态差"就会被磨掉——**说明它确实来自文本中心的指令微调分布**

**为什么值得你重点学**：

1. **它是"结构约束"的完美例子**——不检查内容，直接**换通道**，让指令在结构上失效
2. **它主动评估了自适应攻击**——这正是你的空白②说要做的，人家已经做了
3. **它是 Tramèr 组的**——这个组的论文你要持续跟

**对你的启发**：星上场景里，**遥测/气象/影像数据是不是也可以做"通道降级"**？比如：外部来的内容**一律先转成结构化字段**（而不是自然语言），Agent 就只能读字段、读不到"话"。这跟你原来的"区分数据和话"是同一个思路，**但 Pictionary 给了它一个更强的理论依据和实验范式**。

## 6. Toward Trustworthy Agentic AI（多模态溯源框架）

**出处**：arXiv:2512.23557

**一句话**：提出 **Cross-Agent Multimodal Provenance-Aware Defense Framework（跨 Agent 多模态溯源防御框架）**。

**三个组件 + 一个账本**：

| 组件 | 做什么 |
|---|---|
| **文本净化 Agent** | 清洗文本输入 |
| **视觉净化 Agent** | 清洗图像输入 |
| **输出验证 Agent** | **所有 LLM 输出在下发前独立验证** |
| **溯源账本（provenance ledger）** | 记录每个内容的**模态、来源、信任级别**，贯穿整个 Agent 网络 |

**它明确针对的场景**（跟你要做的很像）：
> 恶意指令**藏在文本、图片、元数据、或 Agent 间消息里**，沿图传播，导致意外行为、违反策略、**状态损坏**。

**对你的影响**：
- 这篇**把"多模态 + 溯源 + 跨 Agent"三件事合起来了**——你的空白③被它填了
- **但它是框架性论文**（8 页，实验规模小），**没有在真实约束下验证**（比如算力受限）
- **这正好留了一个口子给你**：它的框架**代价多大？在星上跑得动吗？**

## 7. CMU 那篇：航天 + 认知脆弱性 —— **标题撞，内容不撞**

**出处**：CMU，Khadija Taki（Heinz College 政策学院），**单作者、4 页预印本、无会议**，2026-09
**标题**：Governing the Intelligence Loop: Architectural Mitigations for **Epistemic Fragility** in Autonomous **Space-Cyber Threat Analysis**
**镜像**：Zenodo DOI 10.5281/zenodo.22839735 → record 22860486（Kilthub 直连 403）

**已读全文，核实结果**：

| 核什么 | 结果 |
|---|---|
| 有没有定义「Epistemic Fragility」 | **没有**。全文 `epistemi` 只命中 5 处，**没有一处在下定义**，这个词只活在标题里 |
| 落地成什么 | 四条：编造 CVE、溯源丢失、置信度不校准、**给了工具所以能被注入**。**前三条没有攻击者**，是模型自己写得不干净 |
| 第四条怎么解 | **把工具收走**（`tools = []` 零工具沙箱）——让它**执行不了**，不是让它**不信** |
| 它的 "space" 是什么 | **文档题材，不是运行环境**。CrewAI 三 Agent（Collector → Analyst → Writer）读「讲航天威胁的通告文档」，产出**文字简报**。不接卫星、不读遥测、不下指令、不碰遥操 |
| 实验 | 3 篇文档、N=10、每条件 30 条。幻觉 23.3%→0%，溯源 40%→100%，**注入下工具执行 80%→0%**。但**那个 0% 是"本来就没有工具"推出来的** |
| 它测过「Agent 读到注入内容、写进简报当事实」吗 | **没有。而这正是课题的题眼** |
| 作者自承 | 整包 guardrail 拆不开贡献、单标注员、0% 是移除工具的必然结果、只有 3 篇文档 |

**结论**：它**管动作，不管认知**；它测**有没有执行**，不测**有没有相信**。它最接近我们，但**没有占掉这个位置**。

**可以引的对比句**：
> Taki (2026) 在航天威胁情报流水线上用零工具沙箱消除了间接提示注入的执行面，并用提示级规则把幻觉从 23.3% 压到 0%；但其评估维度全部落在输出格式与动作拦截上，未建模 Agent 的信念状态，也未考虑分步注入下的信念漂移。

**它留的缝很具体**：入口只做关键词筛查（作者自己把语义检索列为 future work）、只做单步探针、没讨论算力成本、场景里没有轨道参数没有遥测没有指令没有遥操。

# 第五部分：领域现状总结

## 已经形成共识的三条

1. **单步防护不够**——攻击是跨轮、跨主体的，单点判断必然失效
2. **提示级防护不可靠**——要靠架构级；而且攻击方论文（Crescendo §6.3）自己就说"应该假设 LLM 最终都会被越狱"
3. **评测必须放到多轮、自适应攻击下做**——这一条已经有基准支持：**只算第一轮 ASR 0–1%，放到 15 轮变 7.9–16.8%**

## 还有分歧、或者没解决的三条

1. **有状态防御的开销**——SSH 要多智能体做推测、CoopGuard 要多 LLM 协作、多模态溯源要三个净化验证 Agent。**这些开销在受限环境下能不能接受，现有论文都没回答。**
2. **来源可验证，内容真伪没法验证**——所有工作都在**把溯源做细**（provenance ledger、签名、链路记录），但**没有一篇解决"来源合法、内容是假的"**。
3. **「不改动作、只改认知」这类攻击怎么观测**——现有工作都在动作空间做判断（SSH 看轨迹树、VIGIL 看工具流意图、CoopGuard 看日志模式），而一个攻击可以**完全不改动作**。

## 一个值得注意的结构性事实

把这四条技术路线和它们的**算力假设**列一下：

| 技术路线 | 代表工作 | 假设的算力 |
|---|---|---|
| 推测—验证 | Speculative Safety Honeypot、VIGIL | 多智能体 / 多次 LLM 调用 |
| 多智能体协作防御 | CoopGuard | 多个 LLM 协作 |
| 多模态溯源 | Toward Trustworthy Agentic AI、Pictionary | 三个净化 / 验证 Agent |
| 有状态跨轮防御 | Adaptive Adversaries（基准） | 跨轮维护状态 |

**这四条路线都建立在同一个前提上：算力充裕。**

**这不是"空白"，是一个观察**——现有工作在云端算力充足的前提下都成立；算力受限时这些方法还剩多少，目前**没有论文回答**。

# 第六部分：术语补充（新的）

| 术语 | 意思 |
|---|---|
| **Speculate-and-Verify** | 先猜未来风险路径，再用真实观测校准 |
| **Trajectory Tree（轨迹树）** | 把 Agent 未来可能的动作路径摊开成一棵树 |
| **Provenance Ledger（溯源账本）** | 记录每份内容的模态/来源/信任级别的账本 |
| **Modality Casting（通道转换）** | 换内容呈现的模态，让指令在结构上失效 |
| **Stateful Defense（有状态防御）** | 防御方跨轮维护状态，而不是每轮从零判断 |
| **ASR / DR** | 攻击成功率 / 欺骗性周旋率（让攻击者白费力气） |
| **Epistemic Fragility（认知脆弱性）** | CMU 论文用的词——认知层被污染的脆弱性 |
| **Verify-Before-Commit** | 先验证再提交（VIGIL 的核心协议） |
| **EMRA / SIREN / DirectInject** | 三个新的评测数据集/基准 |
