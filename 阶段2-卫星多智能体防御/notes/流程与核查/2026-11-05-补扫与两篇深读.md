## 二、SafeMCP 读后（ACL 2026 正会，★5）

**它到底是什么**：一个**服务端的 MCP 防御插件**。

**做法**（p4–5, Algorithm 1）：
1. Agent 向 MCP server 请求可用工具
2. SafeMCP 先跑一遍：`Φsafe(s_i) = A \ A_filter_i` —— **把会导致不安全转移的工具从可用集合里删掉**（它叫「power regulation」）
3. Agent 在缩小后的工具集里选动作
4. Agent 请求调工具时，SafeMCP 再判一次 `ŝ_{i+1}, ŷ_{i+1}, A_filter_{i+1} ← SafeMCP(A, h_i, a_i)`，`ŷ=unsafe` 就直接 block（fail-safe）

**它的世界模型预测什么**（p5）：
- **Next-State Prediction**：`P(s_{i+1} | s_i, a_i)` —— 下一步状态
- **Unsafe Steps Prediction**：预测未来哪些步会不安全 `U`

**训练三阶段**：环境动力学接地（下步状态 + 未来不安全步）→ 冷启动 SFT → 双可验证奖励 RL（PPO）
**基准**：PowerSeeking Bench、**ToolEmu**、AgentHarm

**结果**（Table 1, ToolEmu）：GPT-4o + SafeMCP Safety **0.99**（无防御 0.42），Utility 0.22（无防御 0.25）——**安全拉满，效用掉一点**。

### 跟 SSH 的差别（这是关键）

| | SafeMCP | SSH |
|---|---|---|
| 动的是什么 | **可用工具集合**（砍掉危险工具） | **未来动作序列**（预测它会做什么） |
| 预测粒度 | 下步状态 + 未来不安全步（**扁平，无分支**） | M 条分支 × D 层深的轨迹树 |
| 剪枝 | 无（不建树，谈不上剪） | 真实动作回来剪 |
| 场景 | MCP 工具获取 / power-seeking | 工具调用型 Agent 的注入+越狱 |
| 会议 | ACL 2026 正会 | ICML 2026 |
| 开源 | ✅ ★5 | ❌ |

**一句话**：**SafeMCP 是「事前把危险工具拿掉」，SSH 是「事前推演它要走哪条路」。** 都在执行前，但一个约束动作空间，一个预测动作序列。

## 三、ToolEmu 读后（ICLR 2024 Spotlight，★229）

**它到底是什么**：**离线的 Agent 安全评测框架**，不是在线防御。

**做法**：
- **LM Emulator**：用 LM 模拟工具执行，给出 observation
- Agent 在模拟环境里跑
- **Safety Evaluator + Helpfulness Evaluator**（都是 LM）：对跑完的完整轨迹打分
- 36 个高危工具包 / 144 个测试用例
- 结论：**68.8%** 的失败是真实世界里也会发生的失败；最安全的 Agent 失败率也有 **23.9%**

### 复核说「ToolEmu 采样多条执行轨迹、再判风险」——**这句不准确**

我逐页查了 ToolEmu 的方法和实验：
- 每个用例跑**两条轨迹**：一条用标准模拟器，一条用**对抗模拟器**（adversarial emulator，会把沙箱状态初始化成更容易诱发失败的样子）
- 为了算标准误，跑 **3 次独立实验**
- **没有**从同一状态分叉出多条未来、**没有**树、**没有**剪枝、**没有**在线干预

所以准确说法是：**ToolEmu 是「模拟环境 + 事后判分」的评测框架**，它把「用 LM 模拟执行来暴露风险」这个机制做出来了，但**不是预测式防御，也不是动作级前瞻**。

### 但它对 SSH 那句「first」的影响是真实的

SSH 原文写：*the first framework that shifts LLM agent defense from retrospective context analysis to proactive future speculation*

- **「用模拟执行来暴露未来风险」这个机制，ToolEmu（ICLR 2024）先做了**——所以这句 overclaim 站不住
- **但加上「防御」和「在线」两个限定，SSH 的说法能站住**：ToolEmu 是评测，不是防御；是离线，不是在线

**写进汇报时的措辞**：不要说「SSH 第一个提出用模拟预测未来」，要说「**SSH 把模拟预测从离线评测搬到了在线防御**」。

## 四、修正后的结论（这一版可以用了）

**1. 「CCF-A 正会 + 开源 + 事前预测」三样齐全：有，SafeMCP（ACL 2026 正会，★5）。**

**2. 「CCF-A 正会 + 多步动作树推演」：仍然只有 SSH。** 但只能说「现有工作极少关注」，不能说「只有」——因为
- ToolEmu（ICLR 2024，CCF-A）做了模拟执行+判风险，但离线、无分支
- SafeMCP（ACL 2026，CCF-A）做了前瞻，但动的是工具集合不是动作序列

**3. 2026 年这一族确实爆发**：ACL 全家桶里 2026 年就有 47 篇；但**进 CCF-A 正会的只有 ACL 2026 的 SafeMCP，EMNLP 2026 正会那 4 篇是 CCF-B，其余全是 Findings。**

**4. SSH 的数字口径要带限定**（已在总结文档里记）：
- 0% ASR 只在 Qwen3-235B；GPT-OSS-120B 是 14.9% → **0.7%**（附录 D.1 Table 5）
- 1.3% 是参数比不是实测开销
- M 的记法论文自己矛盾（Table 1 脚注「beam width 8 (M=4)」，Table 2 扫 M=1–5，Limitations 说 M=5）
