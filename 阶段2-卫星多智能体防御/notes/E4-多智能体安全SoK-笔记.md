> **论文**：SoK: When Safe Agents Fail Together — The Security of Multi Agent LLM Systems
> **作者**：Rui Yang, Junjie Xu, Zhengyu Liu, Neil Fendley, Yang Hong, Ziyang Li, Yinzhi Cao（**Johns Hopkins University** / Nanyang Technological University）
> **出处**：arXiv:2609.00595 · 2026-09-01
> **本地 PDF**：`papers/E4 - SoK Security of Multi Agent LLM Systems (2609.00595).pdf`（21 页）
> **一句话**：用"执行路径"为中心，系统化了 **197 篇**工作，给出 **A-I-R 框架**（攻击者位置 → 交互接口 → 系统级风险）、**六类交互接口**、**七类系统级风险**、**八条攻击路径**，以及一个**五部分防御契约**。

## 一、核心命题（记住这一句就够）

> **Safe agents can fail together.**

**单独用都安全的 Agent，一起用会出问题。**

论文举了三个例子：
- 无害的提示片段**组合起来**变有害
- **真实的报告**能把一群 Agent 引向错误信念
- 攻击者控制的内容可以**穿过诚实的专家 Agent**，到达有特权的工具

**为什么**：MAS 会把**信息、状态、决策、权限**跨"主体边界"搬运——**本地的检查看不到这些**。

**关键警告**（这句对写方案特别有用）：

> Without an execution-level view, a multi-agent setting can easily be mistaken for evidence of a genuinely multi-agent security effect.

翻译：**如果没有"执行层面"的视角，很容易把"多智能体场景"误当成"真的产生了多智能体安全效应"**。——换句话说，别看到多智能体出问题就说是"多智能体的锅"，得看清楚是哪条交互路径造成的。

## 二、A-I-R 框架（攻击的组织方式）

```
A（Adversary position，攻击者在哪） → I（Interaction interface，从哪个接口进） → R（Risk，造成哪种系统级风险）
```

**这个三元组就是你的威胁模型骨架。** 你把它套到卫星场景，改的是"位置、接口、风险"的具体内容，框架不用动。

### 四个攻击者位置（A1–A4）

| 代号 | 位置 | 含义 |
|---|---|---|
| **A1** | External Adversary | 外部攻击者 |
| **A2** | User-level Adversary | 用户级（能操控输入） |
| **A3** | **Member Adversary** | **成员级——MAS 内部的某个 Agent 被攻陷** |
| **A4** | Infrastructure Adversary | 基础设施级（服务、存储、日志） |

> **A3（成员攻击者）是多智能体独有的**——单模型系统里没有"内部成员"这个概念。

### 六个交互接口（I1–I6）—— 这是全篇最有用的清单

| 代号 | 接口 | 讲什么 |
|---|---|---|
| **I1** | **Admission** 准入 | 什么被允许进入 MAS 边界：用户、新主体、外部数据、消息、产物。看身份、来源、角色、初始信任 |
| **I2** | **Message transfer** 消息传递 | 信息在主体之间移动。安全取决于**谁收到、什么顺序和上下文、发送者身份与来源是否可验证** |
| **I3** | **State propagation** 状态传播 | 一次交互的信息被写进状态、之后影响别的主体或执行——**记忆、摘要、计划、历史、文档** |
| **I4** | **Authority transfer and action** 权限转移与动作 | 委派和使用特权能力：工具、凭证、资源 |
| **I5** | **Collective commitment** 集体承诺 | 局部输出变成**群体决策**：投票、共识、最终答案、终止决定、动作触发 |
| **I6** | **Detection and intervention** 检测与干预 | 执行期间的检查与响应：监控、阻断、隔离、撤销、回滚、恢复 |

**为什么这份清单对你最有用**：你导师说的攻击三步（获取参数 → 篡改认知 → 执行不合理操作），**每一步都能对到这几个接口上**：

| 导师的三步 | 对应接口 |
|---|---|
| ① 获取卫星运行参数 | **I1 准入**（数据进来了） |
| ② 篡改认知使其合理化 | **I3 状态传播**（写进状态、影响后续判断）+ **I2 消息传递** |
| ③ 执行不合理操作 | **I4 权限转移与动作** |
| （整体失效） | **I5 集体承诺**（群体决策被带偏） |
| （防御落点） | **I6 检测与干预** |

### 七类系统级风险（R1–R7，已确认的）

| 代号 | 风险 |
|---|---|
| **R1** | Containment Failure 遏制失效 |
| **R2** | Loss of Independence 独立性丧失 |
| **R3** | Collective-Decision ... 集体决策（相关风险） |
| **R4** | Trajectory & Goal Integrity Failure **轨迹与目标完整性失效** |
| **R5** | Cross-Principal Confidentiality Breach 跨主体机密泄露 |
| **R6** | （未确认，需翻原文） |
| **R7** | Availability / Resource Isolation 可用性 / 资源隔离 |

> **R4（轨迹与目标完整性失效）最贴你的场景**——"逐步篡改认知"本质上就是**轨迹完整性**被破坏。

### 八条常见攻击路径

论文归纳了 **8 条反复出现的攻击路径**（具体列表在原文，需要时翻）。

**为什么要"路径"这个概念**：因为**单点检查看不出多智能体的问题**——问题在**路径上**。

## 三、五部分防御契约（写方案时直接照这个框架）

论文不用"技术清单"组织防御，而用**一份契约**，五部分：

| 部分 | 要回答什么 |
|---|---|
| **path target** | 这条防御**针对哪条攻击路径** |
| **observation** | 它**能看到什么**（在哪个层次观测） |
| **intervention** | 它**怎么干预**（阻断/隔离/撤销） |
| **trust boundary** | 它**守的是哪条信任边界** |
| **recovery** | 出事之后**怎么恢复** |

**两个被点名为关键挑战的**：

1. **Path closure（路径闭合）**——防御是否真的把**整条路径**堵死了，还是只堵了其中一段
2. **Recovery（恢复）**——出事之后能不能回到安全状态

> **★ 这两个词就是你导师说的"连环锁"的学术表达。**
> "连环锁" = 不只堵一环，要让**整条路径闭合**。
> 你方案里可以直接用 **path closure** 这个词——比"连环锁"更适合写进论文。

## 四、44 个评测工作的审计 + 四个开放挑战

论文审计了 **44 个**评测/基准工作，指出四个没解决的问题：

1. **隔离交互效应**——分不清"是单 Agent 的问题"还是"多智能体交互产生的问题"
2. **设计可比、可诊断的指标**——现有指标不能诊断"是哪一步被突破"
3. **跨 MAS 设计的复用**
4. **开放系统运行的评测**

**论文总主张**：

> **端到端追踪攻击、测试防御是否闭合了这些路径、用适当的反事实来评测系统级效应。**

"反事实（counterfactual）"这个说法值得留意——意味着你要能回答"**如果没有这个防御，会怎样**"，这跟 A2 的消融实验（T0/T1）是一个思路。

## 五、★ 对你方案的直接价值

### 1. 这就是你威胁模型的骨架

```
A（谁在攻击：A1 外部 / A2 用户级 / A3 成员 / A4 基础设施）
    ↓
I（从哪个接口进：I1 准入 / I2 消息 / I3 状态 / I4 权限动作 / I5 集体决策 / I6 检测干预）
    ↓
R（造成什么系统级风险：R1 遏制失效 / R4 轨迹完整性 / R5 跨主体泄露 / R7 可用性）
```

**把这三层换成卫星场景的内容，你的威胁模型就成型了。**

### 2. "路径闭合"是你要的核心概念

不要用"加了几层防御"来组织方案，要用"**攻击路径有没有闭合**"来组织——这是这篇最值钱的方法论。

### 3. 它的四个开放挑战，你可以挑一个当自己的立足点

- 想做**指标**：挑战 2（可诊断的指标）——正好接上 A2 的 JBR 思路
- 想做**机制**：挑战 1（隔离交互效应）
- 想做**评测**：挑战 4（开放系统运行）

### 4. 它和"多步攻击"的关系

E4 讲的是**空间上的路径**（跨接口、跨主体）；A5（Crescendo）讲的是**时间上的推进**（多轮累积）。

**两者结合才是完整的"多步注入"**：

> **多步 = 在时间上逐步推进（A5）× 在空间上跨接口传播（E4）**

这个结合点，就是你可以主张的**新意**——现有工作要么只讲单次注入的传播（A1/A2），要么只讲多轮越狱（A5），**没有人把"时间上的多步"和"空间上的跨主体路径"合起来建模**。

---

## 六、一句话总结

**单独安全的 Agent 一起用会失败，因为信息、状态、决策、权限在跨主体搬运——所以别用"单点检查"的思路防，要用"攻击者位置 × 交互接口 × 系统级风险"建威胁模型，用"路径闭合 + 恢复"来组织防御。**
