## 二、每篇一句话

**多步检测三件套**
- **CausalTrace**：把轨迹画成因果图，问「去掉注入那段，这个坏结果还会不会发生」，用 do-calculus 算。F1 99.2%，注入点检测 94.8%
- **Peak+Accumulation**：纯正则 + 算式把多轮分加成一个总分，证明加权平均有天花板。recall 90.8%，**但对「话题慢慢跑偏」类攻击 recall 是 0%**
- **Fraud Layer**：42 个结构化「形状」特征 + XGBoost，**执行前 4.6ms 拦**。AUC 0.97

**记忆/信念**
- **PerMIT**：记忆读写收窄成有限接口，不可信值要人确认才「背书」。**Lean 4 机检定理 + ASR 全 0**，但良性误拒 17–32%
- **CAPTURE**：区分「偏好真的变了」vs「记忆被投毒」，用神经微分方程做信念追踪。投毒成功率 11.5%，但**自适应攻击者下升到 24.7%**
- **MAP-Graph**：多 Agent 共享记忆的 provenance 图，动作前加风险敏感门。任务成功 94.96%

**授权/策略**
- **Progent**：权限写成符号规则，LLM 自动生成策略，**SMT 求解器判定每次更新是收紧还是扩大**——收紧自动应用，扩大要人批。叫 monotonic confinement
- **Action-Class Authority**：给动作标可撤等级，闸门只读声明不听 Agent 说。**没有实验、没有定理、无代码，Zenodo 68 浏览 2 下载**

**卫星**
- **SkyGuard**：卫星 SAGIN 分层威胁狩猎，边缘 SLM 本地调查 + 中央 LLM 拼 ATT&CK 链。macro category recall 0.46，chain recall 0.43。静态基线全 0
- **AstroMind**：卫星行为推理基准，133 场景 399 题。**现有开源模型物理一致性普遍差**（中位相对误差 0.85 级），Llama-3-8B 19.70%（低于随机）

**范式**
- **RedHerring**：「假设便宜、验证昂贵」→ 验证工作量成为防御面。用诱饵链 + 假桥，真实漏洞发现降 38.7–60.4%
- **系统级威胁监控**（立场）：主张部署后的系统级监控「largely underexplored」

## 四、还空着的（措辞已按规矩写）

### ① 「信念状态」与「动作可逆性」的交叉

**即便在本文调研的这批工作中，也极少有机制同时处理「Agent 相信什么」和「这个动作能不能撤」。**
- PerMIT 看的是**记忆入口、逐值确认**，不是信念状态
- Action-Class 看**动作**，而且**只看声明、不看内容**

**能答出「那 PerMIT 那篇呢」**——它逐值确认，不判断信念状态。

### ② 卫星场景下的信念校验

**SkyGuard 的判据在外部痕迹（日志 / 快照 / ATT&CK 标签），AstroMind 看卫星的外部行为——都不处理「自家 Agent 读到的数据被改、信念被带偏」。**

**能答出「那 SkyGuard 那篇呢」**——它串的是攻击阶段，不是 Agent 的信念。

### ③ 多智能体之间认知的横向传播

**CausalTrace 把多智能体系统当轨迹的数据来源，没有建模「一个 Agent 被污染后通过协作把错判断传给另一个」。**

### ④ 卫星算力预算下的防御配置

**SkyGuard 已经是分层（边缘 SLM + 中央 LLM），但极少有工作回答「给定功率预算，最优配置是什么」。** 那篇综述**明确没碰轻量化，算力假设是云端**。

## 五、答辩必被问的风险（现在就得想好）

| 风险 | 要准备的答法 |
|---|---|
| **SkyGuard 的「串链」跟导师说的「连环锁」形似** | SkyGuard 串的是 **ATT&CK 攻击阶段**（攻击者走到哪一步）；连环锁锁的是 **Agent 的信念**（它现在认为什么）。**两者不是一回事。** |
| **可逆性分级「已经有人做了」** | 只能说「**概念已被提出，尚无实现与评测**」，不能说「已有工作做过了」。而且要承认那篇是立场文档 |
| **信念侧检查凭什么立得住** | PerMIT 的教训：**要么有定理、要么有硬数字。只画架构图结局就是 68 次浏览** |

## 七、补：CMU「Governing the Intelligence Loop」核完了（全文，4 页）

**结论：它没有占掉「卫星场景下的认知层防御」。**

| 核什么 | 结果 |
|---|---|
| 有没有定义「Epistemic Fragility」 | **没有**。这个词只在标题里，正文一次都没解释。正文用的是 epistemic liabilities / failure modes / vulnerabilities |
| 落地成什么 | 四条清单：编造 CVE、溯源丢失、置信度不校准、工具面可注入。**前三条没有攻击者**，只有第四条有 |
| 第四条怎么应对 | **「不给工具」**——让它执行不了，不是让它不信 |
| 它的"space"是什么 | **文档主题，不是运行环境**。CrewAI 写的威胁情报简报流水线，读"关于航天的通告文档"，产出文字简报。**不接卫星、不读遥测、不下指令** |
| 实验 | N=10，30 样本，3 篇文档。注入下工具执行 80%→0%，但**这个 0% 是"本来就没有工具"推出来的** |
| 它测过「Agent 读到注入、写进简报当事实」吗 | **没有。而这正是课题的题眼** |
| 分量 | **单作者、政策学院（Heinz College）、4 页预印本、无会议、单标注员**；作者自己承认"分数打包在 guardrail 里拆不开" |

**S-LARF**（Elsevier 闭源，只拿到摘录两句）：打的是**星载异常检测模型**的对抗鲁棒性，**对象是 ML 检测器，不是 LLM Agent 的信念**。也撞不上。

**所以「现有工作极少关注 Agent 自己相信什么」这个判断，成立。**
