# 选题方案：两个候选

> 每个候选都写四件事：**空在哪（能答出"那 XXX 那篇呢"）／ 怎么做 ／ 最小实验 ／ 风险**。
> **措辞规矩**：说"空着"一律用「现有工作极少关注」，**不说"没人做"**。

---

# 候选 A：卫星分层架构里的「信念校验环」

## 一句话

> **在 SkyGuard 那种分层架构里，加一环——校验 Agent 自己的判断有没有被改过，而不只是校验它下发了什么指令。**

## 空在哪

**现有卫星侧的判据，全在外部痕迹：**

| 工作 | 看什么 |
|---|---|
| SkyGuard | 日志、快照、ATT&CK 标签 |
| AstroMind | 卫星的外部行为推理 |
| CMU「Governing the Intelligence Loop」 | 文档写得好不好（幻觉率、溯源率） |

**都处理不了「自家 Agent 读到的数据被改、信念被带偏」。**

**能答出「那 SkyGuard 那篇呢」**：
> SkyGuard 串的是 **ATT&CK 攻击阶段**（攻击走到第几步）。它不建 Agent 的信念状态——它的观测对象里根本没有这一项。

**能答出「那 CMU 那篇呢」**：
> 那篇的 "space" 是**文档题材**不是运行环境，它读的是"关于航天的通告"，产出文字简报，**不接卫星、不读遥测、不下指令**。而且它的实验测的是"有没有执行"，**没测过"Agent 读到注入内容、当成事实写进简报"**。

## 怎么做

**核心：让 Agent 的判断变成可校验的对象。**

1. Agent 每一步输出一个**结构化判断**：`{判断内容, 依据来源, 推导用的规则}`
   - 例：「这份遥测要给 A 站」← 依据：任务书第 3 条 + 数据源是 B 站
2. 每一环**独立校验**这个判断的**依据链**，不看结论对不对
3. 依据链断裂、来源越界、推导跳跃 → 拦在这一环

**关键：不判断"结论对不对"，判断"这个结论有没有依据"。**

**这样就不需要攻击手法编号**——因为你看的是"这个判断从哪来"，不是"这像不像某种攻击"。

## 最小实验

**不需要真卫星。** 用 SkyGuard 的公开设置做三件事：

1. 搭一个小规模多 Agent 流水线（遥测判读 → 任务规划 → 指令生成），用开源小模型
2. 注入攻击：改中间数据，让它得出错误判断（Agent 本身不报错）
3. 对比：**只有动作层校验** vs **加上信念校验**

**指标**：
- 错误判断被拦的比例
- 正常任务被误拦的比例
- 额外开销（token 数、延迟）

## 风险

**① 怎么定义"结构化判断"**——Agent 说的理由可能是事后编的（rationalization）。这是最硬的技术风险。
**② 算力**——每步都记判断和依据，星上能不能扛。
**③ 容易被说"只是加了个日志"**——必须有"拦住了一个动作层拦不住的攻击"这个证据。

# 候选 B：信念 × 可逆性的二维分级

## 一句话

> **按「信念被改得多严重」×「这个动作能不能撤」决定校验强度——可撤的松，不可逆的严。**

## 空在哪

**两件事分别有人做，但没有一篇同时看：**

| 做了什么 | 谁 | 它不看什么 |
|---|---|---|
| 记忆/信念侧的信任 | PerMIT | **动作可不可逆** |
| 按可逆性分级 | Action-Class Authority | **只看动作声明，不看内容** |

**能答出「那 Action-Class Authority 那篇呢」**：
> 它**只给了词汇和闸门的形状，没有实验、没有定理、没有代码**。Zenodo 上 68 次浏览、2 次下载，同作者四天后又发了一篇同系列。**是立场文档，不是研究论文。**
>
> **引用措辞必须写**：「**概念已被提出，尚无实现与评测**」。**不能写"已有工作做过了"。**

**能答出「那 PerMIT 那篇呢」**：
> 它是**逐个值确认**（这个值可不可信），不是判断**信念状态**（它现在认为的任务范围对不对）。

## 怎么做

**一张二维表决定校验强度：**

| | 动作可逆 | 动作不可逆 |
|---|---|---|
| **信念可信** | 放行 | 轻校验（结构约束兜底） |
| **信念可疑** | 策略检查 | **重校验 + 硬约束** |

**"不可逆 + 信念可疑"那一格，必须是结构约束**（按 `02-框架` 的判据：不可逆动作没有"再来一次"的机会）。

## 最小实验

1. 构造一个动作集，标注**可逆性等级**（只读 / 自撤 / 需他人撤 / 撤不了）
2. 同一个攻击，在不同可逆性等级下，测**不同校验强度的拦截率和误拦率**
3. 画一条曲线：**校验强度 → 安全性 vs 可用性**

**这个实验本身就值钱**——它第一次给出"该花多少代价检查"的量化依据，而不是"越严越好"。

## 风险

**① 可逆性标注靠人**——谁来标、标得准不准。
**② 可能显得"工程化"**，缺少理论贡献。对策：**证明一个界**（在给定可逆性分布下，最小的校验开销是多少）。
**③ 名字已经被人占了**——必须引用措辞准确，且要承认那篇是立场文档。

# 推荐：A + B 合成一个

> **在卫星按层分布的架构里，按「信念被改的程度 × 动作可逆性」决定每一环的校验强度。**

**为什么合成：**

- **A 提供"看什么"**（信念状态）
- **B 提供"花多少代价"**（可逆性分级）
- 两者都缺对方就不完整：A 光看信念会被说"开销多大"，B 光分级会被说"你分级依据什么"

**为什么可行：**

- 接着现有调研，不用重新学
- 不跟大团队拼机制（Progent、CaMeL 那些机制已经被占了）
- 导师问"你打算做什么"能一句话答清

---

# 可主张的贡献表述（写方案用）

1. **提出信念状态的可校验表示**——把 Agent 的"当前判断"从隐含变成显式对象，使"只改认知、不改动作"的攻击第一次有可观测的对象。
2. **给出按可逆性分级的校验配置规则**——把"该花多少代价检查"从经验判断变成可量化配置。
3. **在卫星分层架构上验证**——现有工作极少在星上算力与动作不可逆的双重约束下评估防御，本方案给出该约束下的可行性边界。

# 三条必须提前想好怎么答的

| 老师会问 | 怎么答 |
|---|---|
| **那 SkyGuard 那篇呢？** | 它串的是 ATT&CK 攻击阶段，**看时间序列**；我锁的是 Agent 的信念，**看内部状态**。听着像，不是一回事。 |
| **可逆性分级不是有人做过了吗？** | 概念被提出过（Zenodo 一篇立场文档），**但没有实现、没有评测**。我用它的词汇，实验自己做。 |
| **你怎么证明"信念被改了"？** | 不判断结论对不对，**判断依据链完不完整**——来源越界、推导跳跃、依据缺失，这三种是可查的。 |
