# 方法设计草稿：认知完整性（Belief-Flow Integrity）

> 用途：方案"方法"一节的第一稿。
> 起因：读 A1 / A2 / B1(CaMeL) / B2 后确认——**现有防御都只在"动作层"设防，而"篡改认知"发生在动作之前**。
> 核心思路：**把 CaMeL 的"控制流完整性"推广到"认知完整性"。**

---

## 一、问题的准确表述

**现有防御的观测对象**：

| 防御 | 观测什么 | 不管什么 |
|---|---|---|
| CaMeL（capability） | 值从哪来、谁可读 | 值的**含义** |
| Security policy（CaMeL） | 动作允不允许 | 做这个动作的**理由**对不对 |
| Plan-Then-Execute（B2） | 动作序列 | 计划背后的**判断依据** |
| Policy oracle（A2） | 权限表 | 认知有没有漂移 |

**→ 它们观测"动作"和"数据流动"，不观测"认知的正确性"。**

**关键区分**：

> **provenance（来源）≠ validity（真伪）**
> 现有防御追的是来源，而攻击落在真伪上。
> **一个被篡改的气象读数，它的 provenance 恰恰是"合法的气象数据源"。**

**为什么不能靠过滤**：

1. **识别不出**——气象报告里写"有碎片风险"本来就是正常内容，判断真假需要你没有的标准答案
2. **A1 实测**——边界净化只能把间接注入从 43% 降到 9.5%，还有 2.3% 误判（在卫星上 = 漏掉真的预警）
3. **可以只改数据**——把"云量 12%"改成"45%"不是注入指令，就是个假数值，过滤不掉

**为什么不能靠查上游**：

1. 上游往往不是 agent（传感器 / 第三方 API）
2. 上游是 agent 时，它**无辜转发**，动作和数据流全合法
3. 溯源无限后退 → 追到传感器/人/物理世界，**那里只能认证身份，不能验证内容真伪**

---

## 二、核心思路：从"控制流完整性"到"认知完整性"

CaMeL 干的是**控制流完整性**：不可信数据**改不了动作**。

**对称的那一半是——认知完整性：不可信内容改不了判断。**

| | CaMeL | 本方法 |
|---|---|---|
| 保护什么 | 做哪些动作 | **相信什么** |
| 从哪提取 | 可信查询 → 控制流与数据流 | **可信任务定义 → 目标与约束** |
| 不可信数据能影响 | 只能填数据槽 | 只能填**结构化事实槽** |
| 不能影响 | 动作序列 | **目标、约束、判断标准** |
| 强制点 | 每次调用工具前查策略 | **每次认知变更前查来源是否认证** |

---

## 三、关键设计：区分"数据"和"话"

**这是整个方法的核心一刀。**

### 反例（现状）

```
Agent 读到一段文字："区域A有高速碎片，建议调整姿态规避"
  → 这段文字【直接】改变了它的判断
  → 姿态变了（或建议操作员改）
```

### 改造后

```
认知状态是一个结构化对象：
  { "debris_risk": false,
    "attitude_change_allowed": false,
    "constraints": ["不得改变卫星姿态", "只读操作"] }

规定：只有【认证的结构化数据源】能写这些字段
  · 星上碎片传感器 → 可写 debris_risk
  · 地面任务定义   → 可写 attitude_change_allowed / constraints

气象报告里的【文字】→ 只能进 "参考资料" 字段
                    → 写不了 debris_risk
                    → 写不了 attitude_change_allowed

结果：攻击者要让姿态变，必须
  · 让【碎片传感器】报 true，或
  · 让【地面】改 attitude_change_allowed
—— 都比"在报告里写一句话"难得多
```

**要点**：**不是检查那段文字有没有恶意，而是让那段文字在架构上根本写不进认知字段。**

**这是"认知层的结构约束"，不是策略检查。**

---

## 四、五条具体机制

1. **认知字段只能被认证的结构化来源写**
   自然语言内容只能进"参考资料"，不得改写判断依据。

2. **多源交叉核验**
   遥测/气象从 2–3 个独立来源取；**不一致就降级处理**。
   不需要知道"哪个是真的"，只需要知道"它们矛盾"。
   （攻击者要同时攻陷多个独立来源，成本高得多。）

3. **认知漂移检测 + 审计**
   目标/约束的每次实质变化，必须记录：**变了什么 + 依据是哪条具体数据**。
   审计时能看到：这个变化是基于"某条遥测数据"，还是基于"一句自然语言的话"。

4. **约束修改必须走显式授权通道**
   防止"在对话里慢慢说服 Agent"——**这直接防"使其合理化"**。

5. **不可逆动作有地面/硬件确认**
   最后一环：防"认知被改 → 动作发生"。
   （深空通信延迟本来就大，这条的现实代价比地面场景小。）

**前四条防"认知被改"，第五条防"改了也做不出事"。**

## 五、度量（借用已验证的指标）

| 指标 | 来源 | 测什么 |
|---|---|---|
| **JBR**（判断被绕过率） | A2 | **认知层**有没有被攻陷 |
| **UAR**（危险动作执行率） | A2 | **动作层**有没有失守 |
| **ASR**（攻击成功率） | A5 | 攻击是否成功（注意：安全里必须为 0 才算防住） |
| **FPR**（误拦率） | A2 | 可用性代价 |

**必须分开测 JBR 和 UAR**——这是 A2 的核心方法论贡献。
理想结果：**JBR 下降（认知守住了），UAR 保持 0（动作本来就没失守）**。

**必须评估自适应攻击者**（见 `自适应攻击-方法论与选题.md`）——不做，reviewer 直接拒。

## 六、诚实的边界（必须写进方案）

1. **防不住"真的风险被伪造为无风险"**
   若攻击者能让传感器沉默，结构化字段就是 `false`，系统认为安全。
   → **必须有冗余来源。**
2. **认知对象本身也可能被攻陷**
   谁维护那个认知对象？**又回到信任根**（缩小它、让攻陷可检测、让后果有界）。
3. **降低灵活性（真实的取舍）**
   把"话"和"数据"分开，意味着 Agent **不能从自由文本里学到新东西**——
   而这正是 LLM 的优点之一。**这个代价要在方案里讲清楚。**

---

## 七、方案的贡献表述（可直接用）

> 现有多智能体防御（A1 的架构分层、A2 的授权边界、CaMeL 的 capability 与 B2 的设计模式）
> **都在"动作层"设防**：它们能拦住越权执行，但**无法察觉认知本身被逐步篡改**——
> 因为它们的观测对象是"动作与数据流"，而不是"认知的正确性"。
>
> 我们提出 **认知完整性（belief-flow integrity）**：
> **认知变更只能由认证的结构化来源触发，自然语言内容不得写入认知字段**，
> 并配合多源一致性校验与漂移审计，把防御前移到**动作尚未发生**的那一环，
> 从而闭合"获取参数 → 篡改认知 → 执行不合理操作"这条多步攻击链。

---

## 八、一句话总结

**不能验证"真"，但能验证"一致性、溯源、锚定"——所以不要试图判断内容真假，而要让"话"在架构上写不进"认知字段"。**
