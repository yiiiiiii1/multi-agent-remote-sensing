# A. 输入侧

## A1 输入值物理可行性（轨道力学）🔴

**是什么**：轨道根数、位置速度这类值，拿去对物理规律——Vis-Viva 能量方程、齐奥尔科夫斯基火箭方程、角动量守恒。

**谁做了**：**Array 2026**（Karunathilake / Abeywardena / Vecchini，期刊 *Array*，DOI 10.1016/j.array.2026.100799）

**做到什么程度**：
- LSTM 先从遥测里检测"可疑轨道操纵"
- **然后**用多道物理门过滤误报，判据是"这个异常在运动学上自相矛盾"
- 摘要明说：**只验证了 Vis-Viva 能量门；齐奥尔科夫斯基和角动量门是设计、未验证**

**剩下的缝**：
- 只验了一道门
- **是检测之后的 post-filter，不是上游拦截**——LSTM 不觉得可疑就不会调用物理门
- 没有 LLM Agent
- 只覆盖轨道域

## A2 输入值物理可行性（平台遥测）🟢

**是什么**：电池 SOC、母线功率、温度这类平台值，查"三秒涨 50% 可能吗"。

**谁做了**：**我这轮没查到。**

**但要说清两件事**：
1. **这可能不是你老师的威胁模型要的**。「卫星运行参数」通常指轨道/姿态，不是平台状态
2. 量程检查在卫星运维里是老做法（见 A4），**所以"查数值"本身不是新颖性**

**检索范围**：英文关键词、arXiv/Google Scholar/ScienceDirect，没搜中文文献。

## A3 跨传感器冗余一致 🔴

**是什么**：两个独立传感器测同一个量，对不对得上。GNSS 位置 vs IMU 递推位置、星敏姿态 vs 太阳敏+磁强计几何。

**谁做了**：**BLADE-SPACE**（Zenodo 20183269，Burak Oktenli，Georgetown，20 页全文读过）

**做到什么程度**：
- 星载治理节点，11 级流水线（传感器 → ADARA 异常 → SATA 信任融合 → IFF → HMAA 授权 → MAIVA 投票 → FLAME → ERAM）
- 输入侧：跨传感器一致性系数 `C(si, S\{si})` + 物理残差 + ADARA 的 3σ 异常罚分
- 用 RTG4 硬件强制机构权限

**关键**：**论文自己承认**——协同欺骗时 `C→1.0` 会失效，只能靠物理残差兜底。

**剩下的缝**：没有 LLM Agent；重心在动作授权；不查单值变化率。

## A4 单值量程/变化率 ⚪

**是什么**：每个测量值在合理范围内、变化率不超过阈值。

**谁做了**：**这是卫星地面站三十年来的标准操作**。搜到 USU SmallSat 的文章原话就写着「验证每个测量值在正确范围内」。

**所以**：**不能把"查数值范围"当新颖性。**

**但有个区别可以争**：老做法防的是**随机故障和传感器飘移**；对抗场景下攻击者会**专门挑一个能通过量程检查的值**。这个区别能立，但不足以独立成篇。

## A5 输入来源可信（血缘/溯源）🔴

**是什么**：这条数据从哪来、经过谁的手、有没有被改过。判据是**来源**，不是**内容**。

**谁做了**（一整个方向，很挤）：
- **ARGUS**（arXiv:2605.03378）——建影响溯源图，校验动作有没有完整的良性因果依据
- **AGATE**（arXiv:2609.30830）——harness 边界上的授权 + 数据血缘门
- **ProTA**（ISC 2026）——provenance-aware tool authorization
- **SIEVE**（arXiv:2512.06716）——Intent Graph 做确定性校验
- **MemLineage**（arXiv:2605.14421）——记忆侧的 chain-of-custody
- **MAP-Graph**（arXiv:2608.10509）——多 Agent 共享记忆的溯源图
- **PerMIT**（arXiv:2610.28987）——记忆值的逐个确认

**为什么这个方向不能碰**：
**Silent Subversion 那篇明确说了**——被篡改的遥测**来源是合法的**，provenance 追不出来。**这类防御对你的威胁模型不起作用。**

## A6 输入与指令/计划对照 🟡

**是什么**：这个值跟我下发的指令、跟任务计划对不对得上。

**谁做了**：ARGUS 的"良性因果依据"部分覆盖。

**剩下的缝**：它查的是"有没有依据"，不是"跟计划一致吗"。

# B. 认知侧

## B1 任务范围/授权边界校验 🔴

**是什么**：Agent 以为自己的任务范围有多大、能调哪些工具、能碰哪些数据。

**谁做了**：
- **Progent**（arXiv:2504.11703）——权限写成符号规则，LLM 生成策略，**SMT 判定每次更新是收紧还是扩大**，扩大要人批准
- **CaMeL**（SaTML 2026）——控制流和数据流分离，不可信数据进不了控制流
- **Trust Propagation**（IEEE CARS 2026）——执行前独立授权
- **ARGUS**——良性依据蕴含

**这个方向极其挤。** Progent 那套"单调收紧"几乎封死了。

## B2 判断的依据链 🔴

**是什么**：不看结论对不对，看这个结论有没有依据。

**谁做了**：**ARGUS 就是它**。摘要原话：校验每个动作"有没有完整的良性因果依据"。

**做到什么程度**：ASR 28.8% → 3.8%，干净任务效用 87.5%。

**剩下的缝**：**Agent 自己报的依据可能是事后编的**。这个问题有专门文献（CoT 可监控性那一族，豆包列了但我没核）。

## B3 内部状态（隐藏状态探针）🔴

**是什么**：在模型的隐藏状态里探"它是不是被注入了"。

**谁做了**：
- **AGRI**（arXiv:2608.02657）——线性探针预测"注入暴露"，**AUROC 0.90+**，探针门控后 ASR 34.6%→0%
- ESLD（arXiv:2605.18918）、PVDetector（arXiv:2607.12624）、Latent Adversarial Detection（arXiv:2604.28129）

**为什么它挡不住你的威胁模型**：它探的是**指令注入暴露**。**数值篡改没有指令**，探针不触发。

## B4 跨步信念漂移 🟡

**是什么**：多步推理里，Agent 的信念有没有一点点被带偏。

**谁做了**：
- **CAPTURE**（arXiv:2609.02265）——区分"偏好真变了"和"记忆被投毒"，用神经微分方程做信念追踪
- **CausalTrace**（ICML 2026）——轨迹建因果图
- **Peak + Accumulation**（arXiv:2602.11247）——浅层的多轮累积（但只认字面）

**剩下的缝**：CAPTURE 管的是**个性化偏好**，不是**任务参数**；而且它的神经微分方程跟"轻量化"冲突。

## B5 多 Agent 之间认知横向传播 🟡

**是什么**：一个 Agent 被污染，通过协作把错判断传给另一个。

**谁做了**：
- **MAP-Graph**——多 Agent 共享记忆的溯源（但它是"谁读得到"，不是"传了什么错判断"）
- **CausalTrace**——只把多 Agent 系统当**轨迹的数据来源**，没建模板传播路径

**剩下的缝**：**没有工作建模"错判断在 Agent 之间怎么传播"**。这是 E4 SoK 提的成员级攻击方向。

**这一条我判断最有希望，但也要专项检索。**

## B6 多模态遥测的一致性 🟢

**是什么**：频谱、图像、热图、时序——不同模态对同一事件的说法对不对得上。

**谁做了**：**没查到。**

**为什么可能是个好点**：现有的血缘工作几乎全在**文本**工具输出上做 provenance。卫星遥测是多模态的，provenance 图要扩展到非文本。

# C. 动作侧

## C1 动作前独立授权 🔴

**谁做了**：Trust Propagation（token + 策略双重）、Progent（SMT 单调收紧）。

## C2 动作物理约束 🔴

**谁做了**：**Glass Box at Orbit**（arXiv:2606.02967）——星上拦截候选动作，过 **6 条物理宪法约束 + 7 条 LTL 不变量**，Z3 + NuSMV 验证，开销 **O(N_c)** 与模型大小无关。

**要做到什么程度**：每个放行的动作带可解释性分数和审计日志。**全仿真**（Project October，CubeSat 级）。

**剩下的缝**：它读到的状态就是被污染的那个。

## C3 按动作可逆性分级 🟡

**是什么**：可逆动作松一点，不可逆动作严一点。

**谁做了**：**Action-Class Authority**（Zenodo 21305381）——但**只有词汇和闸门形状：没有实验、没有自己的定理、没有代码，68 次浏览 2 次下载。**

**引用只能写**：「**概念已被提出，尚无实现与评测**。」

## C4 动作与它自述的认知是否一致 🟢

**是什么**：它说"我认为任务范围是 X"，但实际做的动作超出了 X。

**谁做了**：**没查到。**

**为什么有意思**：这不需要读隐藏状态，也不需要 Agent 自报依据——**用动作反推它的信念，再跟它说的对照**。Agent 想撒谎就得同时管住"说的"和"做的"。

**风险**：可能被归到 B2（ARGUS 那一族）。

# D. 执行侧

## D1 遥操指令签名/防篡改 ⚪

**传统密码学**。Beyond Single-Model 那篇里有消息签名（31%→2.8%）。**不是新颖性。**

## D2 发出后不可撤回的补救 🟢

**是什么**：指令已经发出去收不回了，能做什么。

**谁做了**：**没查到。**

**为什么难**：卫星遥操物理上不可逆，**这一条可能根本不成立**——没有补救手段。除非是"发之前的最后一刻拦截"，那又回到 C1。

# E. 系统/评测侧

## E1 多步攻击检测 🔴

**谁做了**：CausalTrace（因果图 + 反事实，F1 99.2%）、Peak + Accumulation（纯算式，recall 90.8% 但对"话题跑偏"0%）、Fraud Layer（42 特征 + XGBoost，4.6ms）。

**方法、公式、工程三件套都齐了。**

## E2 自适应攻击评测 🔴

**谁做了**：**Adaptive Adversaries**（arXiv:2607.18063v2）——21 个场景、五类威胁、945 场对抗、多攻击模型聚合。

## E3 卫星安全基准 🟡

**现状**：
- **Silent Subversion**（IEEE Aerospace 2026）——NOS3 仿真里复现遥测投毒攻击。**是攻击复现，不是基准**
- **AstroMind**（arXiv:2605.24573）——卫星**行为推理**基准，133 场景 399 题。**不是安全基准**

**剩下的缝**：**没有一个卫星场景的注入/投毒防御基准。** 但基准论文要靠社区采用，本科生推不动。

## E4 算力预算下的防御配置 🟢

**是什么**：给定几瓦功率、多少显存，最优防御组合是什么。

**谁做了**：**没查到。** IEEE Access 那篇综述明确说**没碰轻量化，算力假设是云端**。

**为什么可能好**：SkyGuard 给了一串硬数字（500 字节上行、4–6 秒延迟、1000 倍余量），**有现成的锚点**。

**风险**：评估类论文，要做得足够全才有分量。
