# MAS 方向头脑风暴：15 个想法

> **约束**：必须是**只有多智能体才有**的防御，不能是"一个 Agent 也能做的事"。
> 判断标准：**把 Agent 数量降到 1，这个方法还成立吗？成立就不是 MAS 方向。**

---

# 先定标准

**什么样才算"MAS 方向"**：

| 算 | 不算 |
|---|---|
| 利用**Agent 之间的信息差** | 单 Agent 内部的状态检查 |
| 利用**角色分工**（谁该看到什么） | 把同一个检查在每个 Agent 上跑一遍 |
| 利用**通信拓扑**（谁传给谁） | 加个总控 Agent 统一判 |
| 利用**多个独立视角**对同一事实的交叉 | 单值的物理校验 |

**一句话**：**必须是"1 个 Agent 做不到"的东西。**

---

# 15 个想法

## ① 跨 Agent 判断交叉复核 ★★★★

**是什么**：两个 Agent 独立看同一批遥测，各自下结论，然后比对。**分歧就触发复核。**

**为什么是 MAS 的**：单 Agent 只有一个结论，无从比对。

**谁做了**：多 Agent 辩论（multi-agent debate）这一族做过"提升准确率"，**但没做过"用分歧检测注入"**。

**强度**：高。便宜（不需要额外模型，只是多跑一遍）、可测（分歧率 vs 拦截率）。

**弱点**：星上算力翻倍，可能扛不住。**除非只在不可逆动作前才跑。**

---

## ② 角色-证据绑定（可见性一致）★★★★★

**是什么**：每个 Agent 有它**该看到的东西**。判读 Agent 能读原始遥测，规划 Agent **只能读判读结论**，读不到原文。

**检查**：规划 Agent 的结论里，如果出现了**它无权看到的细节**（比如具体的传感器读数），说明信息越界了——要么判读把不该传的传了，要么规划绕过了判读。

**为什么是 MAS 的**：单 Agent 没有"角色可见性"这个概念。

**谁做了**：信息流控制（information flow control）是经典理论；CaMeL 做了 capability 标签。**但"用结论里的细节反推信息越界"这个具体做法，我没查到。**

**强度**：很高。**极便宜**（只查字段级来源，不用模型）、**能抓到"认知范围被改"**（范围改了，它就会去读本来不该读的东西）。

**这条我最看好。**

---

## ③ 认知漂移的链式累积 ★★★★

**是什么**：不检测单点，检测**整条链上"信心"的递增**。

例子：
- 判读说「电池 90%」（单看正常）
- 规划说「可以高功耗机动」（单看合理）
- 下发说「执行」（单看合规）

**每一步单独都合理，但三步连起来，"假设的强度"在往上叠。**

**为什么是 MAS 的**：单 Agent 没有"多步委托"这个结构。

**谁做了**：Peak + Accumulation 做了对话轮次的累积（并证明加权平均有天花板）；CausalTrace 做轨迹因果。**但没做过"判断在 Agent 链上累积"**。

**强度**：中高。理论上有现成的工具（累积 vs 平均），可以借。

---

## ④ 传播深度界 ★★★★

**是什么**：不是机制，是**理论**——证明"如果每环都做 X，错误判断最多传播 k 环"。

**为什么是 MAS 的**：传播深度只在多 Agent 链上有定义。

**谁做了**：没查到。**这类"界"的论文在安全领域很吃香**（比如拜占庭容错的 f < n/3）。

**强度**：高，但**必须配一个可实现的机制**，光有界不够。

---

## ⑤ 每环的最小独立证据集 ★★★★

**是什么**：每一环要复核上游的判断，需要哪些证据？**这些证据它能不能独立拿到？**

拿不到 → 说明**架构本身有问题**，不是算法问题。

**产出**：一个"独立可验证性"指标，用来评估一个多 Agent 架构设计得好不好。

**为什么是 MAS 的**：单 Agent 的"独立性"没有意义。

**谁做了**：没查到。

**强度**：中高。偏设计原则，可能需要配实验。

---

## ⑥ 授权沿链只能收缩 ★★

**是什么**：上游委托给下游时，能力集只能缩不能扩。下游收到的 scope ⊆ 上游的 scope。

**为什么是 MAS 的**：委托是多 Agent 才有的动作。

**谁做了**：**Progent 做了单 Agent 版**（SMT 判定收紧/扩大）；object-capability 是经典安全模型；CaMeL 做 capability 标签。

**强度**：**低。**这条基本被占了，而且理论根基太老。

---

## ⑦ 信念传播图 ★★

**是什么**：记录"B 的这个判断依据了 A 的哪句话"，A 的话失效就回溯所有依赖它的判断。

**谁做了**：**这是最挤的一条**——ARGUS、AGATE、ProTA、SIEVE、MemLineage、MAP-Graph、PerMIT 全在 provenance 这一族。

**强度**：**低。别碰。**

---

## ⑧ 影子 Agent / 冗余执行 ★★

**是什么**：起一个不看上游输出的影子 Agent，只看原始遥测独立跑一遍，比对结果。

**谁做了**：多 Agent 辩论、ensemble、Speculative Safety Honeypot（并行分支）。

**强度**：低。**算力直接翻倍，星上扛不住。**

---

## ⑨ 分歧即信号（不要求一致）★★★★

**是什么**：不追求"达成一致"，而是把**分歧本身**当检测信号。

正常时两个 Agent 应该高度一致；被注入后，其中一个的观点会跟另一个脱节。

**为什么是 MAS 的**：单 Agent 没有"分歧"。

**谁做了**：多 Agent 辩论追求的是"通过争论提升答案"，**没把分歧当告警**。

**强度**：中高。**但需要一个"正常分歧基线"**，否则误报率高。

---

## ⑩ 接口契约校验 ★★

**是什么**：定义每对 Agent 之间的消息格式和必填字段，校验结构完不完整。

**强度**：**低。**schema 校验是老做法，而且**格式对但语义错**的消息照样过——这正是 Silent Subversion 的做法（"格式和节奏都合法"）。

---

## ⑪ scope 变更的授权源 ★★

**是什么**：Agent 的 scope 必须来自授权源，变更要留痕。

**谁做了**：Progent、Trust Propagation、RBAC。

**强度**：低。被占。

---

## ⑫ 代理间通道加固 ★★★

**是什么**：Beyond Single-Model 列了 14 个攻击向量，其中一类就是 Agent 间消息。**针对这个通道做具体的加固。**

**谁做了**：Beyond Single-Model 给了四层防御（签名、净化、限权、异常检测），但**是 workshop 论文、自建 6 Agent 流水线、规模小**。

**强度**：中。**缝在"规模小、没在真实场景验证"**，但容易被说"你只是把它做大了"。

---

## ⑬ 可机检的证明（proof-carrying action） ★

**是什么**：下游执行前要求上游给一个**可机检的证明**，不是口头解释。

**谁做了**：**有一篇 "proof-carrying agent actions"（Sci Rep）**，我之前检索到过。**被占。**

**强度**：低。

---

## ⑭ 跨模态的 Agent 分工交叉 ★★★

**是什么**：判读 Agent 只看图像，规划 Agent 只看文本，**两个视角对同一事件必须一致**。

**为什么是 MAS 的**：不同 Agent、不同模态，天然有信息差。

**谁做了**：多模态溯源那篇（Toward Trustworthy Agentic AI）碰了边，但没做"跨模态 Agent 交叉"。

**强度**：中高。**但需要多模态数据，做起来重。**

---

## ⑮ 每环的"怀疑预算"分配 ★★★

**是什么**：整条链有一个总的校验预算（算力/延迟），**怎么分配到各环最优**。

**为什么是 MAS 的**：预算是链级的，不是单点的。

**谁做了**：没查到。**跟我之前想的"按可逆性分级"是同一类思路，但从"单 Agent 的动作"升级到"多 Agent 的环"。**

**强度**：中。**评估类，要有好实验才站得住。**

---

# 筛选结果

## 第一梯队（继续深入）

| 想法 | 为什么 |
|---|---|
| **② 角色-证据绑定** | **极便宜 + 能抓"认知范围被改" + 单 Agent 做不到**。最贴合你的威胁模型 |
| **① 跨 Agent 判断交叉复核** | 简单直接，可测；只在不可逆动作前跑就能控制成本 |
| **③ 认知漂移的链式累积** | 有现成理论工具（累积 vs 平均）可借 |

## 第二梯队（作为配菜）

| 想法 | 用途 |
|---|---|
| **④ 传播深度界** | 给论文加理论分量，但必须配机制 |
| **⑤ 最小独立证据集** | 可以做成评估指标 |
| **⑨ 分歧即信号** | 可以并入 ① |
| **⑮ 怀疑预算分配** | 可以并入 ② 或 ① |

## 不建议

⑥ 授权收缩（Progent 占了）、⑦ 信念传播图（最挤）、⑫ 通道加固（workshop 已做）、⑬ proof-carrying（被占）、⑧ 影子 Agent（算力）、⑩ 接口契约（老做法）、⑪ scope 授权源（被占）

# 最有希望的一个组合

> **每一环用「自己该看到的东西」去复核上游交来的判断。**
>
> **机制**：角色-证据绑定（②）。下游 Agent 的结论里出现它无权看到的细节 → 信息越界 → 拦。
> **加一层**：跨 Agent 分歧检测（①⑨）。两个 Agent 对同一事实分歧过大 → 触发复核。
> **理论**：证明每环都做这件事时，错误判断的传播深度 ≤ k（④）。
> **指标**：传播深度、拦截率、每环开销。

**为什么这个组合立得住**：

1. **单 Agent 做不到**——需要角色可见性，需要多个视角
2. **极便宜**——只查字段级来源，不用额外模型
3. **直接咬住威胁模型的第二步**——"篡改认知范围"必然导致 Agent 去读它本来不该读的东西
4. **有理论抓手**——传播深度界
5. **跟连环锁是一回事**——每环独立校验，只是把"校验"具体化成"校验信息边界"
