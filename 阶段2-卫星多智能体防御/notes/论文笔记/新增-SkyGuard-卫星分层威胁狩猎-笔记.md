# SkyGuard：它干了什么

> **论文**：SkyGuard: A Hierarchical SLM–LLM Threat Hunting Framework for the OpenC3+NASA cFS Space-Software Stack
> **作者**：Jonathan Liu 等 6 人（台湾科技大学）
> **出处**：**IEEE CNS 2026**，DOI 10.1109/CNS69863.2026.11720931
> **一句话**：**卫星上做威胁狩猎，小模型在边缘本地查，大模型在中央只收标签拼攻击链。**

---

## 一、它要解决什么

在"星—空—地一体网络"（卫星 + 无人机/高空平台 + 地面站）上做威胁狩猎。

以前有两种做法，**它论证这两种都不行**：

1. **多 Agent 互为大模型** —— 每个 Agent 都是大模型，星上跑不动
2. **边缘机器学习 + 中央大模型** —— 边缘只做简单分类，复杂的都传回中央

**为什么不行？三个硬约束：**

| 约束 | 后果 |
|---|---|
| **低轨过境窗口短** | 卫星一次能跟地面通话的时间很短 |
| **上行带宽受限** | 传不了多少数据 |
| **地面 IDS 对星上实时威胁无效** | 已经有了这个结论 |

**所以"把原始数据全传回去集中分析"这个范式，在卫星网络里根本立不住。**

---

## 二、它的做法：两层

### 边缘（Tier 1）

**每台机器上放一个小模型，只查自己这块。**

- 模型：Qwen2.5 系列，**1.5B 到 7B**，4-bit 量化，LoRA 微调
- 权限：**只读本机的遥测和日志**，看不到别的机器
- 干活方式：会调工具——查快照完整性、查有界时间窗的日志、做跨维度的语义推理

论文里部署了两个：一个查地面站（OpenC3 那套），一个查星上（NASA cFS 那套）。

### 中央（Tier 2）

**一个大模型，只看摘要，不看原始数据。**

- 模型：Qwen2.5-**32B**，4-bit，约 20GB 显存
- **不微调**——因为它收到的已经是整理好的摘要，只负责推理和拼链
- 用 RAG 挂了 ATT&CK 和 SPARTA 两个知识库

### 关键设计：什么能上行，什么不能

| 数据 | 能不能出边缘 |
|---|---|
| **原始遥测、日志、pcap** | **不行**，标 CONFIDENTIAL，永不出边缘 |
| **ATT&CK 标签化摘要** | 能，压到约 **500 字节** |
| **下行指令** | 只发**抽象行为模式**，不发具体 IOC |

还有个巧的设计——**规则分两层生成**：

- **Tier A**（边缘生成）：带真实字段值、容器名、部署细节。**精确但不可移植**，留在本地
- **Tier B**（中央生成）：只有技术级检测逻辑（比如"product: redis"）。**可移植**，能给别的运营商用，不泄露自己的部署细节

## 三、什么是"拼成链"（这篇的核心）

这是最难懂的一点，用一个真实案例讲。

### 一条三步攻击链

| 步骤 | 干了什么 | 在哪台机器 |
|---|---|---|
| ① | **偷凭证**（读 Redis 账号列表、扫 token） | 地面段 |
| ② | **建后门账号** `svc_monitor`，权限 `+@all` | 地面段 |
| ③ | **把任务遥测改道**到 `10.0.0.99` | 星上段 |

### 为什么"单独看都说得通"

- 建一个叫 `svc_monitor` 的监控账号 → **像运维干的**
- 改遥测的输出地址 → **像操作员授权的**

**静态规则就栽在这**：它检出了两个信号，但**哪个都不敢确认**，因为每个都有合法解释。

### 为什么"连起来就没有解释"

**先偷凭证 → 紧接着建一个全权限账号 → 4 分钟后把遥测改成往外发。**

**这个顺序、这个时间窗，没有合法解释。**

**这就是"拼成链"：把"看着都可疑但都解释得通"变成"确定是攻击"。**

### 为什么"只有边缘"拼不出来

| 配置 | 检出 | 拼成链 |
|---|---|---|
| 静态规则 | 0 个 | ❌ |
| **只有边缘小模型** | **3 个全检出** | ❌ **拼不出来** |
| 全信息中央大模型 | 3 个 | ✅（但传不回去，不可部署） |
| **SkyGuard** | 3 个 | ✅ |

**地面那个小模型看到了 ① 和 ②，但它看不到 ③。星上那个看到了 ③，但它不知道地面在偷凭证。**

**两个 Agent 各自都对，谁也拼不出全貌。**

SkyGuard 怎么拼的：边缘报警时挂一个标签「这条可能属于攻击链 R1」，**中央只看 TTP 序列和时间戳邻近性**就拼出来了——

> **它从头到尾没看到那个 IP、没看到被偷的凭证、也没看到那条命令的内容。**

## 四、效果（要说准，别吹）

30 个攻击（其中 6 个是**之前没报道过的 cFS 漏洞**）+ 5 条 APT 链。

| 配置 | macro 类别召回 | macro 链召回 |
|---|---|---|
| 静态规则 | 0.30 | **0** |
| 只有边缘小模型 | 0.46 | **0** |
| **SkyGuard** | **0.46** | **0.43** |
| 全信息中央大模型 | **0.82** | 0.80 |

**注意两点：**

**① 只有它和"全信息中央"能拼出链。** 前两个在每条链上都是 0。

**② 但它的准确率不是最高的。** 全信息中央大模型能到 0.82，它只有 0.46。

**那为什么不用全信息中央？因为卫星传不回去。** 它的价值是**「在链路预算内做得到」**，不是在实验室里跑分高。

### 硬数字

| 项 | 值 |
|---|---|
| 端到端延迟 | **4–6 秒**（7B 边缘 + 32B 中央） |
| 上行摘要 | **约 500 字节** |
| 链路余量 | 5 分钟过境窗口能传 750 条摘要，实际只产生约 10 条 → **余量约 1000 倍** |

## 五、它的瓶颈在哪

论文自己写的：**如果某个应用在训练集里没出现过，召回就是 0。**

代码里有好几行 0.00，作者解释说是"留一交叉验证的覆盖问题，不是检测机制失效"。

**翻译成人话：它得先见过这个软件长什么样，才能认出来。**

## 六、跟你什么关系

**① 这是唯一一篇"能部署"的卫星分层防御。** 严格说，它是你这份调研里**唯一跟卫星贴得上的**。

**② 它的数字能直接用来支撑"算力受限"这一条**：500 字节上行、4–6 秒延迟、1000 倍余量——**这些是硬依据，不是估计。**

**③ 但它不看"认知"。** 它的判据是日志、快照、ATT&CK 标签——**全是外部痕迹**。

**④ 答辩必被问的那条**：

> **SkyGuard 串的是 ATT&CK 攻击阶段（攻击走到第几步）；连环锁锁的是 Agent 的信念（它现在认为什么）。**
> **一个看时间序列，一个看内部状态。听起来都像"串起来"，但不是一回事。**

---

## 七、一句话总结

> **它证明了一件事：卫星上"把数据全传回去"行不通，必须分层；而分层之后，靠标签也能拼出攻击链。但它的判据全在外部痕迹，不碰 Agent 自己相信什么。**

---

## 八、可能被问的问题

| 问 | 答 |
|---|---|
| 它跟连环锁的区别？ | 它串的是 ATT&CK 攻击阶段，连环锁锁的是 Agent 的信念。 |
| 为什么纯边缘拼不出链？ | 边缘只看得到自己那个栈，三个攻击都能检出，但跨栈的关联做不了。 |
| 准确率不高，凭什么发？ | 它的价值是"在链路预算内做得到"。全信息中央能到 0.82，但卫星传不回去。 |
| 它的瓶颈？ | 训练覆盖。某个应用在训练集里没出现过，召回就是 0。 |
| 能直接搬到我们这儿吗？ | 架构能搬。但它的边缘模型是用对应软件栈的数据微调的，得先有那套训练数据。 |
| 它测过 Agent 的信念吗？ | 没有。判据是日志、快照、ATT&CK 标签。 |
