# 术语速查（只记这些，其余先划掉）

> 用途：看累了就翻这一页。**只留 8 个词**，其他名词都是论文内部的编号，用到再查。

---

## 一条主线（所有词都挂在这上面）

> **攻击是一条链：从口子进来 → 往下传 → 最后动手。**
> **防御要让整条链闭不上口。**——这就是你导师说的"连环锁"。

三个词就够：**怎么进 → 怎么传 → 怎么动手**。

---

## 八个必须记的

| 词 | 大白话 |
|---|---|
| **主体 principal** | 一个**能被单独叫到**的参与者（一个 Agent、一个服务）。用这个词是为了分清"同事"和"外人"。 |
| **接口 interface** | 攻击**能钻进来的口子**。别记六个，只分三类：**进来的**（用户输入、检索到的文档、API 返回）→ **往下传的**（Agent 之间的消息、写进记忆的东西）→ **动手的**（调工具、执行指令）。 |
| **攻击路径 attack path** | 攻击从入口走到后果的**整条链**。**别盯单点，盯链。** |
| **路径闭合 path closure** | 防御把**整条链**堵死。**这就是"连环锁"的学术说法。** |
| **认知攻击 cognition attack** | 不直接命令你干啥，而是**慢慢改你对任务的判断**。← 你导师说的"逐步篡改认知"。 |
| **JBR / UAR** | 判断被绕过率 / 危险动作执行率。**要分开测**：JBR 高、UAR 低 = 判断被攻陷了，但动作被拦住了（A2 的核心发现）。 |
| **架构级防御** | 不靠提示词让模型"自觉"，而是**在结构上让它做不到**。反义词是"提示级防御"（靠系统提示挡，A1 证明不管用）。 |
| **能力 capability** | 一个 Agent **被允许干的事**，按角色裁剪。不是"什么都能干但请自觉"。 |

- **Astride / MAESTRO / ThreatGPT**——威胁建模框架的名字
- **confused deputy（混淆代理）**——一个经典安全概念，意思是"低权限的组件骗高权限的组件替它办事"

## 七篇笔记各自只需记住一句话

| 笔记 | 就记这一句 |
|---|---|
| **E4 SoK** | 单独安全的 Agent 一起用会失败；**别查单点，查路径**。 |
| **A1 威胁模型** | 护栏拦不住（67% 中招）；**要架构级防御**；工具输出那条路最危险（43%）。 |
| **A2 信任传播** | 上游被攻陷 ≠ 系统被攻陷——**在动作前放一道独立授权**。而且**签名不够，要独立策略**。 |
| **A5 Crescendo** | 多步攻击的力量来自**累积**，单轮检测无效。 |
| **B1 CaMeL** | 把**控制流**从可信查询里抽出来，不可信数据只能填数据槽，改不了流程。 |
| **B2 设计模式** | 五种拿"自主性"换"安全性"的架构模式，可直接当"连环锁"候选。 |
| **E5 综述** | 两个领域承认的缺口：**自适应攻击下泛化差**、**工具交互评测不足**。 |

## 一句话总结

**攻击是链，防御要闭合链，判断和授权要分开。**
