## 二、★ 两条必须记住的引用注意

### 1. 预印本要说"预印本"

**A2 / B2 / E4 都还没有正式 venue。** 汇报时说"arXiv 预印本"即可——**说成会议论文，导师一查就露**。

**为什么这也正常**：A2 和 E4 都是 2026 年 9 月才挂出来的（5 周左右），正在投稿很正常。**说"这是最新的预印本"反而是加分项**——说明你的检索在前沿。

### 2. ★ CaMeL 的数字有两个版本，别混用

| 版本 | AgentDojo 任务完成率 |
|---|---|
| **arXiv v2**（2025-06，我下载的那版） | **77%**（对比无防御 84%） |
| **IEEE SaTML 2026 正式版** | **67%** |

**引用时必须注明版本**：说"77%"就标 arXiv v2；否则用正式版的 67%。

**建议**：方案里用正式版 **67%** 更稳（有 venue 背书），或者两个都写清楚。

## 补：三篇新增论文的引用注意（2026-10 精读后核出）

### VIGIL（ACL 2026）

- **ASR 降幅口径不一致**：摘要和 §4 都说 **over 22%**，但 p2 的贡献列表写 **over 18%**。
  **引用按 22%**（摘要 + 结果节各一次，多数）。PPT 里用的就是 22%。
- 正文说「领先 DRIFT 22%~24%」，但按 Table 2 五个向量算出来的宏观平均对不上这两个数。
  **引用时写「原文称 22%~24%」**，不要自己算完当原文。
- 作者说静态防御工具流 UA「普遍掉到 12% 以下」，但 **CaMeL 在 Qwen3-max 上是 24.87%**，这句概括偏乐观。

## 1. Speculative Safety Honeypot（SSH）★ 最危险的一篇

**出处**：ICML 2026
**作者**：Zezhong Wang, Xueyang Tang, Rui Lian, Yang Lou, Heqing Huang

**它要解决什么**：现有的多轮攻击检测**依赖历史上下文**，是**回顾式**的——但攻击者会把恶意意图**拆散到多轮里**，让你看不出未来的风险。

**它怎么做**（借了"推测解码"的思路）：

```
【推测阶段】
  用一个小模型组成多智能体模拟系统
  预测目标 Agent 接下来会做什么
  异步构建一棵【轨迹树】——把所有可能的未来路径摊开
        ↓
【验证阶段】
  用 Agent 的【真实动作】校准、剪枝轨迹树
  → 降低误报
        ↓
【判定】
  看【整棵轨迹树的演化】，不是看单个时间点
```

**性质**：**组件式（plug-and-play）**——不替换现有检测器，而是给它提供"决策冗余"。

**为什么对你最危险**：它的三个卖点——**"多轮里分散的恶意意图"、"从被动反应转向提前预防"、"看整条轨迹的演化"**——**几乎就是你想说的**。

**但它和你有一个真实区别**（这是你唯一还站得住的地方）：

| | SSH | 你 |
|---|---|---|
| 观测 | Agent 的**未来动作**（轨迹树） | Agent **相信什么**（目标、约束、判断标准） |
| 盲区 | **一个攻击可以不改任何动作** | ← 你要的位置 |

**具体讲**：Agent 读到被污染的输入，**没调任何工具**，只是把错误的认知写进给操作员的报告——**SSH 的轨迹树上看不出来**，因为动作序列完全正常。

**这个区别是真的，但很窄。你必须在方案里明说 SSH 做了什么、你差在哪。**

## 2. Adaptive Adversaries ★ 直接填掉了你的空白②

**出处**：arXiv:2607.18063，Lambda 公司，"Agents in the Wild" 工作坊
**标题**：Adaptive Adversaries: A Multi-Turn, Multi-LLM Benchmark for LLM Agent Security

**它做了什么**：一个**自适应跨轮攻击**的评测基准。

```
21 个场景
攻击方是一个自主 LLM：观察防守方上一轮的回答，然后调整策略再打
防守方每轮都被当成【全新的交互】来评
3×3 的攻击方—防守方矩阵 = 945 场对抗
```

**★ 最关键的一个数字**：

| 评测方式 | 攻击成功率 ASR |
|---|---|
| **只算第一轮** | **0–1%** |
| **允许 15 轮** | **7.9–16.8%** |

**这一行数字的意义**：**单轮评测会把风险严重低估一个数量级。** 这一条直接证明了"必须多轮评测"，而且是用**基准**证明的，不是用论证。

**其它发现**：
- 把 3 个攻击 LLM 合起来，比最好的单攻击方多找到 **1.7–2.2 倍**的唯一成功输入

- 还办了个竞赛：18,422 场留出对抗，固定 gpt-oss-20b 底座

**对你的影响**：
- **不能再说"没人测自适应攻击"** —— 现在有专门的基准了
- **要改成**："已有自适应基准（Adaptive Adversaries），我们在此基础上……"

## 3. CoopGuard ★ 填掉了你的空白④的一部分

**出处**：arXiv:2608.00134，投 **IEEE TIFS**

**标题**：Stateful Cooperative Agents Safeguarding LLMs Against Evolving Multi-Turn Attacks

**一句话**：现有防御是**被动反应式**的，跟不上攻击者跨多轮的策略调整；这篇做**主动防御 + 多智能体协作**。

**三种防御策略**（分工给不同 Agent）：

| 策略 | 做什么 |
|---|---|
| **干扰（disruption）** | 控制响应节奏，**提高攻击成本** |
| **误导（misdirection）** | 故意给模糊输出，**把攻击者引到无效策略上** |
| **适应（adaptation）** | 对交互日志做**取证分析**，识别攻击模式、改进防御 |

再由一个**自适应协调机制**根据威胁升级动态调整策略。

**数据**：EMRA 数据集，5,200 条对抗样本，8 种攻击类型。

**效果**：
- ASR **平均降 69%**
- 欺骗性周旋（DR）是最好基线的 **6 倍以上**
- 攻击方 token 消耗 **+198.83%**

**对你的影响**：
- 它是**单 LLM 被多轮攻击**的防御，不是**MAS 内跨 Agent 传播**——这个区别还在
- 但它已经"多智能体协作 + 有状态 + 主动防御"了，**你的表述得往后退一步**

## 4. VIGIL ★ 你的清单里本来就该有它（A1 引过）

**出处**：**ACL 2026**，中科大
**标题**：VIGIL: Defending LLM Agents Against Tool Stream Injection via Verify-Before-Commit

**它要解决什么**（它的问题陈述写得很好，值得学）：

> 现有防御面临一个**两难**：越强的模型因为对齐得好，**反而会优先执行被注入的规则**；而静态防护机制又会**切断自适应推理所需的反馈回路**。

**它怎么做**：从"限制隔离"转向 **verify-before-commit（先验证再提交）协议**：
- **推测式假设生成**（speculative hypothesis generation）
- **意图锚定的验证**（intent-grounded verification）

**效果**：ASR 再降 **22% 以上**，同时在攻击下把**可用性翻倍**（对比静态基线）。

**还有**：SIREN 基准，959 个**工具流注入**案例。

**对你的影响**：
- 它做的就是"**让 Agent 生成假设，再验证意图**"——**跟你的"认知校验"思路是同一条线**

## 5. Pictionary（Render Before Reading）★ 思路最漂亮的一篇

**出处**：arXiv:2609.36121，**ETH Zurich + Leiden**（**Tramèr 组**，就是 CaMeL 那个组）
**标题**：Render Before Reading: Visual Rendering as a Prompt Injection Defense

**它的核心发现**（一句话）：

> **多模态 LLM 更容易执行"文本形式"的恶意指令，而同样的指令用图片等非文本通道给它，它就不太会听。**

**为什么**（它的假设）：**指令微调是文本中心的**——模型被训练成"服从文本指令"，而把其他模态**当成要解析的内容**，不当成指令。

**然后它把这个"模态差"变成了防御**：

```
把所有不可信的内容，在送进模型之前，
【渲染成印刷体图片】（或者音频）

→ 模型不再把它当指令，只当内容解析
→ 训练-free，不用改模型
```

**效果**：
- 10 个模型、2 个基准（DirectInject、AgentDojo）
- **即使面对最强的自适应攻击和人类红队，ASR 仍然下降**
- 可用性基本保住
- 反过来验证：如果拿图片渲染过的指令做**良性微调**，这个"模态差"就会被磨掉——**说明它确实来自文本中心的指令微调分布**

**为什么值得你重点学**：

1. **它是"结构约束"的完美例子**——不检查内容，直接**换通道**，让指令在结构上失效
2. **它主动评估了自适应攻击**——这正是你的空白②说要做的，人家已经做了
3. **它是 Tramèr 组的**——这个组的论文你要持续跟

**对你的启发**：星上场景里，**遥测/气象/影像数据是不是也可以做"通道降级"**？比如：外部来的内容**一律先转成结构化字段**（而不是自然语言），Agent 就只能读字段、读不到"话"。这跟你原来的"区分数据和话"是同一个思路，**但 Pictionary 给了它一个更强的理论依据和实验范式**。

## 6. Toward Trustworthy Agentic AI（多模态溯源框架）

**出处**：arXiv:2512.23557

**一句话**：提出 **Cross-Agent Multimodal Provenance-Aware Defense Framework（跨 Agent 多模态溯源防御框架）**。

**三个组件 + 一个账本**：

| 组件 | 做什么 |
|---|---|
| **文本净化 Agent** | 清洗文本输入 |
| **视觉净化 Agent** | 清洗图像输入 |
| **输出验证 Agent** | **所有 LLM 输出在下发前独立验证** |
| **溯源账本（provenance ledger）** | 记录每个内容的**模态、来源、信任级别**，贯穿整个 Agent 网络 |

**它明确针对的场景**（跟你要做的很像）：
> 恶意指令**藏在文本、图片、元数据、或 Agent 间消息里**，沿图传播，导致意外行为、违反策略、**状态损坏**。

**对你的影响**：
- 这篇**把"多模态 + 溯源 + 跨 Agent"三件事合起来了**——你的空白③被它填了
- **但它是框架性论文**（8 页，实验规模小），**没有在真实约束下验证**（比如算力受限）
- **这正好留了一个口子给你**：它的框架**代价多大？在星上跑得动吗？**

# 第五部分：领域现状总结

## 已经形成共识的三条

1. **单步防护不够**——攻击是跨轮、跨主体的，单点判断必然失效
2. **提示级防护不可靠**——要靠架构级；而且攻击方论文（Crescendo §6.3）自己就说"应该假设 LLM 最终都会被越狱"
3. **评测必须放到多轮、自适应攻击下做**——这一条已经有基准支持：**只算第一轮 ASR 0–1%，放到 15 轮变 7.9–16.8%**

## 还有分歧、或者没解决的三条

1. **有状态防御的开销**——SSH 要多智能体做推测、CoopGuard 要多 LLM 协作、多模态溯源要三个净化验证 Agent。**这些开销在受限环境下能不能接受，现有论文都没回答。**
2. **来源可验证，内容真伪没法验证**——所有工作都在**把溯源做细**（provenance ledger、签名、链路记录），但**没有一篇解决"来源合法、内容是假的"**。
3. **「不改动作、只改认知」这类攻击怎么观测**——现有工作都在动作空间做判断（SSH 看轨迹树、VIGIL 看工具流意图、CoopGuard 看日志模式），而一个攻击可以**完全不改动作**。

## 一个值得注意的结构性事实

把这四条技术路线和它们的**算力假设**列一下：

| 技术路线 | 代表工作 | 假设的算力 |
|---|---|---|
| 推测—验证 | Speculative Safety Honeypot、VIGIL | 多智能体 / 多次 LLM 调用 |
| 多智能体协作防御 | CoopGuard | 多个 LLM 协作 |
| 多模态溯源 | Toward Trustworthy Agentic AI、Pictionary | 三个净化 / 验证 Agent |
| 有状态跨轮防御 | Adaptive Adversaries（基准） | 跨轮维护状态 |

**这四条路线都建立在同一个前提上：算力充裕。**

**这不是"空白"，是一个观察**——现有工作在云端算力充足的前提下都成立；算力受限时这些方法还剩多少，目前**没有论文回答**。

## 二、每篇一句话

**多步检测三件套**
- **CausalTrace**：把轨迹画成因果图，问「去掉注入那段，这个坏结果还会不会发生」，用 do-calculus 算。F1 99.2%，注入点检测 94.8%
- **Peak+Accumulation**：纯正则 + 算式把多轮分加成一个总分，证明加权平均有天花板。recall 90.8%，**但对「话题慢慢跑偏」类攻击 recall 是 0%**
- **Fraud Layer**：42 个结构化「形状」特征 + XGBoost，**执行前 4.6ms 拦**。AUC 0.97

**记忆/信念**
- **PerMIT**：记忆读写收窄成有限接口，不可信值要人确认才「背书」。**Lean 4 机检定理 + ASR 全 0**，但良性误拒 17–32%
- **CAPTURE**：区分「偏好真的变了」vs「记忆被投毒」，用神经微分方程做信念追踪。投毒成功率 11.5%，但**自适应攻击者下升到 24.7%**
- **MAP-Graph**：多 Agent 共享记忆的 provenance 图，动作前加风险敏感门。任务成功 94.96%

**授权/策略**
- **Progent**：权限写成符号规则，LLM 自动生成策略，**SMT 求解器判定每次更新是收紧还是扩大**——收紧自动应用，扩大要人批。叫 monotonic confinement
- **Action-Class Authority**：给动作标可撤等级，闸门只读声明不听 Agent 说。**没有实验、没有定理、无代码，Zenodo 68 浏览 2 下载**

**卫星**
- **SkyGuard**：卫星 SAGIN 分层威胁狩猎，边缘 SLM 本地调查 + 中央 LLM 拼 ATT&CK 链。macro category recall 0.46，chain recall 0.43。静态基线全 0
- **AstroMind**：卫星行为推理基准，133 场景 399 题。**现有开源模型物理一致性普遍差**（中位相对误差 0.85 级），Llama-3-8B 19.70%（低于随机）

| 它测过「Agent 读到注入、写进简报当事实」吗 | **没有。而这正是课题的题眼** |
| 分量 | **单作者、政策学院（Heinz College）、4 页预印本、无会议、单标注员**；作者自己承认"分数打包在 guardrail 里拆不开" |

**S-LARF**（Elsevier 闭源，只拿到摘录两句）：打的是**星载异常检测模型**的对抗鲁棒性，**对象是 ML 检测器，不是 LLM Agent 的信念**。也撞不上。

**所以「现有工作极少关注 Agent 自己相信什么」这个判断，成立。**

# 工具调研：kelip-paper-reading（精读论文的 AI skill）

> 调研时间：2026-10-09。抖音刷到的，顺手验了一遍。

## 是什么

GitHub：https://github.com/skJack/kelip-paper-reading （作者 skJack，MIT，Python）

一句话：给它一个 arXiv 链接，它先把**材料拉齐**——PDF、arXiv 的 LaTeX 源码（拍平成 `paper.tex`）、

官方代码浅克隆——然后**一站一站带你读**，一次只讲一站，讲完问要不要往下走：

```
① 动机 → ② 架构 → ③ 训练（损失） → ④ 数据（一条样本长什么样）
      → ⑤ 输入输出信息流 → ⑥ 拿一个例子对着代码走一遍 →（可选 ⑦ 实验和现状）
```

边讲边记 `精读笔记.md`（每站要点 + 用到的图 + 我问过的问题）。

- **公式写成人能读的样子**：Unicode + 符号表 + 代一组小数字算一遍，不丢裸 LaTeX（对话界面常常渲染不出来）。

另外几条：区分「论文写的 / 代码里看到的 / 它推测的」；说"没懂"时换讲法而不是把原话拉长；
代码只读不跑；`profile.md` 记我的背景和常用场景，第 ⑥ 站拿它举例。

## 术语速查.md

# 术语速查（只记这些，其余先划掉）

> 用途：看累了就翻这一页。**只留 8 个词**，其他名词都是论文内部的编号，用到再查。

---

## 一条主线（所有词都挂在这上面）

> **攻击是一条链：从口子进来 → 往下传 → 最后动手。**
> **防御要让整条链闭不上口。**——这就是你导师说的"连环锁"。

三个词就够：**怎么进 → 怎么传 → 怎么动手**。

---

## 八个必须记的

| 词 | 大白话 |
|---|---|
| **主体 principal** | 一个**能被单独叫到**的参与者（一个 Agent、一个服务）。用这个词是为了分清"同事"和"外人"。 |
| **接口 interface** | 攻击**能钻进来的口子**。别记六个，只分三类：**进来的**（用户输入、检索到的文档、API 返回）→ **往下传的**（Agent 之间的消息、写进记忆的东西）→ **动手的**（调工具、执行指令）。 |
| **攻击路径 attack path** | 攻击从入口走到后果的**整条链**。**别盯单点，盯链。** |
| **路径闭合 path closure** | 防御把**整条链**堵死。**不是"某处加了检查"，而是"从任何入口到后果，路上都必然撞上一道检查"**。它是整张图的属性，不是某个点的属性。打比方：保险柜不能只锁前门——**要么所有门都锁，要么锁住唯一那条通路**。 |
| **认知攻击 cognition attack** | 不直接命令你干啥，而是**慢慢改你对任务的判断**。← 你导师说的"逐步篡改认知"。 |
| **JBR / UAR** | 判断被绕过率 / 危险动作执行率。**要分开测**：JBR 高、UAR 低 = 判断被攻陷了，但动作被拦住了（A2 的核心发现）。 |
| **架构级防御** | 不靠提示词让模型"自觉"，而是**在结构上让它做不到**。反义词是"提示级防御"（靠系统提示挡，A1 证明不管用）。 |
| **能力 capability** | 一个 Agent **被允许干的事**，按角色裁剪。不是"什么都能干但请自觉"。 |

---

## 三个最容易迷糊的，展开讲

### 路径闭合 vs 连环锁（这两个容易混）

| | 含义 | 打比方 |
|---|---|---|
| **连环锁** | 一条路上**多道**锁，一道被绕过还有下一道 | **纵深** |
| **路径闭合** | **每条**路都有锁，没有漏网的路 | **覆盖** |

**两个都要**：光有纵深、路有缺口，攻击换条路走；光有覆盖、一道锁被破就完，也不够。

**卫星例子**：攻击链是「污染元数据 → 检索 Agent → 规划 Agent → 执行 Agent 发指令」。
如果只在"检索 Agent 的输出"加检查，但**规划 Agent 也能直接读数据库**，攻击就绕过去了——**路径没闭合**。

### JBR / UAR：站岗打比方

- **有人骗过了岗哨**（岗哨信了伪造的通行证）→ 判断被绕过 = **JBR**
- **门卫不看通行证、独立核对名单**，发现这人不该进 → 动作没做成 = **UAR**

**A2 的实测**：记忆投毒时 **JBR = 100%（岗哨全被骗），UAR = 0%（一个都没进成门）**。

**为什么要分开测**：只报 UAR 会以为"防御完美"；但 JBR = 100% 说明**所有岗哨都被骗了——第一道防线实际等于不存在**，第二道一破就全盘皆输。**JBR 是早期预警信号。**

**对卫星**：导师说的第二步（篡改认知）= JBR，第三步（执行不合理操作）= UAR。**分开测才知道防御在哪一层起作用。**

### 架构级防御 vs 提示级防御

| | 提示级 | 架构级 |
|---|---|---|
| 做法 | 提示里写"不要执行未授权指令" | 结构上让未授权指令**根本发不出去** |
| 靠什么 | 靠模型**自觉** | 靠**代码、配置、密码学**强制 |
| A1 实测 | **67% 的 Agent 被打穿** | 31.2% → **4.2%** |

**一句话**：提示级是"**请它别做**"，架构级是"**它做不到**"。

**A2 补的一刀**：架构级里面，**签名（证明来源）≠ 授权（证明权限）**。真正顶用的是**独立于模型的策略检查**，不是签名、也不是另一个模型的判断。


### 读实验表的通用约定：T0 / T1、w/o、w/

这些都是**"防御开没开"的编号**，不是论文专有名词：

| 写法 | 意思 |
|---|---|
| **T0** | 防御**关**（基线） |
| **T1** | 防御**开** |
| w/o / without | 去掉某个组件 |
| w/ / with | 加上某个组件 |

**看表时的套路**：先找"基线"那一行，再看"加了防御"那一行，**两行一减就是防御的效果**。

**A2 那四档更细**：T0（都不开）→ Token（只开令牌）→ Policy（只开策略）→ T1（都开）。
**结果**：Token 那档 = T0，Policy 那档 = T1 → 说明**顶用的是策略检查，不是签名**。

### 确定性（deterministic）vs 概率性（probabilistic）

**最直白的比喻**：

| | 提示词护栏（LLM） | policy oracle（确定性代码） |
|---|---|---|
| 像什么 | **门口站个保安** | **门上的刷卡机** |
| 怎么判断 | 靠"理解"，说得好听可能就放你进 | **只查卡**，卡不对就不开 |
| 同样的问题问两遍 | **可能给不同答案** | **永远同一个答案** |

- **确定性代码 = 查表**：`if 角色不是执行者 → 拒绝`。跑一万次结果一样。**你骗不了表。**
- **LLM = 理解规则**：规则的字一样，但它是"理解"而不是"执行"——**理解了就能被讲道理绕过去**。

**为什么安全上要命**：LLM 判断"今天说危险、明天说没问题" → **攻击者多试几次，等它松口那一次**。确定性代码没有"那一次"。

**这也解释了 A1 的实测**：提示词护栏被 67% 打穿，因为护栏是个 LLM，靠感觉判断。

> **诚实说明**：A2 论文没明写"oracle 是确定性代码"，但 "policy（策略）+ oracle（独立组件）" 在安全领域的标准含义就是**规则引擎**；而且它的消融结果（token 没用、policy 有用）只有在 policy 不吃话术的前提下才成立。

**oracle 这个词**：一个你能问它问题、它给**确定答案**的黑盒组件。区块链的"预言机"是同一个意思。

**它的边界**：oracle **只能查规则里明确定义的东西**——攻击者打"规则没想到的情况"，它查不出来。

### SOTA / ASR：读安全论文必遇的两个词

**SOTA = State Of The Art = 当前最先进的**

"SOTA 防御" = **当时最好的防御方法**。注意"当时"——论文都要跟 SOTA 比，否则会被说"你只打败了弱鸡"。

**ASR = Attack Success Rate = 攻击成功率**

试 100 次，30 次成功 → ASR = 30%。

**★ 为什么安全论文里"ASR > 0% 就算没防住"**

这是**安全领域的不对称性**：

| | 要做到 |
|---|---|
| **防御方** | **每一次**都必须防住 |
| **攻击方** | **只要成功一次**就够 |

所以 ASR 哪怕 1%，也说明**防御有洞**——攻击者可以反复试，试到成功为止。

**对比**：推荐系统准确率 90% 挺好；安全里"挡住 90%"= **没防住**，因为剩下 10% 会被挑出来用。

**其它常遇到的同类缩写**：

| 缩写 | 全称 | 意思 |
|---|---|---|
| **FPR** | False Positive Rate | **误拦率**——正常的东西被拦掉的比例 |
| **F1** | — | 精确率和召回率的调和平均，综合衡量判断质量 |
| **UAR** | Unsafe Action Rate | 危险动作**真正被执行**的比例 |
| **JBR** | Judgment Bypass Rate | **判断被绕过**的比例 |

### 越狱 vs 注入（别混用，会被抓）

| | 越狱 jailbreak | 注入 injection |
|---|---|---|
| 目标 | 让模型**说出**它本该拒绝的内容 | 让模型**执行**它本不该做的动作 |
| 攻击对象 | **模型本身** | **系统**（Agent + 工具 + 流程） |
| 典型 | Crescendo（A5）、角色扮演绕过 | 间接注入、工具输出投毒（A1） |
| 类比 | 骗一个人说错话 | 骗一个人去干坏事 |

**相关但不同**：A5（越狱）的结论——"模型层不可靠"——可以迁移到注入，但**别在方案里直接写"A5 证明了注入防不住"**，说法不严。

### ★ "防不住"要分三层说（这是本方向最核心的论证）

| 层次 | 防得住吗 | 依据 |
|---|---|---|
| 让模型自己**识别**恶意输入 | ❌ | A1 实测：护栏被 67% 打穿 |
| 让模型自己**记住**要守规矩 | ❌ | A5 实测：SR/GP 防不住 |
| 在系统层让危险动作**执行不了** | ✅ | A1：31.2%→4.2%；A2：UAR 0%；CaMeL：可证明 |
| （信任根被攻陷） | ❌ | 所有安全系统的终点 |

**正确的说法**：不是"防不住"，是"**不能靠模型防**"——防御位置要从"让模型自觉"换成"让结构上做不到"。

**为什么这是好消息**：如果模型层能防住，就不需要"多智能体防护机制"了。**正因为模型层不可靠，才必须把防御放进系统结构**——这就是"连环锁"的存在理由。

### ★ provenance（来源） vs validity（真伪）——本方向最关键的一组区分

| | 问题 | 例子 | 能不能**自动**验证 |
|---|---|---|---|
| **provenance** | 这个值**从哪来**？ | 来自传感器 #3、经链路 A、签名有效 | ✅ **能**（签名、链路记录、哈希） |
| **validity** | 这个值**是不是真的**？ | 实际云量 12%，它报了 45% | ❌ **不能**（需要跟"事实"对照，而你没有事实） |

**核心一句**：

> **现有防御能追踪"来源"，追踪不了"真伪"。而攻击改变的是"真伪"，不改变"来源"。**

**卫星例子**：

```
遥测：区域A 云量 = 45%
  provenance 检查：来自传感器#3，签名有效 → 【放行】
  validity  实际：云量是 12%，这是假值 → 【系统看不见】

capability 看到的是"传感器#3发的、签名有效、允许传给规划Agent"
它看不到"45% 这个数字是伪造的"——因为它没有"事实"可以对照
```

**生活类比**：收到微信"我是你领导，紧急转 5000 块"
- **provenance**：这微信号确实是领导注册的 ✅ 合法
- **validity**：但不是他本人发的（号被盗）❌ 假的
- **实名认证只解决 provenance；诈骗攻击的就是 validity**

**为什么它是两个问题的答案**：

- **"为什么不用过滤"**：过滤器要判断的是 **validity**——需要一个你没有的标准答案
- **"为什么不用查上游"**：查上游 = 追 **provenance**；追到传感器那层，**它说"45%"，你没法验证它是否说谎**。**provenance 链的终点是"只能相信、不能验证"的点**

**★ 关键洞察**：

> 现有防御全在做**第一件事**，因为第一件事可自动化验证。
> **这不是"防御做得不好"，是"第二件事在一般情况下不可判定"。**

**所以出路不是"验证真伪"，而是"不依赖真伪"**：

| 做法 | 怎么绕开 |
|---|---|
| **结构约束** | 不管数据真假，**都改不了动作** |
| **认知校验** | 不问"这个值真不真"，问"**我的认知跟初始锚点、跟多个来源是否一致**" |
