# 工具调研：kelip-paper-reading（精读论文的 AI skill）

> 调研时间：2026-10-09。抖音刷到的，顺手验了一遍。

## 是什么

GitHub：https://github.com/skJack/kelip-paper-reading （作者 skJack，MIT，Python）

一句话：给它一个 arXiv 链接，它先把**材料拉齐**——PDF、arXiv 的 LaTeX 源码（拍平成 `paper.tex`）、
逐页文本、带行号的 `outline.md`、每张图每个表单独裁成 PNG（外加一张 `_contact.png` 总览拼图）、
官方代码浅克隆——然后**一站一站带你读**，一次只讲一站，讲完问要不要往下走：

```
① 动机 → ② 架构 → ③ 训练（损失） → ④ 数据（一条样本长什么样）
      → ⑤ 输入输出信息流 → ⑥ 拿一个例子对着代码走一遍 →（可选 ⑦ 实验和现状）
```

边讲边记 `精读笔记.md`（每站要点 + 用到的图 + 我问过的问题）。

它跟"让 AI 总结一下这篇"的区别在两个硬规矩：

- **讲到哪张图就把那张 PNG 发出来**，先说「这张图是什么、怎么读」再讲机制。只说"见图 3"不算。
- **公式写成人能读的样子**：Unicode + 符号表 + 代一组小数字算一遍，不丢裸 LaTeX（对话界面常常渲染不出来）。

另外几条：区分「论文写的 / 代码里看到的 / 它推测的」；说"没懂"时换讲法而不是把原话拉长；
代码只读不跑；`profile.md` 记我的背景和常用场景，第 ⑥ 站拿它举例。

## 装法

```bash
git clone https://github.com/skJack/kelip-paper-reading.git ~/.dsh/skills/kelip-paper-reading
```

依赖只有 Python 3 + PyMuPDF，**本机已经装好了**（PyMuPDF 1.28.2），不用再 pip。
脚本只访问 arxiv.org / github.com / huggingface.co，我看过 import，没有多余依赖、没有上报。

## 实测（2026-10-09 本机跑的）

拿两篇真跑了 `fetch_paper.py`，都成功：

| 论文 | 结果 |
|---|---|
| **A1** Beyond Single-Model Injection（arXiv:2609.22949，6 页 workshop） | PDF + LaTeX 源码拍平（183 行）+ 逐页文本 + outline（带 paper.tex 行号）；图 0 张、表 2 张，两张表裁得干净（攻击向量表、防御效果表都是我要的数字）；代码正确判定为"没有" |
| π0（arXiv:2410.24164，17 页） | 图 14 张 + 表 1 张全部裁出，拼图检查过，架构图/饼图/曲线都在，位置对；代码没找到（论文里确实没写，要手动 `--code` 补 openpi） |

结论：**脚本这块是靠谱的**，不是 PPT 工程。

## 对我的方向合用吗

合用：

- ② 架构 + ⑤ 信息流 + ⑥ 对着代码走一遍——A/B 那批论文（CaMeL、AutoGen 系、多智能体 GIS）正好需要这个。
- ⑦ 实验和现状是我汇报要的「数字 + 对比对象 + 一句话意义」，虽然它是可选的。
- 拉材料这一步很省事：图裁好了，写 PPT 直接拿 `figures/` 里的 PNG。

不合用 / 要注意：

- ④ 数据那一站的模板是按 VLA 写的（动作、本体状态、指令），我的论文多半没有数据集，这一站会退化成"没写"。
- 它**不干批量调研**。阶段一那种"8 篇论文各出一张卡片"不是它的活，它是一篇往深里挖。
- 仓库是 2026-10-06 建的，**总共 2 个 commit**，作者一个人，96 star 基本是这两天涨起来的（抖音带过来的量）。质量靠 SKILL.md 的文本，脚本没测过太多论文类型，表格裁得比图差。

## 结论

值得装，但别当主力工作流用。定位是**「要精读某一篇、而且要读到能给别人讲」的时候用**，
比如 A1、B1 这两篇要写进方案的。

用法：`读一下这篇 https://arxiv.org/abs/2609.22949`
