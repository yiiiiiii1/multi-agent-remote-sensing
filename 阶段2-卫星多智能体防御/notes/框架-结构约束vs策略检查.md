# 框架：防御的两种类型（结构约束 vs 策略检查）

> 起因：2026-10 讨论 CaMeL 的"嵌套规划器"修法时发现——**它把结构约束退化成策略检查，于是又多了一个 oracle 依赖**。
> 用途：这是"防御设计"那一节的骨架，也是判断一个防御强不强的标尺。

---

## 一、两种兜底方式

| | **结构约束（structural）** | **策略检查（policy / oracle）** |
|---|---|---|
| 怎么工作 | **物理上做不到** | **判断一下**，然后放行 / 拒绝 |
| 例子 | 切断数据回流、计划定死、基础设施层裁剪权限 | policy oracle、capability 检查、内容过滤、异常检测 |
| 押在哪 | **不需要信任任何判断** | **策略完备 + 判定组件可信** |
| 防自适应攻击 | 较能（攻击者绕不过结构） | **弱**（自适应攻击专门找策略漏洞） |
| 弱点 | **牺牲能力 / 可用性** | 策略总有覆盖不到的地方 |

**一句话**：

> **结构约束是"压根流不过去"；策略检查是"检查后拒绝"。**

---

## 二、把已知工作放进去

| 工作 | 兜底方式 |
|---|---|
| **A2**（信任传播与结构遏制） | 策略检查（policy oracle） |
| **A1 的 D3**（按角色限定工具权限） | **结构约束**（在 API 网关基础设施层强制，不靠提示） |
| **B2 的 Action-Selector** | **结构约束**（切断工具输出回流——不是"判断该不该给"，是"压根不给"） |
| **B2 的 Plan-Then-Execute** | **结构约束**（计划定死，脏数据改不了） |
| **B2 的 Dual LLM** | **结构约束**（隔离 LLM 没有工具） |
| **CaMeL 原版** | **结构（控制流定死）+ 策略（capability）** ← 两条腿 |
| **CaMeL + 嵌套规划器** | **只剩策略** ← 腿断了一条 |

### ★ 关键洞察：嵌套规划器就是一次"退化"

> 加嵌套规划器 = **把"控制流定死"这条结构约束，换成了"运行时 capability 检查"这条策略检查。**
> **结构约束不需要判断，所以没有 oracle；换掉之后，就必须新加一个 oracle 依赖。**

**这也解释了为什么自适应攻击能到 85%**：**大部分防御是策略型的**——策略总有没覆盖到的地方，攻击者就找那儿。

**而结构型防御的弱点完全不同**：不担心被绕，问题是**牺牲能力**（Action-Selector 几乎放弃自主性）和**"数据决定动作"这类任务做不了**。

---

## 三、卫星场景：哪些能做成结构型？

| 环节 | 怎么做成**结构型** |
|---|---|
| **遥操指令的发送接口** | 影像 / 遥测数据管道**在架构上就没连到动作接口**——不是"检查后拒绝"，是**流不过去** |
| **姿态控制** | **硬件 / 地面确认**才能下发——物理约束，攻击者绕不过 |
| **轮次** | 超过 N 轮**强制状态重置**——不需要判断"这轮是不是攻击" |
| **权限** | 在**基础设施层**裁剪工具 token（A1 的 D3），不靠提示 |
| **数据读取** | 给数据源分类：只读管道 vs 可触发动作的管道，**架构上分开** |

**只能做成策略型的**：policy oracle 查权限、capability 检查读者、异常检测、内容过滤。

---

## 四、完整阶梯（方案里可以这么写）

```
结构约束        最好，但要牺牲能力，且依赖"实现正确"
   ↓
策略检查        保留能力，但押在"策略完备 + 组件可信"
   ↓
信任根          总有一个（硬件 / 人），只能缩到最小
```

**可主张的贡献表述**：

> 现有防御（A2 的授权边界、CaMeL 的 capability、A1 的签名与净化）**大多落在"策略检查"这一层**，
> 因此其安全性最终依赖策略的完备性与判定组件的可信性——这正是自适应攻击的着力点（Maloyan & Namiot 报告 >85% 成功率）。
> 我们**尽可能把关键环节前移到"结构约束"**：让被污染的认知**在架构上无法转化为动作**，
> 策略检查只作为补充层。

---

## 五、诚实边界

**结构约束也不是万能的**：

1. **依赖实现正确**——代码有 bug 就破（要形式化验证 / 模糊测试）
2. **牺牲能力**——越结构，越死板（Action-Selector 几乎放弃自主性）
3. **最终仍有信任根**——结构也得由某段代码 / 某块硬件来保证

**所以三条原则不变**：**把信任根缩到最小、让攻陷可检测、让后果有界。**

---

## 六、一句话总结

**防御要么是结构（压根流不过去），要么是策略（检查后拒绝）。**
**结构更安全但要牺牲能力；策略保能力但押在策略完备上。**
**你要做的是：把关键那一环尽量做成结构型。**
