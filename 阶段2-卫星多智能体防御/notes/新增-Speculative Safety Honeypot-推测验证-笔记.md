# 笔记：Speculative Safety Honeypot（推测—验证式主动防御）

> **论文**：Speculative Safety Honeypot: Toward Proactive Defense Against Multi-turn Agent Attacks
> **作者**：Zezhong Wang、Xueyang Tang、Rui Lian、Yang Lou、Heqing Huang，华为技术有限公司（香港），通讯作者 Heqing Huang（p1 脚注）
> **出处**：ICML 2026 · arXiv:2609.39549（第 43 届 ICML，首尔，PMLR 306）
> **本地 PDF**：`papers/新增6 - Speculative Safety Honeypot (2609.39549).pdf`（16 页）
> **一句话**：不等攻击发生，趁目标 Agent 还在想的时候，用三个「没做安全对齐」的小模型在一边把接下来的对话演一遍，演出一棵推测树，再用真实动作剪枝，最后让现成检测器只给叶子打分——配合 PromptGuard 或 Judger，把 ASR 从 12.25% / 10.48% 压到 0%（Table 1，p6）。

---

## 一、为什么这篇值得读

这篇是这批文献里离课题最近的一篇，三个理由。

第一，它打的攻击跟我们的多步注入是同一条链。它分两类，多轮越狱和多轮间接注入（IPI）。IPI 机制它讲得直白：Agent 从外部来源读回一段指令，在一次本来正常的对话里被带偏（p1）。这就是「不改代码、不改系统提示，只污染它读到的输入」。

第二，它是主动防御，不是事后检测。它点名批评现有方法都靠历史上下文、是回顾式逻辑，遇到把恶意意图拆到多轮里藏起来的攻击就抓不住（p1）。所以它把防线往前挪一步，攻击还没落到真实环境就先在模拟里跑一遍。

第三，它便宜。模拟器 Dolphin3-3B，目标 Agent Qwen3-235B，作者自己算的参数开销是 1.3%（p9）。而且是即插即用的插件（p1），不换原检测器，只给检测器喂更多决策冗余，对我们的轻量化约束天生对味。

还有一条隐含的：它的结论是「不太准的检测器加推测树也能到 0% ASR」——安全性的瓶颈不一定在检测器多强，而在你给它看什么。

---

## 二、它的出发点（要解决什么问题）

LLM Agent 的威胁正从单轮 prompt 攻击演化为复杂多轮交互攻击，两个典型场景（p1）。

一是多轮越狱。恶意用户跨若干轮引导 Agent，把载荷拆开绕过过滤。它举的例子：Crescendo 用良性试探累积有害上下文，ASJA 操纵对话历史把自注意力从安全关键 token 挪走，AMA 用跨域类比伪装意图。论文给这现象起名叫「上下文漂移」，说累积的语义权重最终压过初始的安全对齐（p2）。

二是多轮 IPI。Agent 在正常对话里从外部读到恶意指令后触发有害动作。它列的基准是 InjecAgent、AgentDojo、STAC，说文档或工具输出里的隐藏指令能在没有直接用户输入的情况下搞坏整个工作流，多步任务里这些被污染的观测会逐步腐蚀 Agent 的内部规划（p2）。

它对现有防御的判断是全文最有用的：**过滤严了误报高，阈值放松了就抓不住拆散序列里的深层恶意意图**（p1）。现有方法归两类，基于提示词的（Sandwich、Spotlight、PromptArmor、Task Shield）和外部检测器（IPIGuard、MElon），共同缺陷是只在眼前上下文里判断，缺少对未来执行路径的预测建模（p2）。

一个细节值得抄：AgentDojo 上风险分数一开始接近零，因为攻击要走到后面某个注入点才触发（p8），这就是延迟激活。回顾式检测的弱点就在这，前面那些轮次单看都干净。

## 三、难点在哪

**一，未来的路径本来不知道，还得猜得像。** 附录 B 把它讲成「保真度」和「风险敏感度」的矛盾（p13）。保真度要贴近目标 Agent 的真实执行逻辑，敏感度要比目标 Agent 更容易被诱骗。它的取舍很硬：高风险场景下敏感度优先，哪怕目标 Agent 靠自己对齐能扛住，模拟器也必须表现出「已经被攻破」，才能把漏洞暴露出来。

**二，算力预算有限还要覆盖风险空间。** 不能无限展开，它的说法是「在有限算力预算内最大化风险空间的探索」（p2）。这直接引出多样性导向 Beam Search。

**三，误报直接吃掉可用性。** 它承认误报会导致过度拦截，让用户觉得 Agent 变笨（p9）。所以推测出来的东西不能随便报警，必须跟真实发生的动作对得上，这就是验证阶段剪枝的动机。

**四，多轮链条上怎么对齐。** 真实动作和推测候选怎么算「同一个」？工具调用和文本的匹配方式完全不同，文本又不能太严，这个细节决定整套系统能不能用。

**五，模拟器本身是风险面。** 三个模拟器全都无安全对齐（p3），是设计选择，所以论文专门强调 Environment Simulator 只给合成反馈、不真执行。

## 四、方法（核心）——推测阶段与验证阶段

### 4.1 模拟系统怎么搭

三个 LLM 模拟器（p3）：**Assistant Simulator** 当目标 Agent 的代理人，用**没有安全对齐**的模型，靠高敏感度把风险早暴露；**User Simulator** 生成多样、含糊的交互意图，同样无对齐，为的是捕捉绕得过标准过滤器的边缘输入；**Environment Simulator** 给工具、MCP、数据库、第三方 Agent 提供合成反馈，**不真的执行**。

三者交互由预定义通信协议管（附录 A，p13），就是个三阶段循环：User Phase 每轮以新查询 UQ 开始；Assistant Phase 自己判断要不要调工具，可直接回答 AR 或发起调用 AC；Environment Phase 模拟执行并返回 ER；到最大轮数结束（Figure 5，p13）。

工程细节值得记：三个模拟器用 LoRA 做 SFT，但**不把权重合进主干**，而是作为并发 Multi-LoRA 适配器挂在**一个共享 LLM** 上（p5，Figure 2 画成 LoRA1/2/3）。论文说这么选是为了降显存，同时能在不同角色间高效切换上下文。等于一个 3B 底座干三个角色的活。

### 4.2 推测树怎么建

触发时机：**目标 Agent 一开始生成，SSH 就被触发**做异步推测。它克隆目标 Agent 当前的 message list 作为基础（p3）。注意是生成时并行跑，不是等生成完。

节点定义：**每一条消息就是一个节点**，Assistant 工具调用、Environment 反馈、User 请求都算（p3）。

两个超参数（p3）：**M** 是采样预算，决定每层推测带宽，也就是树的宽度；**D** 是最大深度，代表连续推测的步数。

**关键节点和常规节点怎么分**（p3）：**关键节点** = 用户请求 + Assistant 动作，这两类分支潜力高，算法在这里触发采样和路径展开；**常规节点** = 工具响应 + 逻辑总结，通常是前面动作的确定性延伸，只做一次采样，不再往下展开。这是它省算力的地方，同一层只有关键节点分叉，工具返回这种基本确定的走单线。

### 4.3 Beam Search 的 M、D，以及四步选择

算法在 Algorithm 1（p5），叫 Diversity-Oriented Beam Search。它跟传统推测解码的目标正好相反：推测解码追命中率，它追路径覆盖率，为的是找出高风险长尾情形（p3）。四步：

**一，分支与采样。** 按上一层分配的配额采样候选。根节点初始配额就是 M；往后每个节点的采样数由上一轮的选择结果动态决定（Algorithm 1 第 2、6 行）。

**二，行为聚类。** 把采出来的 M 个节点按功能或语义身份分堆（p3）。**工具调用**：函数名和参数**完全一致**才算等价。**自然语言文本**：用 **SimHash** 按 N-gram 骨架算相似度，公式是 Overlap(n_i, n_j) = bitcount(¬(Hash(n_i) ⊕ Hash(n_j))) / K，K 是哈希位数，重叠超过阈值归进同一簇，论文设的阈值是 **0.7**。

**三，双层洗牌。** 先打乱簇的顺序，再打乱簇内节点顺序（Algorithm 1 第 10 行），去掉采样偏差。

**四，轮询选择与配额再分配。** 在所有簇之间轮流取节点，直到取满 M 个（第 12-19 行）。关键副作用是：大簇里的冗余节点容易被丢，小簇里的节点可能被**反复选中**（允许 with replacement），于是少数簇的节点在下一轮拿到更高配额（p3）。论文原话是「有效地下采样常见行为、放大稀有行为」。配额传递也明确：选中节点 u 的 u.quota 等于它在 L_selected 里出现的次数（第 20-21 行）。常规节点走另一条路，跳过整套 Beam Search，单次采样直接延长路径。重复到最大深度 D，建成完整推测树。

### 4.4 验证阶段怎么剪枝，怎么匹配

思路是用目标 Agent 的**真实动作**校验推测树，把范围收窄（p4）。

**剪枝**：拿真实动作跟那 M 个推测候选比，用的是跟 3.2 节**同一套行为聚类逻辑**。**函数调用**做函数名和参数的**精确匹配**；**文本回复**还是用 **SimHash** 算相似度。匹配上就把树剪到只留那个匹配簇对应的子树；**匹配不上就保留整棵树**，当作未来风险的参考（p4）。这个「找不到就留着」很关键，不让一次没猜中就丢掉风险信息。

**打分**：剪完枝对剩下的所有叶子做评估。注意**它自己不做检测**，用的是 Agent 原系统里现成的检测器，比如有害内容分类器或外部 LLM 判官。喂法是：把每条推测轨迹从根到叶的**完整 message list 序列化成一个字符串**，送进检测器做二分类，必要时截断以适配上下文长度（p4）。每个叶子标成 risk 或 safe。风险分数定义为「被判危险的叶子占全部被评估叶子的比例」，S(T) = (1/|L_leaf(T)|) · Σ I(D_risk(n0→l) = risky)（p4）。

**两个阈值**（p4）：τ1 是推测成功匹配到真实动作时用的，τ2 是没匹配上时用的，论文设 **τ1 < τ2**。理由是没匹配上说明推测相关性可能低，阈值高一点压误报；匹配上了说明推测可靠，可以用更低阈值做更严的风险控制。触发条件是 S(T) > τ。**τ1、τ2 的具体数值原文未说明**，附录 D.2 标题写了「Hyperparameter Analysis」但正文是空的（p14）。

**触发后**（p4）：可注入引导提示、重采样该动作、或直接终止执行。实验里用重采样，一旦某分支风险分数超阈值就重采样，直到动作落在高风险分支外；最多重采 5 次，5 次还找不到安全动作就中断生成（p6）。

### 4.5 差异化对齐（模拟器怎么训出来）

做法是**故意把模拟器训得又像又脆**（p5、p13-14）。像这半边：种子数据用 Toucan 的 QWEN3 子集，过滤条件卡在问题分 ≥ 4.3、答案分 ≥ 4.5、工具调用完美且顺序正确，再用 MinHash 去重；然后拿这些指令去问 Qwen-235B，收集**原始响应轨迹**，剥掉长 CoT（`<think>` 标签内容）且**不做二次校验**，连目标 Agent 的错误一起学——作者的论证是保真蒸馏要逼近的是**完整行为分布**，不是理想化表现。产出 **11,000 条**样本。

脆这半边：造了 **30 个**注入模板（Table 4，p15 列全，都是「system updates」「administrator overrides」这类字符串），把随机模板追加到样本 A 的工具返回结果后面、再接上样本 B 的用户查询，模拟「Agent 收到工具反馈被里面嵌的命令带偏」。产出 **4,700 条**样本。

## 五、实验结果——关键数字

**设置**（p5、p14）：四个基准——AgentDojo（banking、Slack 这类真实环境，97 任务 629 用例）、ActorAttack（多轮越狱，1,200 个有害目标，每个试 3 条路径，任一条成功即算）、XSTest（200 个含敏感词但意图良性的 prompt）、BFCL-v3（1,000 个多轮用例）。目标 Agent 是 Qwen3-235B（Qwen3-235B-A22B-Instruct-2507），SSH 侧是微调的 Dolphin3-3B。基线三类：提示词方法 Sandwich、Spotlight、Tool Filter；护栏 ProtectAI 和 PromptGuard（Prompt-Guard-86M）；判官 Judger 用 Qwen3-0.6B，判输出是否有害、动作是否偏离用户初始意图（p5）。

**主结果（Table 1，p6；完整版 Table 6，p16）**：

| 防御 | 平均 ASR（↓） | 平均 UA（↑） |
|---|---|---|
| 无防御 | 31.78% | 56.59% |
| Sandwich | 14.52% | 52.88% |
| PromptGuard 单用 | 12.25% | 36.02% |
| PromptGuard + SSH（M=8，D=4） | **0.00%** | 44.14% |
| Judger 单用 | 10.48% | 44.75% |
| Judger + SSH（M=8，D=4） | **0.00%** | 58.43% |

可以直接背的：不管底层检测器是哪个，接上 SSH 都是 **0% ASR**（p6）。PromptGuard 单用 12.25%、Judger 单用 10.48%，接上 SSH 都到 0%。**86M 的轻量检测器被 SSH 增强后也到 0% ASR**，不用为了那点增益去部署更大模型（p6）。AgentDojo 四个场景里 PromptGuard 的 UA 从 42.68 / 40.99 / 34.14 / 33.14，升到 50.90 / 48.79 / 41.10 / 41.66（Table 1）。**平均 UA 提升 8.12%**（p7，原文放在 travel 场景那段里），同页还说 travel 里 PromptGuard 把 UA 压掉了 20% 以上，原因是它主要在识别「有没有注入文本」，而不是判断「LLM 到底有没有被骗」（p7）。

**多轮越狱（Table 2，p7）**：攻击者用 Dolphin-X1-8B。Qwen3-235B 裸奔时 HarmBench 子集 ASR 41.5%、Circuit Breaker 子集 ASR 33.6%。

| M | HarmBench 暴露率 / ASR | Circuit Breaker 暴露率 / ASR |
|---|---|---|
| M=1 | 84.5% / 6.0% | 81.7% / 3.2% |
| M=3 | 94.0% / 0.5% | 90.2% / 1.7% |
| M=4 | 98.5% / 0.0% | 93.5% / 0.3% |
| M=5 | 99.5% / 0.0% | 96.0% / 0.0% |

M=1 时暴露率就到 84.5%，单次采样也能抓到越狱信号；M 加到 5，攻击被 100% 防住（p7）。边际递减也清楚：HarmBench 上 M 从 1 到 3 涨约 10 个点，M 从 4 到 5 只涨 1%（p7）。

**可用性（Table 3，p7）**：BFCL-v3 总体 45.13 → 44.88；XSTest 拒绝率 **0.0% → 0.0%**。**警告率（Figure 3，p7）**：AgentDojo 57.2%、ActorAttack 81.5%、BFCL-v3 **0.0%**、XSTest **0.0%**，BFCL-v3 上平均风险分数接近零，没有推测路径越阈值。**系统级 FPR 0.2%**（p9）。

**消融（Figure 4，p8）**：Beam Search 在风险暴露率和命中率上都稳定赢 Top-P。命中率有个落差——AgentDojo 工具调用环境，动作推测命中率 M=4 时 **47.2%**；ActorAttack 纯文本越狱上只有 **8%**。论文解释是后者内部验证机制被绕开，防御几乎只能靠推测分支提供的风险暴露。BFCL-v3 上 **D=5、M=16 命中率仍接近 70%**，它强调推测不需要跟真实路径精确对齐，70% 足够支撑有效剪枝（p8）。

**泛化（Table 5，p15）**：GPT-4o-mini 平均 ASR 8.4% → 0.0%；GPT-OSS-120B 14.9% → **0.7%**（不是 0），论文措辞是「降到接近零」（p14）。**开销**：3B 模拟器相对 235B 目标只加 **1.3%** 参数（p9）。

## 六、局限与作者自承的不足

作者在 p9 自己列了两条。

**第一条，算力和环境代价。** 原文说 SSH 的主要代价就是并行推测的额外算力。虽然用轻量 3B 模型加 Multi-LoRA，相对 235B 目标只加 1.3% 参数开销，但**跑 M=5 条并行分支的显存和功耗不可忽略**。缓解手段是 vLLM 批处理提吞吐、跨推测分支复用 KV cache 压能耗。最后它承认大规模部署时这笔「安全税」得跟一次成功入侵的代价一起权衡。

**第二条，误报对用户体验的冲击。** 误报导致过度拦截，让用户烦躁，也让 Agent 显得不聪明。它在 AgentDojo 上做到系统级 FPR 0.2%，虽然低，但一次误报（一个良性工具调用被拦或被重采样）会带来**大约 3-7 秒的延迟惩罚**，还可能让 Agent 给出更保守、更啰嗦的回复。作者还承认，在高度创意或开放式的任务里「有野心的意图」和「恶意意图」的边界很薄，可能还需要人在环（user-in-the-loop）机制来消解这类冲突（p9）。

除这两条，我自己读出几个原文没展开或者有出入的地方：

**M、D 记法在原文里自相矛盾。** Table 1 标题写「4 和 8 分别代表最大推测深度 4（D = 4）和 beam width 8（M = 4）」，括号里是 M = 4，可 beam width 又说 8；正文 p6 说「beam search width 设为 8，每步选 4 个节点展开」，p7 又说「M = 8、D = 4」。引用时别照抄括号里的 M = 4。

**阈值和超参缺。** τ1、τ2 具体数值没给，附录 D.2「Hyperparameter Analysis」只有标题、正文空（p14），复现不出来。

**模拟器无安全对齐，本身是暴露面。** 它靠「故意脆弱」换敏感度（p13），论文只强调 Environment Simulator 不真调工具、模拟过程隔离（p3），没讨论对模拟器本身的防护。

**验证只认动作。** 剪枝的唯一依据是真实动作能不能跟推测候选匹配（p4）。如果攻击压根不产生动作，或者产生的动作在工具名和参数上看着完全正常，验证阶段没有东西可以对。这是机制性盲区。

## 七、映射到卫星场景

结论：骨架能搬，但三处要改，其中一处是硬伤。

**能直接搬的。** 一，部署形态就是我们要的，3B 底座加 Multi-LoRA 扛三个角色，相对 235B 只加 1.3% 参数（p9）。星上不可能放 235B，但只要星上那个 Agent 是小模型，模拟器可以更小，「一个底座干多个角色」正好对上星上显存吃紧。二，它把 Environment Simulator 设计成不真调工具（p3），在我们这儿不是可选项而是必须项——遥操指令发出去就收不回，环境模拟器绝对不能在真链路上执行任何东西。三，它的干预手段有「注入引导提示、重采样、直接终止执行」三种（p4），映射到星上就是「重规划 / 换一条遥操指令 / 挂起等地面确认」，这个动作清单可用。

**要改的第一处，也是硬伤：M 条并行分支的显存和功耗。** 论文自己说跑 M=5 条并行分支的显存和功耗不可忽略（p9），而且这是在数据中心级 GPU、还用 vLLM 批处理和跨分支 KV cache 复用的前提下说的。搬到星上会放大好几倍。

一，推测树宽度按 M 走、深度按 D 走，KV cache 随分支数线性涨。M=8、D=4 是论文主力配置（p6、p7），同一时刻要维持 8 条并行推测上下文，每条还要往下推 4 步。星上只有一块 8-16 GB 加速器，还得同时放下目标 Agent 本身，这个账很难平。

二，星上散热和供电是硬约束，不是成本问题。地面可以靠多卡摊、靠电网兜；星上功率预算写死，没余地。而它那两个缓解手段（vLLM 批处理、复用 KV cache）都是冲吞吐去的，不是冲峰值功耗去的。再加上它推测是异步的、目标 Agent 一生成就并行开跑（p3），如果目标 Agent 跑在地面或星地链路另一端，要么星上本机跟着跑，要么逐轮把 message list 传下来，星地带宽先受不了。

我的判断：真要在星上用，M 得从 8 砍到 1-2，D 砍到 2-3。数据支持这个砍法——Table 2 里 M=1 的暴露率就有 84.5%（p7），M=5 才到 99.5%，说明 M 小的时候不是全无防护，只是防不干净。另一个折中是只在关键节点、只对高风险动作触发推测，用它「关键节点 / 常规节点」的划分（p3）做入口节流：星上常态只跑单分支轻量推测，风险分数抬头再扩宽。这一层调度论文没做，是我们自己要补的。

**要改的第二处：多模态。** 我们场景是数据多模态，而这篇的环境模拟器只处理文本和工具返回（p3），附录里也没有任何多模态实验。这块得自己补，而且多模态会加重上面显存的问题，图像 token 的 KV 开销比文本大得多。

**要改的第三处：动作物理不可逆。** 论文的干预点在动作**发出去之前**（p4），这是我们唯一能接受的窗口。但它的重采样是「最多重采 5 次，5 次还不行就中断」（p6）。在星上，「中断」得映射成安全默认行为——挂起、上报地面、维持当前状态。这个安全默认态论文没定义。

**最值得借的一条：它的威胁模型里，攻击者的目标就是让 Agent 去调一个不该调的工具。** 我们那条多步注入链的最后一步「在篡改后的认知下执行不合理操作或篡改遥操数据」，正好对应它的 Assistant 动作节点。所以可以把 SSH 当成这条链最后一环的独立校验——「连环锁」里的最后一道，管的就是「动作出去之前，先在模拟里把后续几步演一遍，看会不会跑到危险的地方」。前面几环（认知有没有被污染）它管不了，得另外补，这就是下一节第一问。

## 八、可能被追问的问题 + 答案

**问一：它跟你课题里说的「篡改认知」有什么区别？**

答：它的推测对象是**动作层**，不是认知层。节点定义就是一条条消息——工具调用、工具返回、用户请求（p3），验证阶段唯一的比对依据也是真实动作（p4）。那就有个漏洞：一个攻击可以**完全不产生动作**。Agent 没调任何工具，只是把被污染的判断写进给操作员的报告里，或者写进一句结论里。这种时候推测树上没有节点能跟真实动作对齐，剪枝无从谈起，风险分数也没落点。它能抓「这个 Agent 接下来要调 transfer_password 这种危险工具」，抓不了「这 Agent 脑子里的东西被换了但行为看着正常」。所以它是我们防线的最后一道，不是全部。

**问二：模拟器用无安全对齐的模型，它自己不就是风险点？**

答：作者是有意这么选的，理由是敏感度——它要比目标 Agent 更容易被诱进去，才能当早期预警（p13）。代价是这套模拟器本身是脆的，论文的防护只有一层：不真执行，只给合成反馈（p3）。搬到我们这儿，第一条纪律就是推测链路必须物理隔离，不能接任何真实遥测、遥操或指令上行通道。

**问三：为什么非要接一个现成检测器？它不能自己判吗？**

答：这是它整个设计的立意。它把「决策冗余」和「判断精度」拆开：推测树提供同一时刻的多个未来分支，检测器只对一个叶子做二分类（p4）。结果就是检测器的绝对精度没那么重要——PromptGuard 单用 12.25% ASR、Judger 单用 10.48%，接上 SSH 都是 0%，连 86M 的小检测器接上也能到 0%（Table 1，p6）。这对我们很划算，星上放不下强判官，放个小的，让推测树补。

**问四：M 和 D 怎么定？星上能开多大？**

答：M 是采样预算也就是树的宽度，D 是最大推测深度（p3）。论文主力配置 M=8、D=4（p6、p7），ActorAttack 上扫到 M=5 就 100% 防住（p7）。代价是显存和功耗，作者说 M=5 条并行分支「不可忽略」（p9）。注意原文对 M、D 的记法有矛盾，Table 1 标题把 M 写成 4、正文又写 8（p6），引用别照抄。星上我会先砍到 M=1-2、D=2-3，因为它自己的数据显示 M=1 时暴露率已经有 84.5%（Table 2，p7）。

**问五：命中率只有 47.2%，甚至 8%，这还能用？**

答：能用，这是它论证里比较关键的一步。命中率是「推测路径撞上真实路径」的比例，AgentDojo 工具环境下 M=4 时 47.2%，纯文本越狱的 ActorAttack 上只有 8%（p8）。论文解释是推测**不需要跟真实路径精确对齐**，BFCL-v3 上 D=5、M=16 命中率接近 70%，作者说这个量级就够支撑有效剪枝。命中率低也不代表没用，没命中时它保留整棵树当参考（p4）。

**问六：0% ASR 是不是有点可疑？**

答：分两处看。一，这个 0% 有条件：目标 Agent 是 Qwen3-235B，用重采样策略、最多重采 5 次（p6）。二，泛化到别的目标模型就没那么干净——GPT-4o-mini 是 8.4% → 0.0%，但 GPT-OSS-120B 是 14.9% → **0.7%**，不是 0（Table 5，p15），论文自己的措辞也是「接近零」（p14）。引用时最好带上「Qwen3-235B 上 0%」这个限定。

**问七：误杀率怎么样？会不会把正常任务也拦了？**

答：系统级 FPR 0.2%（p9），但每次误报成本不低，大约 3-7 秒延迟，还可能让 Agent 变保守、变啰嗦（p9）。可用性上 BFCL-v3 总体 45.13 → 44.88（Table 3，p7），XSTest 拒绝率 0.0% → 0.0%，警告率 BFCL-v3 和 XSTest 都是 0.0%（Figure 3，p7），所以确实没伤到正常任务。不过作者自己认了，创意类、开放式任务里「有野心」和「恶意」的边界很薄，可能得靠人在环补（p9）。

## 九、值得顺藤摸的引用

前五个优先：

1. **Speculative Decoding**（Leviathan et al., ICML 2023，p2）——整套思路的来源，小模型打草稿、大模型并行验证。看这篇才明白它把「token 级推测」抬到「动作级推测」跨了多远。
2. **Dynamic Speculative Agent Planning（DSP）**（Guan et al., 2025，arXiv:2509.01920，p2）——把推测框架用到 Agent 工作流，小模型起草多步动作、大模型验证，是它最直接的先例。
3. **Speculative Actions: A Lossless Framework for Faster Agentic Systems**（Ye et al., 2025，arXiv:2510.04371，p2）——预测环境状态和用户动作来支持连续规划。我们要做星上低延迟，这篇的工程视角更实用。
4. **STAC: When Innocent Tools Form Dangerous Chains to Jailbreak LLM Agents**（Li et al., 2025，arXiv:2509.25624，p2）——工具链式越狱，跟我们的多步攻击链形态最像。
5. **AgentDojo**（Debenedetti et al., NeurIPS 2024，p5、p14）——它主战场，97 任务 629 用例，我们自己搭评测绕不开。
6. **Toucan**（Xu et al., 2025b，arXiv:2510.01179，p13）——它全部训练数据的来源，现成的数据集。
7. **MElon**（Zhu et al., ICML 2025，p2）和 **IPIGuard**（An et al., EMNLP 2025，p2）——一个带可证明保证、一个用工具依赖图，都属「结构约束」那一派，跟 SSH 互补，也跟我们笔记里的 A2、B1 能对上话。
8. **Dolphin3.0-Qwen2.5-3B**（Hartford et al., 2024，p5）——它模拟器的底座，要复现从这儿开始。

攻击侧还要读两篇：**Crescendo**（Russinovich et al., USENIX Security 2025，p2）和 **ASJA**（Du et al., AAAI 2025，p2）。后者操纵对话历史把注意力从安全 token 上挪走，跟我们说的「逐步篡改认知使其合理化」几乎是一回事。

## 十、一句话总结

这篇把「猜未来」从解码加速搬到了安全防御：用三个故意不设防的 3B 模拟器，趁 Agent 还在想就异步把接下来几轮演成一棵树，再用真实动作剪枝，最后让现成检测器只给叶子打分——于是 12.25% 的 ASR 变成 0%，参数开销只加 1.3%，代价是 M 条并行分支的显存和功耗。
