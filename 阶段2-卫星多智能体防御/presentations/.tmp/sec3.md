### 第 5 篇 · Design Patterns（P22–25）

**P22 · 题名页（10 秒）**

"第五篇是 Design Patterns，arXiv 预印本，**没有 venue**，**14 个作者**按字母序排，Google、IBM、微软、ETH 联合做的。它排在 CaMeL 前面，因为它给的是分类总览，CaMeL 是其中一条的深挖。"

**P23 · 动机与难点（35 秒）**

"它先承认一件事：**通用 Agent 提供不了可靠的安全保证**，因为注入的根因——模型分不清哪句是指令、哪句是数据——短期消不掉。

所以它把问题换掉了：不问怎么让通用 Agent 安全，问的是今天能造出哪些**既能干活、又抗注入**的 Agent。

这不是让模型变强，是把能力范围缩到能保证安全的那部分，拿可用性换安全。它还分开了两类东西：设计模式是选一个用，最佳实践是每个都得做。"

**P24 · 模型（50 秒）**

"六个模式，**共同点是切断通道，不是检查内容**。它不判断这句话像不像注入，它让被污染的那份输入根本没有路走到有后果的动作上。

控制流这条线，灵活度递增。Action-Selector 最严，工具输出不回流，Agent 只从预定义清单里挑动作，论文说它**对注入免疫**；Plan-Then-Execute 让输出回流，但计划先定死，数据改不了动作序列；Code-Then-Execute 再推一步，先写程序，再执行程序。

数据隔离这条线。LLM Map-Reduce 派隔离子 Agent 处理单块数据，一块脏了不影响别的块；Dual LLM 是它的推广，隔离 LLM 没工具，只回符号不回内容，实际值由非 LLM 的调度器在调工具那一刻填进去。

还有正交的一条 Context-Minimization，管的是用户提示，指令用完就从上下文里删掉。

为什么能生效——要造成后果，攻击必须经过「数据影响动作」这个通道；通道切断了，注入再狠也只是噪音，不用先识别它。代价也很清楚，能力被砍掉了。"

**P25 · 实验结果（25 秒）**

"这一页得先说清楚：**这是设计模式论文，不是实证论文，没有 benchmark 数字**。价值在分类，加 **10 个案例**，每个案例给的都是有漏洞的实现和稳健设计的对照。

它自己承认的那处最有信息量：**Plan-Then-Execute 和 Code-Then-Execute 都只防改动作，不防改参数**。日历里藏一句注入，改不了计划，但能把发给老板的邮件内容随便换掉。

还有一个共同盲区：只改生成内容、不改控制流也不改数据流的攻击，这六个模式都管不了。

**对星上——切断通道这一类最省算力，不加模型、不加判官，只限制信息流，正好压在星上算力受限这条约束上。**"

### 第 7 篇 · Speculative Safety Honeypot（P30–33）

**P30 · 题名页（10 秒）**

"第七篇是 Speculative Safety Honeypot，**ICML 2026**，华为香港做的。这篇离我们最近，我多给一分钟。"

**P31 · 动机与难点（45 秒）**

"现有检测都是回顾式的，靠已经发生的上下文判断，只能事后反应，过滤严了误报高，阈值松了就漏。

难点是攻击把恶意意图拆到多轮里，前面每一轮单看都干净。它举 AgentDojo 的例子——风险分数一开始接近零，因为攻击要走到后面某个注入点才触发，这叫延迟激活。

所以它把依据从「已经发生了什么」换成「接下来可能发生什么」：趁目标 Agent 还在生成，在一边把它后面几轮先演一遍，攻击没落到真实环境就先在模拟里跑出来。"

**P32 · 模型（70 秒）**

"三个模拟器，**都没做安全对齐**。Assistant 当目标 Agent 的替身，故意比真的更容易被诱进去；User 生成多样、含糊的意图，专挑绕得过过滤器的边缘输入；Environment 只给合成反馈，不真调工具。底座是 Dolphin3-3B，三个角色用 Multi-LoRA 挂在同一个底座上，一个 3B 干三份活。

树怎么建。目标 Agent 一开始生成，就异步克隆它的 message list，一条消息一个节点，宽度 M、深度 D。只有用户请求和 Agent 动作这类关键节点才分叉，工具返回这种确定性的走单线，省下的算力全堆在分叉上。

Beam Search **不是追命中率，是追路径覆盖率**。候选先按行为聚簇，函数调用要名字和参数完全一致才算一类，文本用 SimHash 算相似度；然后簇间轮流取，大簇里冗余的被丢掉，小簇的反被反复选中，稀有行为下一轮就拿到更高配额。

验证。真实动作来了就对一遍，函数调用精确匹配名字和参数，文本还是 SimHash；对上就剪到对应的子树，对不上整棵树留着当参考。最后让现成检测器只给叶子打分，风险分是危险叶子占全部叶子的比例，超阈值就重采样或者终止。

为什么能生效——它不要求检测器准，只要求检测器看得到。检测器看眼前一轮会漏，但它面前摆的是同一时刻的多条未来分支，只要有一条跑到危险的地方，风险分就抬头。"

**P33 · 实验结果（55 秒）**

"数字：**PromptGuard 12.25%、Judger 10.48%，接上 SSH 都是 0%**，连 **86M** 那个 PromptGuard 接上也是 0%，不用换大模型。

但 0% 有前提：目标模型是 Qwen3-235B，靠重采样，**最多重采 5 次**。换目标模型就没这么干净——GPT-OSS-120B 是 **14.9% 降到 0.7%，不是 0**，论文自己的措辞是接近零。

命中率它自己给了：**AgentDojo M=4 是 47.2%，纯文本越狱只有 8%**；但没命中时整棵树留着当参考，所以照样防。

开销：模拟器相对 235B 目标 **参数只加 1.3%**，可作者自己说跑 M=5 条并行分支的显存和功耗不可忽略。

最要紧的一条是它的推测对象——**动作层**。全文没有 belief、没有 cognitive、没有 internal state，它只看 Agent 下一步做什么，不看 Agent 信了什么。这是我们课题的立足点。

再加上 **τ1、τ2 原文没给**，附录那一节只有标题、正文是空的，复现不出来。

**对星上——它能当连环锁的最后一道，卡在动作出去之前那一下；但认知有没有被污染它管不了，星上真正缺的是前面那几环。**"
