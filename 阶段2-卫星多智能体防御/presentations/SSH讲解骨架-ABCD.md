# 三、方法：A / B / C

## A · 系统与训练

### A-1 三个模拟器（3.1）

| 角色 | 演谁 | 关键设计 |
|---|---|---|
| **用户** | 用户 | 生成**多样、模糊**的意图，覆盖边角 |
| **助手** | 目标 Agent | 学它的执行习惯 |
| **环境** | 工具 / MCP / 数据库 / 第三方 Agent | **给合成反馈，不真执行**——推演隔离无害 |

**三个都用「无安全对齐」的模型。**

**必须落到**：**探子必须肯往坏处走，才能预报坏处。**

### A-2 Differentiated Alignment（3.4）

| 维度 | 要求 | 只做这个会怎样 |
|---|---|---|
| **保真** | 平时像主 Agent | 跟它一样难骗，**抓不到东西** |
| **敏感** | 遇攻击时**比主 Agent 更容易被带偏** | 推演跟它没关系，**没参考价值** |

**高风险场景里，敏感优先于保真**——哪怕主 Agent 靠对齐能挡住，**探子也要演成"被攻破"**。

**两份数据**：
- **11,000 条蒸馏**（235B 真实轨迹，去掉长 CoT 但**保留错误模式**）→ 保真
- **4,700 条合成**（正常指令从用户位置挪进工具返回）→ 保敏感
- **工具和用户**复用同一份 Toucan 数据，只把微调目标从 `assistant` 换成 `tool` / `user` 字段

**必须落到**：**探子不是"另一个主 Agent"，是"故意容易上当的那个版本"。**

---

## B · 推测：树怎么画出来（3.2 + Algorithm 1）

**① 起点**：Agent 每次开始生成，SSH **异步**克隆当前 **message list**（Agent 手上的全部上下文），**Agent 不等它**。

**② 两个超参**：**M = 树宽（5）**、**D = 最大深度（4）**。

**③ 多样性导向 Beam Search 三步**：

| 步 | 干什么 | 为什么 |
|---|---|---|
| **聚类** | 函数调用按**动作身份**精确匹配；自然语言用 **SimHash + N-gram**，**overlap 阈值 0.7** | 相似动作归一类 |
| **双层打乱 + 轮询（RR）** | 先随机打乱**类间**和**类内**顺序，再从每类**轮流**各取一个，取满 M | **不追命中率，要路径覆盖**——按概率取前 5 条会长得一样 |
| **配额再分配（RA）** | 数每个节点被选中几次，作为**下一层的采样预算** | 算力往"有希望"的路径挪 |

**节点分两类**：关键节点（用户请求、助手动作）**要展开**；普通节点（工具返回、逻辑总结）**只采一次**。

**必须落到**：**分堆、轮流拿、拿得多的下一层多给预算。**

---

## C · 验证、打分，以及告警后怎么响应（3.3 + 4.2.1）

**① 比对**：真实动作跟 M 条候选比——**函数调用比函数名 + 参数**（精确）；**文本用 SimHash** 算相似度。

**② 剪枝**

> **匹配上** → 只保留那一支的子树
> **匹配不上** → **保留原树**，当未来风险的参考

**③ 打分**：检测器看**剩余叶节点**。送进去的不是单个节点，是**从根到叶的整条路径**。

> **风险分 = 被判为有风险的叶子数 / 总叶子数**

**④ 双阈值 τ₁ < τ₂**

| 情况 | 用哪个 | 为什么 |
|---|---|---|
| 推测**命中** | **τ₁（低）** | 推测可信，**从严** |
| **未命中** | **τ₂（高）** | 参考价值低，**从宽防误报** |

**⑤ 超阈值后的三种响应**（p3）：**引导 / 重采样 / 直接终止**

**⑥ 实验里实际选的是「重采样」，不是直接终止**（p6，4.2.1）

> **不直接终止**。超阈值就重新生成，**直到生成出一个落在高风险分支之外的动作**。
> **最多 5 次**，5 次都找不到安全动作，**才中断**。

**为什么选这个**：

| 做法 | 后果 |
|---|---|
| 告警即终止 | 任务失败 → **UA 掉** → 安全但没用 |
| **先重采样** | 换个动作再来 → **任务还有机会完成** → **UA 保住** |

**这个选择的代价与收益**（p7）：SSH 加重采样，**平均 UA 提升 8.12%**。

**必须落到**：**它不靠"一告警就掐死"保安全，而是先让它重试最多 5 次——所以安全提上去了，功能反而没掉。**

# 四、Key advantages（第四大点，p2 引言第 4 段）

**这一段是论文唯一自称 "A key advantage of SSH" 的地方**，只有两条论断，都是机制层面的。**不放实验数字，也不放响应机制。**

## 优势一 · 给检测器「超出当前上下文」的预测信息

> 现有检测器只看当前这一段上下文。SSH 喂给它的是**一棵推测出来的未来树**。

## 优势二 · 决策冗余 → 降低对单个检测器精度的依赖

**论文原话**：

> 跟判**单个孤立节点**相比，推测树提供了更强的**决策冗余**。
> 因为判断依据是**整棵树上的风险趋势演化**，而不是某一刻的输出——**所以降低了对单个检测器绝对精度的依赖**。

**说人话**：**一个节点判错不要紧，多个判断互相兜底。**

**支撑这个论断的数字**（p6）：

> PromptGuard 单独用是 **12.25% ASR**，Judger 单独 **10.48%**；**加上 SSH，两个都变 0%**。
> **连 86M 的 PromptGuard 都能做到 0%**——不用为了小幅安全提升去上大模型。

**必须落到**：**它的优势不是"多了一个检测器"，是"让检测器不用那么准也行"。**

---

# 五、一句话把四块串起来

> **它用三个模拟器在后台推演未来（A），靠多样性 Beam Search 把风险路径铺开（B），用真实动作剪枝、再用两个阈值判风险（C）——所以能给检测器一棵未来的树、靠决策冗余降低对精度的依赖（第四大点）。**

# 六、四处别讲混

| 别混 | 正确 |
|---|---|
| **RR / RA** vs **重采样** | RR=轮询选、RA=配额再分配（**建树时**）；重采样是**告警后**的响应，归 C |
| **86M** vs **3B** | 86M = PromptGuard 检测器；3B = 探子骨干 |
| **并发** vs **轮流** | **逻辑上轮流**（用户→助手→环境）；**部署上并发**（三份 LoRA 常驻、按角色路由） |
| **优势** vs **证据** | 第四大点只放两条机制论断；8.12% 和 86M 是**支撑数字**，各自挂在该条下面 |
