# 一、两类威胁

| 类型 | 谁在攻击 | 例子 |

| **多轮越狱** | **攻击者本人就是用户** | 一轮轮把模型往坑里带 |

# 三、方法：A / B / C

## A · 系统：三个模拟器（3.1）

| 角色 | 演谁 | 关键设计 |
|---|---|---|
| **用户** | 用户 | 生成**多样、模糊**的意图，覆盖边角情况 |
| **助手** | 目标 Agent | 学它的执行习惯 |
| **环境** | 工具 / MCP / 数据库 / 第三方 Agent | **给合成反馈，不真执行**——保证推演隔离无害 |

**三个都用「无安全对齐」的模型。**

**必须落到**：**探子必须肯往坏处走，才能预报坏处。**

---

## A · 训练：Differentiated Alignment（3.4）

**两个方向相反的目标，分开调：**

| 维度 | 要求 | 只做这个会怎样 |
|---|---|---|
| **保真（Fidelity）** | 平时要像主 Agent | 跟它一样难骗，**抓不到东西** |
| **敏感（Sensitivity）** | 遇攻击时**比主 Agent 更容易被带偏** | 推演跟它没关系，**没参考价值** |

**论文原话**：在高风险场景里，**敏感优先于保真**——哪怕主 Agent 靠对齐能挡住，**探子也必须演成"被攻破"的样子**。

**两份数据各管一个维度**：

- **11,000 条蒸馏**（235B 的真实轨迹，去掉长 CoT 但**保留错误模式**）→ 保真
- **4,700 条合成**（把一条正常指令从用户位置挪进工具返回）→ 保敏感
- **工具和用户**直接复用同一份 Toucan 数据，只把微调目标从 `assistant` 字段换成 `tool` / `user` 字段

**必须落到**：**探子不是"另一个主 Agent"，是"故意容易上当的那个版本"。**

---

## B · 推测：树怎么画出来（3.2 + Algorithm 1）

**① 起点**：Agent 每次开始生成，SSH **异步**克隆当前 **message list**（Agent 手上的全部上下文），**Agent 不等它**。

**② 两个超参**：**M = 树宽（5 条分支）**、**D = 最大深度（4 层）**。

**③ 多样性导向 Beam Search（DBS）三步**：

| 步 | 干什么 | 为什么 |
|---|---|---|
| **聚类** | **函数调用**按动作身份精确匹配；**自然语言**用 SimHash + N-gram，**overlap 阈值 0.7** | 相似动作归一类 |
| **双层打乱 + 轮询（RR）** | 先随机打乱**类间**和**类内**顺序，再从每个类**轮流**各取一个，取满 M | **不追命中率，要路径覆盖**——按概率取前 5 条会长得一样 |
| **配额再分配（RA）** | 数每个节点被选中几次，作为**下一层的采样预算** | 把算力往"有希望"的路径挪 |

**节点分两类**：关键节点（用户请求、助手动作）**分支多，要展开**；普通节点（工具返回、逻辑总结）**基本确定，只采一次**。

**必须落到**：**分堆、轮流拿、拿得多的下一层多给预算。**

---

## C · 验证与打分（3.3）

**① 比对**：真实动作跟 M 条候选比——**函数调用比函数名 + 参数**（精确）；**文本用 SimHash** 算相似度。

**② 剪枝**：

> **匹配上** → 只保留那一支的子树
> **匹配不上** → **保留原树**，当未来风险的参考

**③ 打分**：检测器看**剩余叶节点**。送进去的不是单个节点，是**从根到叶的整条路径**（序列化成字符串）。

> **风险分 = 被判为有风险的叶子数 / 总叶子数**

**④ 双阈值 τ₁ < τ₂**：

| 情况 | 用哪个 | 为什么 |
|---|---|---|
| 推测**命中** | **τ₁（低）** | 推测可信，**从严** |
| **未命中** | **τ₂（高）** | 参考价值低，**从宽防误报** |

**⑤ 超阈值后三种响应**（p3）：**引导 / 重采样 / 直接终止**

**必须落到**：**对上了就剪窄，对不上就留着；风险分就是"有风险的叶子占多少"。**

# 四、D · 优势（三条，第三条是关键）

## ① 给检测器"超出当前上下文"的预测信息

> 现有检测器只看当前这一片上下文。SSH 给它的是一棵**推测出来的未来树**。

## ② 判断依据从"单个节点"变成"整棵树的趋势"

**论文原话**：跟判单个孤立节点相比，推测树提供了更强的**决策冗余**；因为判断依据是**整棵树上的风险趋势演化**，而不是某一刻的输出——**所以降低了对单个检测器绝对精度的依赖**。

**必须落到**：**一个节点判错不要紧，多个判断互相兜底。**

## ③ 重采样机制把可用性捞回来 ★

**这条最实在，也最容易被漏。**

**实验里实际选的是重采样，不是直接终止**（p6，4.2.1）：

> **不直接终止**。风险超阈值就触发**重采样**——重新生成，**直到生成出一个落在高风险分支之外的动作**。
> **最多 5 次**，5 次都找不到安全动作，**才中断**。

**为什么这么做**：

| 做法 | 后果 |
|---|---|
| 告警即终止 | 任务失败 → **UA 掉** → 安全但没用 |
| **先重采样** | 换个动作再来 → **任务还有机会完成** → **UA 保住** |

**论文给了数**（p7）：

> SSH 加上重采样，**平均 UA 提升 8.12%**。

**必须落到**：**它不靠"一告警就掐死"来保安全，而是先让它重试最多 5 次——所以安全提上去了，功能反而没掉。这个 8.12% 就是重采样换来的。**

---

# 五、一句话把 D 串起来

> **它给检测器一棵未来的树（①），让判断从看一个点变成看整体趋势（②），并且在报警时先让 Agent 重试而不是直接掐死（③）——所以既防住了，又没把功能砍掉。**

# 六、三处别讲混

| 别混 | 正确 |
|---|---|
| **RR / RA** vs **重采样** | RR=轮询选、RA=配额再分配（**建树时**）；重采样是**告警后**的响应 |
| **86M** vs **3B** | 86M = PromptGuard 检测器；3B = 探子骨干 |
| **并发** vs **轮流** | **逻辑上轮流**（用户→助手→环境）；**部署上并发**（三份 LoRA 常驻、按角色路由） |
