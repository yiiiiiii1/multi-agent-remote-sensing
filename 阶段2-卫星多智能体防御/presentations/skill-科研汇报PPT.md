# 科研论文汇报 PPT

做给导师看的**论文汇报 PPT**。核心是：**按论文逐篇讲，每篇四页，程序化生成，几何上不出错。**

---

## 一、先确认三件事（别直接开做）

1. **讲几篇、哪几篇**——逐篇讲意味着每篇占 4 页，篇数直接决定页数和时长
2. **每篇四页的固定结构**（除非用户另有要求）：
   **题名页 → 动机与难点 → 模型 → 实验结果**
3. **时长**——经验节奏：**每篇 2 分钟**（题名 10 秒 → 动机 40 秒 → 模型 40 秒 → 实验 30 秒），开场收尾各 2 分钟

> 页数公式：`4（开场） + 4×篇数 + 3（收尾）`
> 8 篇 → 39 页 → 20 分钟。

---

## 二、PPT 上「只放内容」

**这条最容易反复踩，务必先自检。**

**PPT 上不能出现**：

| 类别 | 反例 |
|---|---|
| 提到老师 / 导师 | 「导师给的」「需要老师拍板」「学生定不了」 |
| ★ 号与提醒 | 「★ 注意」「必须区分」「别说成会议论文」 |
| 讲法提示 | 「过渡：…」「预答：…」「预埋：…」「这里要说明…」 |
| 工作痕迹 | 「v2 修正」「（待讨论，未验证）」「全篇核心页」 |

**判断标准**：这句话是在说「我这次汇报该怎么讲」，还是在说「研究对象本身」？**是前者就删。**

**别靠记性——写个自检脚本，构建完自动跑**（`check_ppt.py`）：把 PPT 里所有文字（含表格）
抽出来，正则匹配违规词，命中就非 0 退出。实测这套正则能抓出：8 个题名页上的
「本篇四页：…」、KPI 卡里的「引用要注明版本」、副标题里的「导师给的三步」——
**这些靠自己复查都会漏。**

**删掉的东西放哪**：讲稿（`汇报稿-*.md`）、大纲（`*大纲*.md`）、notes。

**另外两条**：
- **论文一律用原标题，任何位置都不要自编简称**
  - **目录页**：写**完整原标题**（换行改空格），配「出处」和「定位」两列
  - **题名页**：写**完整原标题**（可按语义换行）
  - **页眉**：用「**第 N 篇 · 页类型**」（如「第 3 篇 · 模型」），**不要**写 "SSH""VIGIL""A1" 这类简称
  - **封面**：如果要列篇目，列「**定位**」（如「推测—验证」）而不是自编名
  - 自编编号/简称只能出现在**内部笔记和大纲**里，不能出现在 PPT 上
- **实验结果页优先放「论文原表格 / 原图」**，不要自己重画精简表——原表更有说服力，也省得抄错数字
  - 只有当论文**确实没有**合适的表/图时，才自己画
- 自己要画的表（如目录页）**只要表头和数据**，不要「特点」「说明」这类描述列——描述由讲的人说

## 三、结构模板

```
开场（4 页）
  P1  封面        标题 / 副标题 / 篇数与分类 / 日期
  P2  背景        用户给的命题 + 场景界定与约束
  P3  领域坐标    用一个框架把要讲的论文定位（来自综述或自己归纳）
  P4  目录        表格：# / 论文 / 出处 / 定位

正文（每篇 4 页）
  P·1 题名页      英文原标题 / 作者+单位 / 出处 / 一句话定位
  P·2 动机与难点  左栏「要解决什么」+「难点在哪」；右栏可放论文的问题示意图
  P·3 模型        核心机制。宽图（比例≥1.7）图上文下；方/竖图图右文左
  P·4 实验结果    精简表格 + KPI 大数字行 + 1~2 句要点；必要时配图

收尾（3 页）
  现状小结      共识 / 未解决 / 结构性事实
  后续计划      接下来读什么 + 需要确认的问题
  致谢
```

**排序逻辑**（按论文性质分两组，组内按时间或机理递进）：
- 攻击侧：范式 → 威胁模型 → 评测基准
- 防御侧：按防御机理从旧到新

## 五、防重叠：工程上的根本做法

**唯一可靠的办法：每个绘制函数都返回自己的底边 y，下一个元素相对它摆放。**

```python
def bullets(..., y, ...) -> new_y
def table(...,   y, ...) -> new_y
def image(...,   y, ...) -> new_y
def callout(..., y, ...) -> new_y
def kpi_row(..., y, ...) -> new_y
```

**三条必须遵守的细节**：

1. **python-pptx 的 `TextFrame` 没有 `height` 属性**——`tf.height = ...` 只是给对象加了个没用处的属性，**文本框高度一点没变**。
   正确做法：**先估算高度，再用 `shapes.add_textbox(x, y, w, h)` 建框**。
   （估高：按 `sum(1.0 if 中文 else 0.55 for ch in text)` 算宽度单位，除以每行容量取上整。）

2. **表格会自动长高**——`rows[i].height` 只是「最小高度」，内容换行时表格会超出你给的高度，后面的元素必然被压住。
   正确做法：**逐行估算需要的行数**（按列宽和字号），自己累加出真实高度并返回。

3. **图片按比例缩放并居中**：`sc = min(w/iw, h/ih)`，`x' = x + (w - iw*sc)/2`。**绝不要直接拉伸**，比例失真在投影上很明显。

4. **结果页的摆法要算，不要写死**：图可以「整幅在上、KPI 在下」，也可以「左图右文」。
   两种各算一次缩放倍率，**选大的那个**：

   ```python
   sA = min(CW / iw, (avail_h - reserved) / ih)     # 整幅在上
   sB = min(wl / iw, avail_h / ih)                   # 左图右文
   ```
   `reserved` 要**按实际组成累加**（图注 0.4 + KPI 行 1.1 + 每条 note 0.34），
   漏算就会顶到底边。

**收尾一定跑几何审计**（见第八节）。

## 六、从论文 PDF 自动裁图

**不要用「找空白行切带」的办法**——正文行距（~9pt）和图内元素间距（~3pt）差别不够大，会切错。
**要用矢量绘图对象**：

```python
def graphic_rects(page):
    out = [dr["rect"] for dr in page.get_drawings() if dr["rect"].width > 4 and dr["rect"].height > 4]
    for im in page.get_images(full=True):
        out += list(page.get_image_rects(im[0]))
    return out

def figure_bbox(page, cap_y, gap=34):
    # 找图注的 y 坐标（用 get_text('blocks') 里以 Figure/Fig./表 开头的块）
    rects = [r for r in graphic_rects(page) if r.y1 <= cap_y + 4]
    rects.sort(key=lambda r: r.y1, reverse=True)      # 靠图注的在前面
    u = pymupdf.Rect(rects[0])
    for r in rects[1:]:
        if u.y0 - r.y1 > gap:      # 与当前包围盒断开 → 到图顶了
            break
        u |= r
    # 扩展 x：把与图同高的文本块（图里的标签、注释框）也纳入
    for b in page.get_text("blocks"):
        br = pymupdf.Rect(b[:4])
        if br.y1 > u.y0 and br.y0 < u.y1 and br.height < u.height * 0.9:
            u |= br
    return u
```

然后 `page.get_pixmap(dpi=400, clip=u)` 渲染，再用非白像素裁白边（pad 8–10px）。

**裁表格：用显式坐标，不要用 `find_tables()`**

`page.find_tables()` 在学术论文上很不可靠（经常框错位置或框到旁边的图）。可靠做法：
1. 打印该页所有文本块（`get_text("blocks")`），看 y / x 范围
2. **人工判定表格的包围盒**（表注 + 表头 + 数据行）
3. 写进 `crop_tables.py` 的 `JOBS` 表：`(名字, 文件, 页码, (x0, y0, x1, y1))`
4. 400 dpi 渲染 + 自动裁白边

**表太长要截**：21 行的表缩到 7 英寸宽，投影上根本看不清。**截取「表注 + 表头 + 前几行」**，
把聚合数字放到 KPI 卡里。

**两个坑**：
- **双栏论文**：图注常通栏但图只在一栏。自动判栏很容易误伤——**给需要的那张手工指定横向范围**（按页宽比例），比写复杂启发式可靠。
- **表注在页顶**：`Table 1` 的图注在表**上方**，此时表在下面，不能用「往上收」的逻辑。**表格建议不裁**——在 PPT 里用原生表格重画（更清晰、可编辑、还能只留表头和数据）。

裁完**必须逐张 `read_image` 目检**：常见问题是左/右边缘被切掉（图里有文字标签但不在矢量对象里）。

## 七、讲稿（跟 PPT 配套交付）

每篇论文一段，逐页口播：

- **加粗**必须说出口的数字和关键句
- 括号里写**动作提示**（「放慢」「指这一步」），不是要念的字
- 篇末附**追问预答**：导师最可能问的 2–3 个问题 + 应答口径
- 全篇附**突发情况应对**：被问「那你打算做什么」、被否掉、被问住、被要求压缩时间

**时间被压缩的方案**也要写：15 分钟版删哪几页、10 分钟版只讲哪几页。

## 八、交付前必跑：几何审计

```python
# 1) 出界
for sh in slide.shapes:
    if sh.height and (sh.left < 0 or sh.top < 0 or
                      sh.left+sh.width > SW or sh.top+sh.height > SH):
        print("出界")

# 2) 文字溢出（粗估）
need = sum(估算每个 run 的行数 × 字号 × 1.25 / 72 for para in tf.paragraphs)
if need > sh.height/EMU + 0.15: print("溢出")

# 3) 图片/表格 与 其它元素重叠
#    只查图片与表格（形状作为底色与文字有意叠放，属正常）
```

**还有一条手工检查**：把 PPT 翻一遍，重点看**每页底部余量**——小于 0.3 英寸会显得挤，大于 1.8 英寸会显得空，都不好看。

## 九、内容质量的硬要求

- **每个数字都要能追到原文**。引论文出处前先核实（会议 / 期刊 / 预印本），**预印本要说「预印本」**
- **同一篇论文的不同版本数字可能不一样**（arXiv 版 vs 正式版）——**引用必须注明版本**
- **说「空白 / 没人做」之前，必须拿这个词去专项检索**。检索不到才能说，且措辞用「现有工作极少关注」。归纳出来的只能叫「我这批文献里的空白」
- **有强相关工作的地方要主动承认**，并说清自己差在哪。回避比承认更危险
- **页数、读了几篇、图怎么裁的——这些不写进 PPT**

## 十、目录约定

```
阶段N-主题/
├── papers/           论文 PDF（不上传 git）
├── figures/          裁好的图（命名：p<篇号>-<简称>-<用途>.png）
└── presentations/
    ├── crop_figs.py          裁图脚本（JOBS 表驱动，可单独重裁某张）
    ├── build_ppt.py          PPT 生成脚本（PAPERS 列表驱动全部内容）
    ├── *大纲*.md              逐页大纲（含每页要点与数字）
    ├── 汇报稿*.md             逐页口播稿 + 预答 + 突发应对
    └── *.pptx               生成物
```

**内容与排版分离**：所有文字放进 `PAPERS` 这个数据结构，排版由通用函数完成。改内容只改数据，不碰排版。

## 十一、执行顺序

1. 确认篇数、篇目、时长
2. 先出**逐页大纲**给用户确认（含每页要点和数字）
3. 裁图（脚本 + 逐张目检）
4. 写生成脚本（PAPERS 数据 + 四类页面的渲染函数）
5. 生成 → 跑几何审计 → 修 → 再审计
6. 写讲稿（口播 + 预答 + 突发应对）
7. 交付前自检：PPT 上有没有「讲法 / 导师 / ★ / 工作痕迹」；论文标题是不是原标题；表格有没有多余描述列
