# 方向定位：这个方向该怎么讲

> 这份解决一个问题：**在别人眼里，这到底是 AI 还是安全？**
> 讲法不同，你被归到哪个组就不同。

---

## 一、一句话方向

> **在卫星的分层架构里，让每一环独立校验 Agent 自己的判断，而不是只校验它最后做了什么。**

**技术底座是"LLM 多智能体系统的可信机制"，卫星是验证场景。**

---

## 二、为什么必须这么讲

| 讲法 | 结果 |
|---|---|
| 「**做卫星网络安全的**」 | 掉进传统网安，做 AI 的老师不会看你 |
| 「**做 Agent 可信机制，卫星是验证场景**」 | 落在 AI 里 |

**两者差别很大：**

| | 传统网安 | 这块（AI 安全） |
|---|---|---|
| 关键词 | 漏洞挖掘、渗透、逆向、密码学 | **Agent、注入攻击、架构防御、评测** |
| 主要会议 | CCS / S&P / USENIX / NDSS | **ICML / NeurIPS / ICLR / ACL** |
| 日常的活 | 挖洞、写漏洞利用、协议分析 | **跑实验、改架构、做评测** |

**证据**：这次读的八篇里，CaMeL 是 Google DeepMind（SaTML）、推测验证那篇是 ICML 2026、Design Patterns 那篇是 ETH + Google + Microsoft。

**这些是 AI 圈的人，不是安全圈的人。**

---

## 三、三个真实风险

**① 面试被误归类**
对方老师不做 Agent 的话，会把「多步注入防御」归成安全。

**② 方向偏窄**
「卫星 + Agent 安全」太具体。做 CV/NLP 的老师会觉得不对口。

**③ 这个题不好发（最实际）**
卫星场景**缺公开数据集、缺 benchmark、评测难做**。做得太"航天"，投 AI 顶会会被质疑评测不充分。

→ **所以方案里必须写清"用什么公开基准验证"。**

---

## 四、五条做法

1. **技术底座锚在"通用多智能体"**上，卫星只是验证场景。这次八篇调研正好是通用底座，别浪费。
2. **成果优先投 AI 方向的会议或工作坊**，不投安全会议——**这决定了材料被谁看到**。
3. **留一条能迁移的线**：「多步攻击下的信念校验」这套东西，搬到网页 Agent、代码 Agent 都成立。
4. **简历上别写"安全"**，写「**LLM 多智能体系统 / Agent 架构与可信性**」。
5. **保研前至少有一篇能完整讲的工作**（工作坊、arXiv 都行）。**这比方向重要。**

---

## 五、"只要能展现科研能力就行"——对一半

**对的**：保研看的是**有没有跑通完整闭环**（问题 → 方法 → 实验 → 结论）加独立贡献。本科生主要看这个。

**不完全对的**：**方向决定你被哪个组注意**。差太远，第一轮筛就被过滤。

**所以**：方向不匹配的杀伤力有限，但**材料里全是"安全"字眼，就会被默认归到安全组**。

**而这条攻击链的第二步，恰恰是改认知。**
