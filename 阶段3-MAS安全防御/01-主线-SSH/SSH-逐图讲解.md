# 一、核心研究问题（一句话）

> **现有检测都是"回头看历史"。但攻击把意图拆散在多轮里、把危险藏在未来。能不能在 Agent 动手之前，先推演它可能做什么？**

**展开三句**：

1. 多轮攻击有两种：多轮越狱（骗用户侧）、多轮间接注入（藏工具输出里）
2. 现有检测靠**历史上下文**——只能看到已经发生的
3. 而攻击者**故意把意图拆开**，让每一轮单看都没问题，等攒够了再引爆

**所以缺的是"前瞻"能力。**

# 三、Fig. 1 怎么讲（动机图，60 秒）

**先说这图画了什么**

左边是**用户**，中间是**Agent**，右边是**黑客**。底下有个 **SSH** 框，画着"Speculated Future"（推演出的未来）。

**按顺序讲**

1. **用户只说了一句话**："给我快速总结一下今天的邮件。"
   ——**这句话完全正常，单独看没有任何问题。**

2. **Agent 开始读邮件。** 黑客的攻击藏在邮件内容里。
   ——**这就是间接注入**：用户是干净的，脏东西在 Agent 读到的数据里。

3. **SSH 在 Agent 真的动手之前，先推演它接下来可能做什么。**
   推演结果里出现了两件事：**转账**、**改密码**。

4. **这两件事跟"总结邮件"毫无关系，而且都是高风险。**
   所以 SSH 报警。

**收尾一句话（这句最重要）**

> **用户的话是干净的，攻击藏在数据里，而危险动作还没发生——所以这个防御是"提前"的，不是"事后"的。**

**她可能问**：为什么不直接检测邮件内容？
**答**：检测内容就是现有做法，但攻击可以把恶意拆散在好几轮、好几次工具返回里，单看每一段都正常。**这篇的办法是不看内容，看"Agent 接下来会干什么"。**

# 四、Fig. 2 怎么讲（模型图，90 秒）

**这张图分三块，从左到右讲。**

## 左边：输入——异步

- 目标 Agent 把**当前的消息列表**发给 SSH
- 关键词是**"异步"**：**不拖慢主流程**，Agent 该干嘛干嘛

## 中间：模拟器——建一棵推测树

**用什么东西模拟**：一个**无审查的 LLM**（uncensored LLM），上面挂**多个 LoRA**。

**为什么必须"无审查"**：如果拿一个对齐得很好的模型来推演，它自己就会拒绝走危险路径，**推演不出攻击**。这是这篇一个很实用的设计点。

**三个角色轮流演**：
- 一个 LoRA 演**用户**（下一步会说什么）
- 一个 LoRA 演**助手**（Agent 下一步会调什么工具）
- 一个 LoRA 演**环境**（工具会返回什么）

**轮流往下推**（Round-Robin），推出一棵树。

**树有多大**：**M = 5 条分支，深度 D = 4 层**。

## 右边：验证——剪枝 + 打分

- 现有检测器去看树的**叶节点**，找高风险分支
- Agent 真实动作出来后，**剪枝**：
  - 把真实动作跟 5 条候选比对
  - **函数调用**：比函数名 + 参数，精确匹配
  - **文本**：用 SimHash 算相似度
  - 匹配上哪一支，就只保留那一支的子树
- 然后算风险分

## 右下角那个小图（Beam Search）

这容易看漏，但它是方法的一个要点。

- **字母**（A、B、C…）= 不同的动作
- **灰框** = 动作聚类（把相似的动作归成一类）
- **紫色数字** = 轮询选择的顺序（1、4、2、5、3……）

**它在说**：**不是简单取概率最高的 5 条，而是按聚类轮流选。**

**为什么要这样**：如果只取概率最高的，5 条分支会长得几乎一样，**推演就没意义了**。要保证多样性，才能覆盖不同的危险路径。

**她可能问**：为什么用多个 LoRA 而不是多个模型？
**答**：省资源。一个 3B 的模型挂多个 LoRA，**参数只多 1.3%**（相对于 235B 的主模型）。

# 五、结果怎么说（先记住这几个数）

**Table 2（ActorAttack 数据集）**：

| 配置 | 风险暴露率 | 攻击成功率 |
|---|---|---|
| 目标模型，无 SSH | — | **41.5%** |
| M = 1 | 84.5% | 6.0% |
| M = 3 | 94.0% | 0.5% |
| **M = 5** | **99.5%** | **0.0%** |

**同一个表里，另一个数据集（Circuit Breaker）**：无 SSH 时 33.6%，M=5 时 **0.0%**。

**两个数一起看才是重点**：
- **暴露率越高越好**（说明推演抓到得多）
- **攻击成功率越低越好**（说明真拦住了）

**它们一起动，才说明不是"多报警"，是"报得准"。**
