# 二、逐节通读

## Abstract（第 1 页）

**一段话，五句，结构是「现状 → 问题 → 我们做什么 → 怎么做 → 效果」**

1. LLM Agent 部署越来越多，多轮攻击成了大问题
2. **现有检测靠历史上下文**——但这种"回顾式"逻辑，识别不出**被拆散在多轮里、用来隐藏未来风险的深层意图**
3. 所以提出 SSH，借**推测解码**的思路
4. SSH 用**小模型组成的多 Agent 系统**，做"动作级的推测—验证"：推测阶段预测 Agent 未来行为、异步建轨迹树；验证阶段用真实动作剪枝
5. 它是**即插即用**的：给现有检测器提供"超出当前交互片段"的决策冗余

**最后一句是它的价值主张**：判断依据从"单个时间点"变成"整棵树的演化"，**于是不再依赖单个检测器有多准**。

## 1. Introduction（第 1–2 页）

**四段，逐段看：**

**第 1 段：把威胁分两类**
- 多轮越狱（骗用户侧，把恶意拆到多轮绕过过滤器）
- 多轮间接注入（藏工具输出里，利用 Agent 对外部反馈的信任）

**第 2 段：指出现有防御的软肋**
- 提示类方法（Sandwich、Spotlight 等）和外部检测器，**都只在"当前上下文"里防**
- 缺的是"对将来执行路径的预测"

**第 3 段：讲自己的思路**
- 既然缺预测，那就**主动去预测**
- 用一个小模型系统在后台推演，Agent 该干嘛干嘛（**异步**）
- 推出来的树，让现有检测器去看叶节点
- 风险分 = 高风险叶节点占的比例，超过阈值就告警

**第 4 段：说清"为什么这样更好"**
- 给现有检测器**更多信息**
- 判断依据从"单个节点"变成"整棵树的趋势"
- **所以降低了对单个检测器精度的依赖** ← 这句是它的核心卖点

**然后三条贡献（编号列表）**：
1. 第一个把 Agent 防御从"回顾上下文"改成"前瞻推演"
2. 多样性导向的 Beam Search（在有限预算下探索多样风险路径）
3. 实验：**0% ASR**，同时缓解现有防御带来的效用下降

**图 1 在这一页**——动机图，下面单独讲。

## 2. Related Work（第 2 页）

**三小节，注意它是"从远到近"排的**

### 2.1 Speculation Techniques（推测技术）
- **远**：推测解码（SD）——小模型起草，大模型并行验证，加速推理
- **中**：已经有人把它用到安全（SSD）、用到 Agent 规划（DSP）、用到环境状态预测（Speculative Action）、用到推理（SpecReason）
- **近（它的位置）**：别人做到"动作级"了，**但没人用它做安全防御**

**这一节的作用**：证明"动作级推测是可行的"，给自己的方法找技术依据。

### 2.2 Multi-turn Attacks（多轮攻击）
- **多轮越狱**：Crescendo（良性探针累积有害上下文）、ASJA（改对话历史让注意力偏离安全词）、AMA（跨域类比伪装意图）
- **多轮间接注入**：InjecAgent、AgentDojo、STAC 这些基准；还有改 HTML 引导网页 Agent 的

**这一节最后一句是关键**：「这些方法暴露了一种**context-drift**（上下文漂移）漏洞——累积的语义重量压过了最初的安全对齐。」

**这句话就是它要打的靶子。**

### 2.3 Limitations of Existing Defenses（现有防御的局限）
- 提示类方法和外部检测器，**都只在当前上下文里防**
- **缺少对将来执行路径的预测模型**

**这一节只有三句，但它是全文的转折**——**把"别人不行"锁定在"缺少预测"这一点上**，后面所有方法都从这来。

## 3. Methodology（第 3–5 页）

**开头一段先给全局流程**，然后四个小节：

> 推测 → 建树 → 检叶节点 → 真实动作来了就剪枝 → 算剩余子树的风险比 → 超阈值就告警/重采样/终止

### 3.1 Construction of the Simulation System（三个模拟器）

**三个角色，各有一个"为什么"**：

| 模拟器 | 演谁 | 为什么这么设计 |
|---|---|---|
| **Assistant** | 目标 Agent | **用没有安全对齐的模型**——它更容易走危险路径，风险才能暴露出来 |
| **User** | 用户 | 也**不做安全对齐**——为了生成多样、模糊的意图，覆盖边缘情况 |
| **Environment** | 工具 / MCP / 数据库 / 第三方 Agent | **给合成反馈，不真执行**——保证推演过程隔离、无害 |

**架构是去中心化的**，三个模拟器之间怎么轮流说话，由一份预定义协议管（附录 A）。

**这一节最反直觉的一点**：**故意用"不安全"的模型来当防御组件。** 理由写在 3.4 里（见下）。

### 3.2 Speculative Trajectory Tree Drafting（建推测树）

**触发时机**：目标 Agent 一开始生成，SSH 就异步启动，**克隆当前消息列表**当起点。

**关键一句**：

> 传统推测解码追求**命中率**；**我们要的是路径覆盖，去找高风险的边角情况。**

**所以那个 Beam Search 是"多样性导向"的，不是"取概率最高的"。**

**两个超参**：M（树宽，每层最多几条分支）、D（最大深度）。

**节点分两类（这是算法能省算力的关键）**：
- **关键节点**（key nodes）：用户请求、助手动作——**分支多，要采样扩展**
- **普通节点**（regular nodes）：工具返回、逻辑总结——**基本是确定的，只采一次，不扩展**

**所以不是盲目把树撑爆，是把算力花在会分叉的地方。**

### 3.3 Asynchronous Verification and Risk Scoring（异步验证 + 打分）

**剪枝怎么做**：
- 把真实动作跟 M 个候选比对
- **函数调用**：函数名 + 参数，精确匹配
- **文本**：SimHash 算相似度
- 匹配上哪一支 → **只保留那一支的子树**
- 匹配不上 → **保留原树**，当"未来可能风险"的参考

**风险分**：叶子节点里被判为高风险的比例。超阈值 → 告警 / 重采样 / 直接终止。

### 3.4 Training（训练——这节容易被跳过，但很重要）

**① Differentiated Alignment Strategy（差异化对齐）**

**这段是全文最反直觉的**：

> 为了让推演路径留在目标 Agent 的执行空间里、**同时更容易在对抗场景下被诱发违规**，他们**故意增强 SSH 在对抗环境下的脆弱性**，来最大化风险暴露和预警能力。

**说人话**：**把探子训练得容易被骗，它才会往最坏的方向想。**

**② SFT 保持"像"**
- 用开源数据集（Toucan 等）+ 目标 Agent 的真实轨迹
- **去掉长 CoT**（`<think>` 里的内容），**但保留错误模式** → 精确近似目标 Agent 的行为分布

**③ 合成"良性注入"数据**：把 A 样本的正常指令塞进 B 样本的工具返回里，模拟"被工具反馈带偏"

**④ Tool / User 模拟器**：复用同一份数据，只换微调的目标字段

**⑤ Multi-LoRA**：三个 LoRA **不合并进主干**，而是作为并发适配器挂在一个共享 LLM 上 → **省显存、切换快**

## 4. Experiments（第 5–8 页）

**三组实验，回答三个问题**（这是读实验节最该抓的结构）：

| 小节 | 回答什么问题 | 用哪个基准 | 结论 |
|---|---|---|---|
| 4.2.1 | **能防间接注入吗** | AgentDojo | ASR 全 0 |
| 4.2.2 | **能防多轮越狱吗** | ActorAttack | M=5 时 ASR 0 |
| 4.2.3 | **会不会拖累正常功能** | BFCL-v3、XSTest | 基本无损 |

### 4.1 Setup（第 5 页）

| 项 | 是什么 |
|---|---|
| 基准 | AgentDojo、ActorAttack、XSTest、BFCL-v3 |
| **目标模型** | **Qwen3-235B-A22B-Instruct-2507**（235B） |
| **SSH 用的模型** | **Dolphin3.0-Qwen2.5-3B**（3B，无审查） |
| 基线三类 | 提示类（Sandwich / Spotlight / Tool Filter）、护栏（ProtectAI、PromptGuard-86M）、裁判（Qwen3-0.6B） |
| 指标 | **ASR（越低越好）**、**UA（Utility under Attack，越高越好）** |

**注意 235B 对 3B**——**差了近 80 倍**，这是它"轻量"主张的底气。

### 4.2.1 防间接注入（第 6 页，Table 1）

**Table 1 是 AgentDojo 上四个场景（Workspace / Slack / Travel / Banking）× 六类攻击的表。**

**只看三行就够**（平均行）：

| | ASR | UA |
|---|---|---|
| 无防御 | 31.78% | 56.59 |
| PromptGuard 单独 | 12.25% | 36.02 |
| **PromptGuard + SSH** | **0.00%** | **44.14** |
| Judger 单独 | 10.48% | 44.75 |
| **Judger + SSH** | **0.00%** | **58.43** |

**两个结论**：
1. **不管底层是哪个检测器，加了 SSH 都是 0% ASR**
2. **UA 还回升了**——加了 SSH 比检测器单用更不伤功能

**它的解释很关键的**：PromptGuard 主要识别"有没有注入文本"，而**不判断 Agent 有没有被带偏**——所以它单用时 UA 低。**SSH 补的是"有没有真被带偏"这一维。**

**还有一个实用结论**：**连 86M 的检测器加上 SSH 都能到 0% ASR**——不用为了小幅安全提升去部署大模型。

### 4.2.2 防多轮越狱（第 7 页，Table 2）

**攻击方用的是 Dolphin-X1-8B**（无审查模型）。理由写得很实在：**安全对齐的模型不肯发起攻击，太弱的模型设计不出有效攻击路径。**

**Table 2 看 M 的边际收益**：

| M | 暴露率 | ASR | |
|---|---|---|---|
| 1 | 84.5% | 6.0% | **一个样本就抓到八成四** |
| 3 | 94.0% | 0.5% | |
| 4 | 98.5% | 0.0% | |
| **5** | **99.5%** | **0.0%** | |

**边际收益递减**：M 从 1 到 3 涨 10 个点，**从 4 到 5 只涨 1 个点**。

**这就是"M=5 够了"的依据。**

### 4.2.3 对正常功能的影响（第 7 页，Table 3 + Fig 3）

**Table 3**：BFCL-v3 总分 45.13 → 44.88，**基本不动**；XSTest 拒答率 0.0 → 0.0，**没有误拦**。

**Fig 3**（第 7 页）：平均风险分 vs 超过阈值的比例
- **AgentDojo 57.2%、ActorAttack 81.5%**——有攻击时，风险分确实高
- **BFCL-v3 0.0%、XSTest 0.0%**——正常任务上，**风险分接近零，一个都没超阈值**

**这张图是"不误报"的证据。**

**Fig 4**（第 8 页）：M 变大时暴露率和命中率怎么变。结论：**Beam Search 比 Top-P 采样更容易找到威胁。**

## 5. Conclusion（第 8 页）

**一段话**，重复摘要的主张：从回顾改成前瞻；轻量模拟器 + 多样性 Beam Search；**0% ASR**。

---

## Limitations（第 9 页）

**两条，都很实：**

**① 算力与能耗**
- 3B 模型 + Multi-LoRA，**参数只多 1.3%**（相对 235B）
- **但 M=5 条并发分支的显存和功耗不可忽略**
- 他们用 vLLM 批处理 + 复用 KV cache 来压

**② 误报影响体验**
- AgentDojo 上系统级 FPR **0.2%**
- 一次误报带来 **3–7 秒延迟**，而且回答会更保守、更啰嗦
- 承认在开放式任务里"有野心"和"有恶意"的边界很薄，**可能需要人在回路**
