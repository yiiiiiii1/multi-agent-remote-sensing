**一个问题**：有没有跟 SSH 类似、但**开源**的论文，要求 **CCF-A**？

## 一、一句话答案

**没有「CCF-A 正会 + 开源 + 事前预测」三样齐全的论文。**

- 「CCF-A 正会 + 事前预测」→ 只有 **SSH 自己**（ICML 2026），但它不开源
- 「开源 + 事前预测」→ 有，最像的是 **SafePred（★71）**
- 「开源 + 步级工具调用安全」→ **ToolSafe（★86）**

**SSH 独有的那一步（多分支轨迹树 + 三模拟器分工 + 告警后重采样），开源界没有对应物。**

**但有三处数字口径必须加限定**（原稿没写，复核指出，我已核对 PDF 附录）：

1. **「0% ASR」只在 Qwen3-235B 上成立。** 附录 D.1 Table 5：GPT-4o-mini 8.4% → 0.0%，但 **GPT-OSS-120B 是 14.9% → 0.7%**。论文自己的措辞是 "near-zero"。
2. **「1.3%」是参数比不是实测开销。** 原文：adding only 1.3% parameter overhead relative to the 235B target，紧接着就说 GPU memory 和 power "non-negligible"。**拿它当轻量化论据会被打。**
3. **M 的记法论文自己矛盾。** Table 1 脚注写 "beam width of 8 (M = 4)"（AgentDojo 用 M=4）；Table 2 才扫 M=1–5（ActorAttack 的 99.5%/96.0% 出自这）；Limitations 里又说 "M = 5 concurrent branches"。**引用必须带是哪张表。**

## 二、最重要的一个辨析：三个「proactive」不是一回事

这一族论文都自称 proactive，但**判断对象完全不同**：

| | 判断什么 | 具体例子 | 代表 |
|---|---|---|---|
| **A. 判当前这步** | 眼下这个动作安不安全（执行前判） | 这个 `send_email` 会不会把 PIN 发出去 | **ToolSafe**（★86） |
| **B. 预判后果** | 这步执行后状态会变成什么 | 删了这条日志，后面审计就查不到了 | **SafePred**（★71） |
| **C. 推演未来动作** | Agent 接下来会做哪几步 | 下一步它会点转账、再下一步改密码 | **SSH**（唯一） |

**只有 C 是 SSH 在做。** A 和 B 都是「执行前」，但都不是「推演未来」。

**这个辨析能直接用在汇报里**——它解释了为什么这一族论文看起来很挤，其实各做各的。

## 三、这一族的地图

**名字**：predictive / proactive guardrail（预测式护栏）

**规模**：至少 25 篇，**几乎全部集中在 2025Q4–2026 的预印本**。

**开源的一共 5 个**：

| 项目 | 星数 | 做什么 | 出处 |
|---|---|---|---|
| **ToolSafe / TS-Bench** | ★86 | 步级工具调用安全检测 + 反馈不中止 | Findings of ACL 2026 |
| **SafePred** | ★71 | world model 预判短期+长期风险，剪掉高风险动作 | arXiv 2602.01725 |
| **HarmonyGuard** | ★28 | Web Agent 自适应策略 + 双目标优化 | arXiv（与 SafePred 同作者） |
| **IPIGuard** | ★26 | 工具依赖图防间接注入 | arXiv 2025 |
| **WebGuard** | ★13 | 可泛化的 Web Agent 护栏 | arXiv 2025 |

**不开源但重要的**（了解即可）：SafeMCP、JANUS、SeerGuard、TRACES、SafetyDrift、MAGE、SafeAgent、AgentDoG、ShieldAgent、VeriGuard、Simura、GuardAgent、TS-Guard

**另外这几篇是同场景但不同思路的 CCF-A**：SecAlign（CCS 2025，把抗注入训进权重）、DRIFT（NeurIPS 2025，注入隔离）、The Task Shield（ACL 2025，动作必须服务用户目标）、IsolateGPT（NDSS 2025，执行隔离）、Fides（NeurIPS，信息流控制）

## 四、对卫星方向能用的三样东西

**1. 标注格式 → 照 ToolSafe 的 TS-Bench**

它把步级风险标成四类：恶意用户请求 / 提示注入 / 有害工具 / 良性工具配危险参数。

**卫星那条攻击链「第几步算越界」，可以直接照这四类标。**

**2. 「不中止，给反馈让 Agent 自己改」 → ToolSafe 的 TS-Flow**

这正是 SSH 的「重采样而不是终止」。但 ToolSafe 是**单模型 + RL**，比 SSH 三个模拟器轻得多。

**3. 复现 SSH 是可行的，而且第一层只要 3–5 天**

| 层 | 做什么 | 工期 |
|---|---|---|
| **第一层** | 模拟器用 API 模型 prompt 扮演，自己写推理层（轨迹树 + Beam Search + 剪枝 + 双阈值 + 重采样），插在 AgentDojo 上 | **3–5 天**，核心 400–600 行 |
| 第二层 | 换掉两个模拟器：环境用 mock 执行器（不用训）、用户用 TS-Bench 样本当行为库 | +1–2 周 |
| 第三层 | 复现 Differentiated Alignment（11,000 蒸馏 + 4,700 合成 + 3 个 LoRA） | +3–4 周 + 显卡 |

**零件全在**：Dolphin3.0-Qwen2.5-3B（HF 公开）、Toucan（开源）、AgentDojo（★985）、ActorAttack（★135）。

**为什么第一层就够**：SSH 的核心创新在**推理层**，不在训练层。而且星上算力受限，**训三个 LoRA 本来就不现实**，prompt 版模拟器反而更贴约束。

## 五、这次检索的过程和我犯的错

**四轮，每轮都发现上一轮不够：**

| 轮次 | 方法 | 收获 | 问题 |
|---|---|---|---|
| 一 | 网页搜索 | 9 篇 | **撞见式**，系统性差 |
| 二 | OpenAlex 关键词 + 会议过滤（51 查询 × 8 词族 × 17 个 CCF-A 会议） | 补 4 篇 | **子串匹配造成 5 篇假阳性** |
| 三 | 反查 2 篇的参考文献 | 补出整族 11 篇 | 反查样本太少 |
| 四 | 反查 4 篇的参考文献 | 又补 8 篇 | 还会继续长 |

**两类错误，性质不同：**

- **第一轮漏检**（撞见式）→ 少找了 4 篇
- **第二轮假阳性**（会议名子串匹配）→ 多算了 5 篇。**这个更糟**：漏检只是没找到，假阳性是说错了。
  - KG-Guard 实为 **ICMLCA**，我写成 ICML（因为 `"International Conference on **Machine Learning** and Computer Application"`）
  - ShadowPlay 实为 **Cyber-AI**，我写成 ASE
  - TrustAgent / R-Judge 实为 **Findings of EMNLP**，我写成 ACL
  - Causal Influence Prompting 实为 **Findings of ACL**，不算正会

**教训两条：**

1. **查「同一族」最快的路不是搜关键词，是读最接近那篇的 related work 和参考文献。**
2. **会议归属不能靠字符串推断，必须看 DOI 或官方列表。**

**能说的和不能说的：**

- 能说：在 17 个 CCF-A 会议、2023 至今、51 个英文查询 + 4 篇反查这个框里，**该扫的扫了，结论稳定**
- 不能说：**期刊没扫**（TDSC/TIFS/TSE）、**非英文没扫**、**OpenAlex 索引有滞后**
