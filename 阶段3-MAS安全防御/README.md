# 阶段3 · MAS 安全防御

**开启时间**：2026-11-05

## 这一阶段要解决什么

老师在上一次汇报后给的指示：**查 SSH 是否开源；如果不开源，找类似的开源工作。**

查完的结论改变了方向：

1. **SSH 没开源**（论文、ICML 页、arXiv 页、GitHub 全查过）
2. **CCF-A 正会 + 开源 + 事前预测**的只有 **SafeMCP（ACL 2026）**，但它是**单 Agent**
3. **卫星场景是多智能体**，所以主线应该转到 **MAS 安全防御**
4. **SSH 的架构跟我们的任务错位**：它假设「有一个大模型要保护，且有余量养三个防守小模型」；而我们是「算力紧到必须拆成多个小模型干活」

**因此这一阶段的目标：定下「星上多智能体安全防御」的技术路线和主参照论文。**

## 三条当前的判断（待与老师确认）

**① SSH 只能当思路来源，不能当架构模板。**
它保护的是一个大模型，我们保护的是一群小模型；它加算力换安全，我们要省算力。

**② 真正贴我们的是「连环锁」：复用星上已有小模型互相校验，不额外养防守模型。**
这既是老师说的「每一环独立校验」，也正好绕开算力约束。

**③ 这个空位正在被填。**
2026 年已出现 AgentShield（零信任护栏）、Synoptis（互相认证）、MeshHeal（自愈网络）等预印本，方向相近但都不是 CCF-A。**要做就得快。**
